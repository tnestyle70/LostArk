# 클래스 로직 — 스킬 타이밍 데이터 로더와 창술사 스탠스

작성자: JS · 2026-08-02

> 통합 상태(2026-08-03): 이 문서는 담당자의 실측과 시도 이력을 보존한다. 최종 제품
> 경로는 `.md/TEAM/TEAM_GAMEPLAY_INTERFACE_HANDBOOK.md`가 정본이다. `win=`
> 애니메이션 참조 데이터와 Engine crossfade는 통합했지만, DirectInput에서 스킬·스탠스를
> 로컬 재생하는 구현과 소비자가 없는 `SkillData` 런타임은 통합하지 않았다. 스탠스는
> Shared command → Server approval → snapshot 계약이 추가된 뒤 활성화한다.

캐릭터 4종을 뽑아둔 상태에서 "각 클래스 특성에 맞는 로직"을 시작했다. 이 문서는 그 1·2
단계다. 3단계(체인 재생에 캔슬·콤보 윈도우 배선)와 나머지 3클래스 아이덴티티는 아직이다.

## 1. 시작 전에 정리한 담당 경계

프레임워크 담당의 `.md/GB/08-02/2026-08-02_MINIMAL_GAMEROOM_ENTITYREGISTRY_PLAYER_SPAWNED_PLAN.md`
§10이 다음 단계를 못박고 있다.

```text
G3 PlayerController local input -> C2S_MOVE -> GameRoom 권위 위치 -> S2C_WORLD_SNAPSHOT
```

그리고 §4.4가 `Character.h`의 `CHARACTER_DESC`, `Character.cpp`의 `Initialize()`와
`Update()`를 **통째로 교체**한다. 따라서

- **입력 경계(`CHARACTER_INPUT` / `CPlayerController`)는 만들지 않았다.** G3와 정면으로
  겹치고, 그쪽 코드가 `ICharacterLogic::Update(Character, fTimeDelta)` 시그니처를 그대로
  쓰고 있어 인자를 바꾸면 그 블록이 깨진다.
- 이번 작업은 **`Initialize()`/`Update()`를 건드리지 않는다.** `CCharacter`에 추가한 것은
  새 함수 하나(`Set_PartVisible`)뿐이다.

반대로 같은 문서 §9는 "Character Catalog는 LanceMaster만 지원한다. 다른 class Prototype과
spec이 준비되기 전에는 해당 Spawn을 실패 처리한다"고 적고 있어, 클래스 쪽은 이쪽이
막고 있는 항목이다.

## 2. 아이덴티티는 클래스마다 종류가 다르다

바인드 테이블을 클래스별로 채우려다 멈췄다. 키 배치가 런타임에 바뀌기 때문이다.
`.clipseq`를 실측한 결과 넷이 서로 다른 모양이었다.

| 클래스 | 아이덴티티 | 전환 |
|---|---|---|
| 창술사 | 2스탠스 토글 (긴 창 18스킬 / 짧은 창 9스킬, 평타도 각각 34010·34510) | `34000` 긴→짧, `34500` 짧→긴 |
| 건슬링어 | 3스탠스 링 (샷건 38001 / 라이플 38002 / 권총) | `38160` 정방향, `38161` 역방향 |
| 도화가 | 스탠스 없음 — identity/mode 항목이 아예 없다 | |
| 슬레이어 | 일시 모드(폭주). 모드 전용 평타 45001, 전용 회피 45011 | `45003` 발동 |

토글·링·없음·일시모드다. **공용 스탠스 프레임워크를 만들면 넷 중 어디에도 안 맞는
추상이 나온다.** 각 `Logic_*.cpp`가 자기 상태를 들고 자기 테이블을 고르고, 공유하는 것은
바인드가 아니라 스킬 타이밍 데이터뿐이다.

스탠스 판별을 **ID 범위로 하면 틀린다.** `34630 "초각성기_연가창식: 마룡합일섬"`은 34500
이상이지만 짧은 창 스킬이 아니다. 실제 마커는 이름의 `긴 창_` / `짧은 창_` 접두사다.

## 3. 1단계 — 입력 윈도우 정규화와 런타임 로더

### 3.1 라벨은 정제된 enum이 아니었다

`.animnotify`의 `kind=CANCEL src=InputTiming` 행에 캔슬·선입력 창이 들어 있는데, 판별자가
기획자가 손으로 쓴 한글 라벨뿐이고 4클래스 통틀어 **56종**이었다.

```text
""(476)  [선이](292)  [선스](289)  연가심공(138)  이동캔슬(93)  [회피캔슬](84)
[이동캔슬](70)  입력캔슬(51)  [스킬캔슬](51)  회피기캔슬(테스트)(50)  스킬캔슬(45)
[선콤](38)  이동선입력(24)  스킬선입력(24)  콤보선입력(8)  콤보입력(5) ...
```

같은 개념이 `이동캔슬`/`[이동캔슬]`/`이동기캔슬`/`이동기 캔슬`로 갈라져 있다.

### 3.2 추출기에서 접었다

`Logic_*.cpp`는 CP949 코드 페이지에서 빌드되어 ASCII를 유지하는 파일들이라, 런타임에서
한글을 매칭하려면 UTF-8 헥사 이스케이프를 박아야 했다. **정규화를 추출기로 옮겼다.**

`extract_action_loa.py`에 `window_class()`를 추가해 두 축으로 접는다 — 어떤 행동인지
(MOVE/SKILL/COMBO/DODGE/ANY) × 선입력이냐(PRE) 캔슬이냐(CANCEL). 확신이 없는 것은 `OTHER`로
두고 규칙을 지어내지 않았다. `.animnotify` 행에 `win=` 필드로 나간다.

| 클래스 | 분류된 창 | NONE | OTHER |
|---|---:|---:|---:|
| LanceMaster | 320 | 271 | 146 |
| GunSlinger | 325 | 108 | 132 |
| Artist | 237 | 18 | 11 |
| Slayer | 413 | 79 | 45 |

LanceMaster의 OTHER 대부분은 `연가심공`(138)인데 버프성 스킬 표시라 이번 범위에서 제외했다.

데이터 재생성은 **순수 추가**임을 확인했다 — 바뀐 12,119줄에서 `win=`만 떼면 원본과 완전히
동일하고, `clipmap`/`clipseq`/`animevents`는 바이트 동일이라 손대지 않았다. 툴의
`.animnotify` 파서는 `Read_Pair` 기반이라 모르는 키를 무시하므로 호환된다.

### 3.3 `CSkillData`

`Client/Public/SkillData.h` · `Client/Private/SkillData.cpp` (신규). 클립별 길이와 입력 창,
스킬별 쿨다운(`cd=`)과 히트 시점(`t=`/`w=`, 캐스트 전체 시계 기준 ms)을 읽는다. 애셋 이름으로
캐시해 같은 클래스가 여러 명 떠도 한 번만 파싱한다. 스킬은 `base=`로 색인한다 — 트라이포드
변형들이 공유하는 값이고 클립 체인이 들고 다니는 id가 그것이다.

`Initialize()`에 로드를 걸지 않았다. 실제로 쓰는 3단계에서 지연 접근자로 붙이는 편이
프레임워크 담당의 함수 교체와 충돌하지 않는다.

**검증** — 엔진 없이 독립 실행 프로브를 컴파일해 실제 파일로 돌렸다.

```text
LanceMaster clips=144 skills=23   GunSlinger clips=122 skills=33
Artist      clips=67  skills=16   Slayer     clips=148 skills=22
```

네 값 모두 파일에서 직접 센 기준값과 일치한다. 창 경계도 전부 통과했다.

```text
Slayer wbk_att_battle_2_01: len=1.8000 windows=8
  SKILL_PRE 0.30 true / 0.70 false     COMBO_INPUT 1.00 true / 0.30 false
  MOVE_PRE  0.70 true                  DODGE_CANCEL 1.00 true
Slayer skill 45050: cooldown=12000ms hits=5 (t=1770/1100x3/1843)
```

## 4. 2단계 — 창술사 스탠스

### 4.1 상태 기계

`CLogic_LanceMaster`가 스탠스별 바인드 테이블 둘과 전환 상태를 들고 있다.

```text
Z         스탠스 전환 (긴 창 34000 <-> 짧은 창 34500)
          긴 창                          짧은 창
Q W E R   이연격 열공참 회선창 반월섬       나선창 사두룡격 굉열파 유성강천
A S D F   연환섬 질풍참 선풍참혼 맹룡열파    절룡세 적룡포 돌파(이동기) -
C         청룡출수                        -
X         평타 34010                      평타 34510
1         초각성기 34630 (스탠스 무관, 양쪽 공통)
```

**스탠스는 전환 클립이 끝난 뒤에 뒤집힌다.** `34000`/`34500`은 `flm_mode_identity1/2`를
재생하는데 그게 무기를 바꾸는 동작이라, 캐스팅 시작 시점에 뒤집으면 손과 무기가 어긋난다.

Z가 아이덴티티가 되면서 거기 있던 `34100 청룡출수`는 C로 옮겼다. 나머지 긴 창 바인드는
기존 그대로다.

작업 중 잡은 버그: 키 눌림 상태를 **바인드 슬롯 인덱스**로 저장했더니, 스탠스가 바뀌면
슬롯 i가 다른 키를 가리켜 전환 직전에 눌려 있던 키가 새 스탠스에서 한 번 안 먹었다.
DirectInput 키 코드로 직접 색인하도록 바꿨다.

`Logic_LanceMaster.h/.cpp`는 스킬명을 clipseq와 눈으로 대조할 수 있게 한글을 넣었고, 그
대신 **UTF-8 BOM으로 저장**했다. BOM이 없으면 MSVC가 CP949로 읽어 C4819가 뜬다.

### 4.2 무기가 실제로 바뀌게

`WP_WFLM_00` 패키지 안에 `wp_wflm_00l_sk`와 `wp_wflm_00s_sk`가 **나란히 들어 있었다.**
기존 추출본은 glTF라 파이프라인에서 안 쓰이고 있었을 뿐이다. `-groups` psk로 다시 뽑아
짧은 창을 쿠킹했다.

런타임 교체는 살아있는 캐릭터의 모델 컴포넌트를 갈아끼우는 대신 **두 창을 다 조립해두고
그리는 쪽만 바꾼다.**

- `CPart_Equipment::Set_Visible()` — 숨긴 파츠는 소켓을 계속 따라가되 `Late_Update`에서
  렌더 큐에 안 들어간다. 기본값 `true`라 다른 클래스 동작은 그대로다.
- `CCharacter::Set_PartVisible(partTag, bool)` — `Find_PartObject` + dynamic_cast. 새 함수라
  교체 예정 함수들과 겹치지 않는다.
- `Spec_LanceMaster`에 무기 파츠 2개(`Part_90_Weapon_R`, `Part_91_Weapon_R_Short`), 둘 다
  `b_weapon_rhand`.
- `CLogic_LanceMaster::Apply_Stance()` — 스탠스가 뒤집히는 순간 호출. 파츠는 스폰 후에야
  존재하므로 최초 표시는 첫 Update에서 적용한다.

### 4.3 무기 스케일 예외를 없앴다

짧은 창을 새로 뽑아 넣으니 엔진에서 100배로 나왔다. 원인은 **긴 창만 옛 추출 경로에서
나와 있었던 것**이다.

```text
기존 WP_WFLM_00L.wmodel   2.33 유닛   <- 그래서 x100이 필요했다
새로 뽑은 긴 창            233.1 유닛
새로 뽑은 짧은 창          171.2 유닛
```

`2.33 x 100 = 233`으로 정확히 맞는다. 긴 창도 같은 방식으로 재추출·재쿠킹하고 Loader의
preTransform을 `XMMatrixIdentity()`로 통일했다.

```text
긴 창 233.1 / 짧은 창 171.2 / 대검 209.1 / 권총 30.4   (캐릭터 키 ~124)
```

**이제 프로젝트의 모든 무기가 예외 없이 identity다.** 07-29·08-01 문서에 남아 있던
"창술사 창만 x100" 설명에는 정정 표시를 넣었다.
