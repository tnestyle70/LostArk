# 2026-09-05 데미지 텍스트 원작 계약 적용 PLAN

전투 중 뜨는 데미지 숫자를 원작 `EFUI_DAMAGE` 패키지의 `damagetext.gfx` 계약대로 바꾼다. 수치는 Server
`DAMAGE_EVENT` 그대로이며 폰트·크기·팝업 방식만 바꾼다. 색은 사용자 결정으로 입힌 데미지 전부
노란색(원작 크리티컬 색), 받은 데미지 빨간색.

## 원작 자료

- 패키지 `EFUI_DAMAGE`(`OVSG0AHW8W2OD62YW96I6C.upk`) → `damagetext.gfx`. 추출본
  `D:\ClaudeWork\Extracted\DamageGfx_Extracted\`(XML, AS3, 아틀라스 PNG).
- 실전 클래스는 `ark.ui.damageText.DamageTextCBT2`(`DamageTextFactory.makeCBT2`로 생성). 텍스트 필드
  `$YoonGasiIIM` 32px, 가운데 정렬, 1080p 스테이지. 우리 `Font_EventDamage`가 이미 `YoonGasiIIM.spritefont`.
- 모션은 `DamageTextTween` 선형 두 단계. native가 값을 넘기며 데이터 테이블에 없어 AS3 factory 기본값을
  사용: phase0 450ms 32px 유지·15px 상승, phase1 70ms 32→19px 축소·100px까지 상승·alpha 1→0.
- `DamageTextWnd` 색: PC 흰색 `FFFFFF`, 적 `FF0000`, 크리티컬 `FFCC00`, 미스 `999999`, 힐 `00FF00`.
  구형 `AdvancedDamageText`($YG760 32px, type별 ease)와 `DamageTextElement`(타임라인)는 미사용 경로.
- `$eventDamageFont`(`BMKkubulimTTF.ttf`)는 만우절 이벤트용 `DamageTextFoolsDay` 전용.

## 구현

- `CMainApp::RenderDamageNumbers`: 수명 0.52s, 글자 높이 = 32px × (viewport 높이/1080)를
  `Measure_Text` 기준으로 스케일, 히트 위치 +1m 투영점에서 화면 px 상승, 색 노랑/빨강.
  crit·miss·heal은 현재 `DAMAGE_EVENT`에 구분이 없어 미적용.

## 연속 히트가 빠지던 원인 (2026-09-05 사용자 실행: 발탄 연타 시 1타만 표시)

- `CNetworkManager`가 아직 소비하지 않은 인접 `WORLD_SNAPSHOT`을 새 스냅샷으로 통째로 교체(coalesce)한다.
  수신 worker의 raw frame 큐와 main thread의 parsed event 큐 두 곳 모두. entity/player 상태는 전체 상태라
  최신만 남겨도 되지만, `DamageEvents`/`BossCombatEvents`는 그 tick에만 실리는 이벤트라 함께 사라졌다.
  TCP가 스냅샷 두세 개를 한 번에 넘기면(30Hz Server, frame당 drain) 마지막 것만 남아 히트가 빠졌다.
- 수정: parsed event 큐는 교체 전에 이전 스냅샷의 두 이벤트 벡터를 새 스냅샷 앞에 이어 붙인다(최대 256).
  raw frame 큐는 backlog가 30 frame(1초) 이상일 때만 coalesce해 cold load 보호는 유지한다.
- 같은 tick의 여러 대상 히트도 `RenderDamageNumbers` 커서가 첫 이벤트 뒤 바로 올라가 나머지를 버리고
  있었다. 루프 시작 시점 값과 비교하도록 수정.
