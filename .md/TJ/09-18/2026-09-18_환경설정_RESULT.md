# 환경설정(시스템 옵션) 창 구현 결과 (2026-09-18)

브랜치 `feature/system-options`. 조사 내용과 원작 실측값은
`.md/TJ/09-17/2026-09-17_환경설정_조사.md`(7절이 이번 전수추출)에 있고 이 문서는 구현 상태만 담는다.

## 1. 범위

조사에서 합의한 1차 범위 그대로다.

- 오디오 탭: 전체음량 / 배경음악 / 효과음. 항목마다 `켜기` 체크박스 + 볼륨 슬라이더 한 쌍.
- 비디오 탭: 화면 밝기, 후처리 효과.
- 해상도·화면 모드는 제외. `g_iWinSizeX`가 컴파일 상수이고 스왑체인을 다시 잡는 코드가 없다.
- 여는 키는 Esc이며 **다른 런타임 창이 하나도 열려 있지 않을 때만** 열린다.

## 3. 오디오 연결

- `CSound_Manager::Ready_CategoryGroups`가 FMOD master 밑에 `LostArk.Music`, `LostArk.Effect`
  두 ChannelGroup을 만들고 master에 붙인다.
- `Play_Sound` / `Play_SoundCue` / `Play_LoopingSound`는 Effect 그룹, `Play_Music`은 Music 그룹으로
  재생한다. `Play_TrackedSound`에 그룹 인자를 추가했다.
- 전체음량은 master 그룹 볼륨이다. `Update_ApplicationFocusMute`는 master의 `setMute`만 쓰므로
  `setVolume` 기반 카테고리 볼륨과 충돌하지 않는다. `켜기` 해제는 mute가 아니라 volume 0이다.
- 이미 재생 중인 채널도 그룹 볼륨 변경을 즉시 받는다.

## 4. 비디오 연결

`CRenderingProfileService::Resolve_EffectiveQuality`가 global quality와 scene profile을 합치는
유일한 통로이고 Level/region 전환마다 `Commit_Resolved`가 다시 커밋한다. 사용자 설정은 이 함수
끝에서 얹으므로 씬이 바뀌어도 유지된다. `Apply_RenderQualitySettings` 직접 호출은 쓰지 않는다.

- 화면 밝기 0..100은 profile이 가진 `fGamma`에 곱하는 배율이다(0 → ×0.75, 50 → ×1.0, 100 → ×1.25).
  절대값으로 덮지 않으므로 Level별로 저작한 밝기 차이가 유지된다. 1..3 범위로 clamp하고
  기존 `Validate_GlobalQuality`가 다시 검사한다.
- 후처리 효과 해제는 `bBloomEnabled = false`와 `SourcePostProcess.bEnabled = false`다.
  bloom tint·desaturation 같은 저작 무드값은 건드리지 않는다.
- 편집 중 즉시 반영은 `CMainApp::Update_SystemOptionWindow`가 `Take_VideoDirty()`를 보고
  현재 active profile을 다시 `Activate_Profile`하는 방식이다. Level 전환을 기다리지 않는다.

## 5. 저장

`Client/Bin/UserSettings.json`이다. `CProfilerCaptureIO::Get_CaptureDirectory`와 같은 `<exe>/..`
기준이라 Debug/Release가 한 파일을 공유한다. `Data/UI`는 저작 계약이므로 쓰지 않고 publisher도 없다.

- 로드: 파일이 없으면 기본값 유지(실패 아님). 파싱·범위 오류는 **살아 있는 설정을 그대로 두고**
  이유만 남긴다.
- 저장: `.staging`에 다 쓴 뒤 rename 한 번으로 교체한다. 중간에 끊겨도 반쪽 파일이 남지 않는다.
- 저장은 `확인` 버튼만 한다. 값 자체는 편집 즉시 적용되고, `취소`/`X`/`Esc`는 창을 열 때
  찍어 둔 snapshot으로 되돌린다.

## 6. Esc 게이트

`CMainApp::Is_AnyRuntimeWindowOpen()`이 인벤토리·캐릭터 정보·아바타·탈것·칭호·월드맵·스킬·채팅·
서버선택 창의 `Is_Open()`을 본다. 이 판정은 **각 창의 Update보다 먼저** 실행되므로 인벤토리를
닫는 Esc가 환경설정을 같이 켜지 않는다. 환경설정 자신은 이 목록에 없고 자기 Update에서 Esc
edge를 소유한다. 여는 프레임의 눌린 Esc는 `Open()`이 latch를 세워 무시한다.

## 7. 실행한 검증

- `cl /Zs` 구문 검사 통과: `UserSettingsDocument.cpp`, `SystemOptionWindowView.cpp`,
  `RenderingProfileService.cpp`, `MainApp.cpp`, `Engine/Private/Sound/Sound_Manager.cpp`,
  `Engine/Private/GameInstance.cpp`. 제품과 같은 조건(`/utf-8` 없이, CRLF 원본)으로 다시 확인했다.
- 편집한 기존 파일 5개의 줄바꿈을 CRLF로 되돌렸다(10절).
- 생성한 `SystemOption_Layout.json` / `SystemOptionStrings.json`은 생성 도구가 쓰고 다시 읽어
  파싱을 확인했다.
- `git diff --check` 통과.
- 추출한 원작 아트와 실제 게임 spritefont(`YG760`, `YoonGasiIIM`)로 두 탭 미리보기를 렌더해
  사용자에게 전달했다.
- 사용자 화면 확인(2026-09-18): 위 1차 범위에 대해 "괜찮다"는 판정을 받았다. 이어서 원작의
  나머지 탭까지 창 구성을 확장하고, 엔진이 지원하는 기능만 실제로 연결하기로 했다.

## 8. 아직 하지 않은 것

- **제품 빌드를 하지 않았다.** Engine public header(`Sound/Sound_Manager.h`, `GameInstance.h`)를
  바꿨으므로 Engine → Client 순서의 Product 빌드가 필요하다.
- 화면 확인은 사용자가 직접 한다. 창 배치·슬라이더 조작감·소리 변화·밝기 변화의 visual PASS는
  기록하지 않았다.
- 원작에 있는 나머지 오디오 항목(환경음·인터페이스·시스템음성·연주·주크박스·인물대사)과
  비디오 항목(해상도·화면 모드·품질 프리셋·계단 현상 방지 등)은 범위 밖이다.
- 탭 칼럼은 원작 비율(224px)을 유지해서 탭이 두 개뿐인 지금은 아래가 비어 보인다.

## 9. 사용자 확인 절차

1. Product 빌드: `powershell -ExecutionPolicy Bypass -File Tools/Build/Invoke-BuildAndRegression.ps1 -Configuration Debug`
2. Client 실행 후 Lobby에서 바로 `Esc`. 다른 창이 열려 있으면 그 창이 먼저 닫히고, 아무 창도
   없을 때 환경설정이 열린다.
3. 오디오 탭에서 배경음악 슬라이더를 움직여 즉시 음량이 바뀌는지, `켜기`를 해제하면 해당 계열만
   조용해지는지 확인한다.
4. 비디오 탭에서 화면 밝기를 움직여 즉시 밝아지는지, 후처리 효과를 끄면 블룸이 사라지는지 확인한다.
5. `확인`으로 닫고 재실행해 값이 유지되는지, `취소`로 닫으면 원래 값으로 돌아가는지 확인한다.
6. 맵을 이동한 뒤에도 밝기·후처리 설정이 유지되는지 확인한다.

## 10. 편집 시 주의: MainApp.cpp의 줄바꿈을 바꾸지 말 것

`Client/Private/MainApp.cpp:6319`에 `// 사망하였습니다` 주석이 있다(2026-08-26 `daaad043`,
사망 화면 작업 / PR #236). 이 한글은 UTF-8로 21바이트, 즉 홀수다. 이 파일은 `.vcxproj`에서
`/utf-8`을 받지 않으므로 CP949 source charset으로 해석되고, 마지막 `0xA4`가 lead byte로 잡혀
뒤 1바이트를 삼킨다.

| 줄바꿈 | 결과 |
|---|---|
| CRLF | `0xA4`가 `0D`만 삼키고 `0A`가 남아 줄이 정상 종료된다. 문제 없음 |
| LF | 삼킬 것이 `0A` 하나뿐이라 줄바꿈이 사라지고 다음 줄(`const float2_t vTitleMeasured = ...`)이 주석에 먹혀 `C2065`가 난다 |

저장소는 `core.autocrlf=true`라 체크아웃이 CRLF이므로 팀 빌드와 런타임은 영향이 없다.
이번 작업 중 Python `read_text`/`write_text`로 파일을 패치하면서 `MainApp.cpp`,
`RenderingProfileService.cpp`, `GameInstance.cpp`, `Sound_Manager.cpp`, `GameInstance.h`의
줄바꿈이 LF로 바뀌어 위 오류를 한 번 만들었다. 전부 CRLF로 되돌리고 `/utf-8` 없이
`cl /Zs`를 다시 돌려 `MainApp.cpp`·`SystemOptionWindowView.cpp`·`UserSettingsDocument.cpp`가
exit 0으로 통과하는 것을 확인했다.

- 기존 소스를 스크립트로 패치할 때는 바이트 단위로 읽고 쓰거나 줄바꿈을 명시적으로 유지한다.
- 이 주석 자체를 더 안전하게 하려면 같은 줄의 `strTitle`이 이미 쓰는 와이드 hex escape 방식으로
  바꾸면 된다. 다만 지금 동작에 문제가 없어 이번 변경 범위에 넣지 않았다.
