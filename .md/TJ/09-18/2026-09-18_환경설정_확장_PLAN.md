방침: **창은 원작 구성대로 전부 놓고, 엔진이 지원하는 기능만 배선한다.** 미구현 항목은 원작과 같은

## 1. 행 표는 데이터로 확정됐다

`EFTable_SystemOption`(`data2.lpk`, 787행)이 원작 환경설정 창의 정본이다. 탭·그룹·순서·컨트롤
종류·기본값·범위·선택지·행 안 좌표까지 전부 이 테이블에 있다. 스크린샷에서 옮겨 적은 것은 없다.

`Tools/LpkPipeline/build_system_option_rows.py` → `Data/UI/SystemOption/SystemOptionRows.json`
(`lostark.system-option-rows` v1). 19탭 전부를 담고 이번에 만들 7개만 `included: true`다.

| 컬럼 | 뜻 |
|---|---|
| `Tab` / `Category` | 어느 화면, 어느 탭 칼럼 부모 |
| `DisplayOrder` | 화면 안 순서. `TAB_TITLE` 행에서는 **탭 칼럼 자체의 순서** |
| `ComponentType` | 0 콤보 · 1 슬라이더 · 2 체크박스 · 3 단축키 · 4 색상 · 5 스케일라디오 · 6 버튼 · 7 그룹제목 · 8 소제목 · 9 구분선 · 10 텍스트입력 · 13 탭제목 · 14 개수라디오 · 15 라디오쌍 · 16 스피너 |
| `AttachTargetIndex` + `Direction` + `MarginX/Y` | 상대 배치. 다른 행의 `PrimaryKey`(또는 20000+ 컨테이너 앵커)에 붙어 아래(3) 또는 오른쪽(2)으로 |
| `Enabled` | 0 = 원작도 표시하지 않음 |
| `WidgetEnabled` | 그룹제목의 즐겨찾기 ★ 보유 |
| `ExportName` | 저장 태그. `UserOption.xml`의 `Tag="..."`와 동일 |
| `ChildComp01..11` | 콤보·라디오 선택지(GameMsg 키) |

탭 칼럼 순서(= `TAB_TITLE`의 `DisplayOrder`):

```
   0 비디오        300 게임플레이>전투 관련 설정     700 커뮤니티>채팅      1000~1600 단축키 7개
 100 오디오        400 게임플레이>조작 관련 설정     800 커뮤니티>매크로     1700/1900 게임패드 2개
 200 접근성        500 게임플레이>표시 관련 설정     900 커뮤니티>알림
               600 게임플레이>네임태그
```

이번 범위 7화면 = **279행** (비디오 38 · 오디오 37 · 접근성 32 · 전투 50 · 조작 22 · 표시 59 ·
네임태그 41). 커뮤니티·단축키·게임패드는 문서에 남기되 만들지 않는다.

### 검증

세 곳이 서로 맞는다.

- 테이블 ↔ 스크린샷 13장: 행 순서·그룹·선택지가 일치. 스크린샷에 없던 항목은 전부 `Enabled=0`
  (DirectX 설정, 음성 대화 옵션/HUD, 음성 언어 선택, 게임 나래이션 어시스턴트모드)이었다.
- 테이블 ↔ `UserOption.xml`: `ExportName`과 저장 태그가 동일. 스크린샷의 전체음량 14%가
  `MasterVolume=14`와 같다.
- 마우스 커서 선택지 7개 중 `기분 좋은 모코코 커서`가 인덱스 6이고 `UserOption.xml`의
  `Tag="Cursor"=6`과 일치한다.

GameMsg 키 6개는 테이블이 대문자 섞어 쓰고 GameMsg는 소문자라 처음에 비었다
(`combobox_NarrationAssistant`, `keyboard_language_Korean` 등). 도구에 소문자 fallback을 넣어
현재 참조된 모든 키가 해석된다.

## 2. 커서 — 전량 추출 완료, 원작 파일 그대로 쓴다

`Tools/LpkPipeline/extract_cursors.py`가 `EFUI_CURSOR`(`OVSG0AAS7EM7D62YWWEBO8.upk`)를 직접 읽어
`Client/Bin/Resources/UI/Cursors/<preset>/<size>/<name>.{ani,cur}` **990개**와 `manifest.json`을
쓴다. export 58개 중 커서가 아닌 2개(패키지 객체, redirector)를 제외한 56개 전부다. 세 포맷이 섞여
있고 전부 `LoadCursorFromFileW`가 그대로 읽는다.

| 포맷 | 어디에 |
|---|---|
| `.ani` (RIFF/ACON, 애니메이션) | `normal`의 preset6(모코코) 전 사이즈, `portal` |
| `.cur` (정지) | 나머지 대부분 |
| `.ico` → `.cur`로 재태깅 | export가 따로 가진 `<size>hotspotx/y`를 헤더에 써 넣음 |

데이터가 접근성 탭과 맞는 방식:

- `preset1..6` = **마우스 커서** 7선택지(기본 + 6). 모코코 = preset6 = `UserOption.xml` `Cursor=6`.
  시트로 대조: preset1 하늘색, preset3 분홍색, preset6 모코코 — 드롭다운 문구 순서와 일치.
- `<size>` = **마우스 커서 사이즈** 5단계. `normal` 48px, `large` 64, `full` 96, `xlarge` 128,
  `xxlarge` 192. 이름 순서와 달리 `large < full`이므로 픽셀 크기로 매핑한다.
- `<name>_black/_blue/_white` export = **마우스 커서 외곽선** (없음/파란색/검은색/흰색).
- 핫스팟: normal 9,9 · large 8,8 · full 17,17 · xlarge 17,17 · xxlarge 33,33 (`normal` 기준).

`.upk` 읽기는 도구 안에 자족적으로 있다(AES-256-ECB 4KB 프리픽스 + LZ4, 20바이트 chunk, 68바이트
export 레코드 — umodel 목록과 대조해 검증). 기존 `umodel_lostark_cursordata.exe`(26/51개)는 더 이상
쓰지 않는다. Desktop의 `LostArk_Cursors` PNG 26장은 정지 프레임이므로 쓰지 않는다.

## 2b. 상대 배치 규칙 — 스크린샷과 숫자로 대조해 확정

`AttachTargetIndex`/`Direction`/`Margin`을 다음 규칙으로 풀면 원작 좌표가 나온다.

```
Direction 3 (아래):   x = parent.x + MarginX          y = parent.y + parent.height + MarginY
Direction 2 (오른쪽): x = parent.x + MarginX + ANCHOR  y = parent.y + MarginY
```

- 행 높이(컨트롤별): 탭제목 24 · 그룹제목 24 · 구분선 5 · 콤보 34 · 슬라이더 24 · **체크박스 31** ·
  스피너 28 · 버튼 30 · 소제목 24. 체크박스는 gfx 도형이 30이지만 원작 pitch가 41(=31+10)이다.
- 컨트롤 내부 오프셋(gfx 실측): 체크박스 박스 = `MarginLength`+117 · 콤보 박스 = `MarginLength`,
  화살표 = 박스 오른쪽 −30 · 슬라이더 아이콘 122 / 트랙 151 / 값 오른끝 349.
- 오른쪽 붙임의 등록점 상수 `ANCHOR`: 체크박스 242 (전체음량 켜기 mx140 → 812, 빛줄기 mx50 → 798,
  회복 폰트 mx50 → 795 — 세 표본이 기울기 1로 같은 절편), 버튼 106.
- 탭 칼럼: 첫 행 y 92, pitch 39, 폭 224 (`SystemOptionBaseTreeItem`), 부모 `V2step1List`+화살표,
  자식 `V2step2List` 들여쓰기 27. 탭 제목 y = pane 14 + 42.

검증(`fit_layout.py`가 추출 크롭을 스크린샷에 템플릿 매칭, 제 렌더에도 같은 매칭):

| 화면 | 원작 | 제 렌더 | 차이 |
|---|---|---|---|
| 오디오 체크박스 9행 | (812, 186..490) | (815, 186..490) | y 0, x +3 |
| 오디오 스피커 9행 | (433, 186..490) | (436, 186..490) | y 0, x +3 |
| 비디오 콤보 화살표 | (696, 134/172) | (699, 134/172) | y 0, x +3 |
| 비디오 체크박스 4행 | 215/253/291/331 | 215/253/291/331 | 0 |
| 전투 체크박스 14개 | y 182..606 | y 181..595 | ≤11 (하단 누적) |

x의 +3은 세 화면 모두 동일해 캡처 원점 차이(창 테두리 3px)로 본다. 전투 하단의 누적 오차는
구분선→그룹제목 구간의 1~2px 반올림이 쌓인 것으로 한 화면 안에서 최대 11px이며, 원작 재현 판정에는
지장이 없어 여기서 멈춘다. 미리보기: `mock_all_tabs.py`(작업용, 미커밋).

## 3. 단계 — 현재 상태

1. **행 표 추출** — 완료. `build_system_option_rows.py` + `SystemOptionRows.json`.

   (구글에서 받은 32px)을 원작 기본 커서 48px(핫스팟 9,9)로 교체했다.
3. **위젯 구현** — 코드 완료, 미빌드. `CSystemOptionWindowView`를 다시 썼다.
   - `SystemOptionWindowView.cpp`: 프레임·탭 트리(부모 접기/펼치기, 제외 탭 3개는 접힌 채 표시)·

   - `SystemOptionWindowView_Rows.cpp`: 상대 배치 해석, 컨트롤별 런타임 슬롯(콤보+드롭리스트,
     슬라이더, 체크박스, 스피너, 라디오 목록, 색상 프레임, 그룹제목 ★, 구분선, 행 하이라이트),

4. **상대 배치 해석** — 완료(2b절 규칙, `Layout_Screen`).
5. **배선** — 아래 4절의 "지금 연결" 항목은 코드에 연결됐다.
