# 레이드 클리어 → 시상식 → 관문 진행 (2026-09-18)

브랜치 `feature/raid-clear-mvp`. 두 단계로 나눠 커밋했다.

## 1. 클리어 문양 뒤 시상식 (커밋 92941dd7)

- 발탄: 보스 사망 latch → 클리어 문양 → 문양 끝나는 순간 MVP 시상식(`CMvpResultView`, 쿠크와 같은 뷰를
  발탄 Level에 추가). 시상식을 닫은 뒤에만 돌아가기 버튼.
- 쿠크세이튼: 이 커밋에서는 클라 latch(주 보스 전멸)로 문양을 띄웠으나 2단계에서 Server 통지로 교체.
- MVP 샘플 페이지는 `CMvpAwardCatalog::Build_PreviewPage(그룹, 관문, 난이도, 인원)`로 두 Level이 공유.
  참가자 수치는 아직 샘플(서버가 기여도를 주기 전).

## 2. 관문 진행 (Server 권위, protocol 91)

### 원작 자료
- 좌상단 위젯 = `EFUI_EPICGATECOMMANDERPROCESS` `EpicGateCommanderProgressFrame`(sprite 172): bg 302×265(축약 프레임 2),
  `gateIcon0..2` (59,74)/(121,74)/(183,74) 59×65, 상태 프레임 `check`(체크 붙은 문장)·`active`(파란 글로우)·`inactive`(파란 문),
  `dungeonName` 18px (11,7) 중앙, 두 번째 줄 `[노말]`. 텍스처는 umodel로 `epicgatecommanderprocess_i5a/i52/i60`.
  호스트가 놓는 화면 위치는 문서에 없어 기준 (8,12)에 2/3 배율로 뒀다.
- 흐름 문자열(GameMsg `sys.commander.*`): `progress_vote` "던전 진행", `progress_vote_dialog_desc`
  "던전을 계속 진행하시겠습니까?", `_desc_1` "{0}님이 던전 진행을 신청하였습니다…", `progress_vote_fail_dialog_desc`,
  `stop_dungeon_progress` "중단하기". 관문 보상 창(`ResultFrame`)은 보상 데이터가 없어 이번엔 생략.

### Shared
- `C2S_GATE_PROGRESS_PROPOSE {seq, world}`, `C2S_GATE_PROGRESS_RESPOND {seq, proposalId, accept}`,
  `S2C_GATE_PROGRESS_STATE {world, gateCount, currentGate(1-based), clearedMask, proposalId, proposerNetId, accepted, total, closed, result}`.
  `NETWORK_PROTOCOL_VERSION` 90 → 91. Server/Client 함께 빌드·재시작 필요.

### Server (`GameRoom_GateProgress.cpp`)
- 관문 표(쿠크 3관문: placement id + 플레이어 위치, F1 표와 같은 값)를 Server가 소유.
- `Notify_GateBossDeath`: 주 보스 DEAD despawn 때 같은 관문의 다른 보스가 없으면 클리어 비트 세우고 broadcast
  (2관문은 대형 세이튼·쿠크 중 마지막).
- `Note_GatePlacementRaised`: 관문 placement가 올라오면(F1 버튼 포함) 그 관문을 current로.
- 투표: 파티 raid entry 투표와 같은 규칙(리더=roster front, 솔로는 즉시 확정, 30초 timeout, 거절 즉시 실패).
- `Advance_Gate`: `Reset_CardMaze` → `Despawn_KoukuSaydonArenaDebugEntities` → 다음 관문 placement spawn
  (`Build_WorldEntity`, `Apply_KoukuGateEntryCard`, broadcast) → 모든 플레이어를 기존 navigation 검증
  (`Validate_DebugTeleportDestination`)으로 이동. 죽었거나 속박된 플레이어는 자리에 남는다. Release에서도 동작.

### Client
- `CRaidGateProgressView`: 위젯(`Data/UI/RaidGateProgress/RaidGateProgress_Layout.json`, 아트 4장) + 진행/투표 프롬프트
  (`RaidGateVote_Layout.json`, 파티 초대 모달의 패널·버튼 재사용) + 상단 알림.
- 쿠크 Level: `S2C_GATE_PROGRESS_STATE`로 클리어 문양 트리거, 시상식 닫힌 뒤 리더에게 "던전 진행/중단하기",
  파티원에게 "{이름}님이 … 수락/거절", 실패 알림, Server가 올린 관문의 표현(`Apply_ServerGate`: HUD focus·
  combat analysis 초기화, Debug에서는 관문 오브젝트·조명·audition 대상까지).
- 발탄 Level: 위젯만(1관문, 클리어 시 체크).

## 3. 위젯 실측 배치·상시 표시·버튼 (재시작 / 던전 진행 / 나가기)

사용자 인게임 캡처(원작 1080p, 프레임 좌상단 (0,48))를 실측해 배치를 다시 잡았다.

### 배치(프레임 기준 원작 px, 기준 해상도에는 2/3 배율, 프레임 원점 (4,32))
- 첫 실측에서 프레임 아래 초상화 3개를 관문 아이콘으로 잘못 보고 아이콘을 프레임 밖으로 내렸다가(빈 공간·버튼 누락)
  다시 재서 원작 sprite 172 자체 배치로 되돌림. 초상화는 별도 파티 프레임.
- 제목 16px 흰색 중심 (141,28): 원작 문자열은 `tip.name.scene_group_index_name_contents_commanderraid_37081_1`
  "광기군단장 쿠크세이튼" / `…_37051_1` "마수군단장 발탄" (시상식이 쓰는 지역명 "한밤중의 서커스"가 아님).
- 난이도 13px #FFD200 중심 (141,52). 문자열은 `MvpContentNames.json`이 이미 `[노말]` 괄호를 포함하므로 뷰에서 덧붙이지 않음.
- 관문 아이콘 (59,74)/(121,74)/(183,74) 59×65(62px 간격, 난이도 줄 아래·버튼 위), 현재 관문 글로우는 92×88을 같은 중심에 `Set_SlotRect`로.
- 버튼 (56,128) 176×37 프레임 하단, 아트는 `shareimagev2_i46`의 V2 버튼(normal (643,988), over (328,988) 103×36).
- 관문이 하나도 올라오지 않은 상태(진입 직후)에는 1관문을 현재로 표시하고 `재시작` 버튼을 보인다. Server도 이때의
  RESTART를 1관문 상승으로 처리한다.
- `build_raid_gate_progress_ui.py`가 위 값으로 layout JSON(슬롯 `RGP_Bg/RGP_Button/RGP_Icon0..2`)과 아트 6장을 다시 생성.

### 버튼 상태(쿠크, `Update_GateProgress`)
- 관문이 올라와 있고 미클리어 → `재시작`(GameMsg `sys.common.annihilate_itself_vote_progress_btn`).
  누르면 `재시작 투표` 확인창(확인/취소) → `C2S_GATE_PROGRESS_PROPOSE eKind=RESTART` → 파티 투표 →
  전원 수락 시 Server `Advance_Gate(현재 관문)`: 보스 재소환·플레이어 시작 위치 이동·클리어 비트 해제.
- 현재 관문 클리어 & 다음 관문 있음 → `던전 진행`(`sys.commander.progress_vote`) 확인창 → `eKind=ADVANCE`.
- 마지막 관문 클리어 → `나가기`(`sys.common.exit_btn`) → `Request_ReturnToBern`(Server `Handle_ReturnToBern`이
  쿠크는 마지막 관문 클리어 비트가 있을 때만 허용).
- 리더(roster front)만 누를 수 있고 투표 진행 중·시상식 표시 중에는 비활성. 파티원은 같은 위젯을 보며
  투표 프롬프트만 받는다(`{이름}님이 던전 진행을 신청하였습니다 / 재시작 투표를 신청하였습니다`, 수락/거절).
- 시상식이 닫힌 뒤 리더에게 자동으로 뜨던 진행 프롬프트는 제거(원작처럼 버튼으로 시작).
- 위젯은 진입부터 계속 표시(이전에도 상시였고, 이번엔 버튼과 제목까지 포함).

### 발탄
- 제목 "마수군단장 발탄", 관문 1개. Server 관문 진행이 없으므로 버튼은 클리어 후 시상식이 닫힌 뒤 `나가기`만
  (`Request_ReturnToBern`, 기존 클리어 화면 돌아가기 버튼과 같은 경로). 재시작 투표는 발탄 Server에 없어 미제공.

### Shared/Server 변경
- `C2S_GATE_PROGRESS_PROPOSE`에 `eKind`(ADVANCE/RESTART), `S2C_GATE_PROGRESS_STATE`에 `eKind` 추가(코덱 포함).
  protocol 91 그대로이므로 이전 91 바이너리와는 호환되지 않는다 — Server/Client 함께 빌드·재시작.
- Server: RESTART는 관문이 올라와 있으면 언제든 제안 가능, ADVANCE는 현재 관문 클리어 + 다음 관문 존재 시.
  종료 broadcast에 `eKind`를 실어 Client가 재시작(같은 관문 재상승)을 구분한다.
