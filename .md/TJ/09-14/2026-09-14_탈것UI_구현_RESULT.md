# 탈것 UI 구현 결과 (2026-09-14)

브랜치 `feature/vehicle-ui`. 추출 근거는 같은 폴더의 `2026-09-14_탈것UI_전수추출.md`.
승인 범위: **리스트 4행, 탑승/탑승 해제, 탑승 중 HUD** (사용자 결정). 탭·검색·정렬·즐겨찾기·소환 모션 패널은 배치하지 않았다.

## 2. 조작

- **N**: 탈것 창 열기/닫기 (I/P와 같은 게이트: 텍스트 입력 중·ImGui 입력 중이면 무시). 원작 기본키 Alt+V는 이 프로젝트에서 `ALT_V` 스킬 슬롯이라 쓰지 않았다.
- 행 클릭: 선택 (선택 스킨 `V2step2List_selected`, 이름 `#d5ac66`). 선택하면 H 키의 우선 탈것(`Set_PreferredVehicleId`)도 같이 바뀐다.
- **탑승** 버튼: 선택한 탈것 요청. 이미 그 탈것에 탑승 중이면 라벨이 **탑승 해제**로 바뀌고 0(해제)을 요청한다. 현재 직업의 rider pose가 없는 탈것은 버튼이 disabled 스킨 + 회색 라벨.
- **닫기** 버튼 / 우상단 X / **Esc**: 창 닫기. 창 위 마우스는 `Claim_Mouse_This_Frame`으로 게임플레이 클릭을 막는다.
- 탑승 중인 행에는 원작 `equipMc` 리본 + 이름 뒤 ` (탑승중)`(`#23C9FF`) 표시.
- 탑승 가능 world는 Server가 결정한다 (`Is_VehicleRidingWorld`: BERN, CHARACTER_SELECT_ARENA). 아레나에서는 요청이 가고 `REJECTED_WORLD_NOT_ALLOWED`로 거절되며 `[Client][VehicleRiding]` 로그에 남는다.

## 3.7 탑승 중 HUD 재작성 + O 키 제거 (사용자 스크린샷 피드백 2차)

- 1차 구현(스킬 슬롯 전부 숨기고 탈것 슬롯 하나)은 원작과 달라 폐기. 원작 탑승 HUD는 HUD 틀을 그대로 두고 중앙 아이덴티티 자리에 탈것 엠블렘, Q/W/E/R에 탈것 스킬, 나머지 행은 잠금 아이콘을 보인다 → `Update_VehicleHud`를 `Update_KoukuHudMode`와 같은 형태로 다시 썼다: `Set_ActiveOwnerClass("VehicleRiding")`(아이덴티티 블록 숨김), `KOUKU_HIDDEN_SLOTS`(T/V) 숨김, `Vehicle_Hud_Emblem` 표시, `Skill_{Q..F}_Icon`에 탈것 스킬 아이콘 또는 `UI/Vehicle/Vehicle_LockIcon.png`, 쿨다운 파이 숨김. 잠금 아이콘은 quickslot.gfx 슬롯 sprite 564의 `lockMc` → shareimage `icon_lock_01`(shareImage_I5 689,492 21×27)을 원작 오프셋 (15.8,11)px대로 52×52 캔버스에 올린 것(1차에 쓴 shareimagev2 `V2contentLockIcon_01`은 자물쇠가 아니라 `!` 배지였음 — 문서 3.5절 좌표 오류). 키 라벨은 쿠크 모드처럼 T/V만 생략.
- 탈것 스킬 데이터: `EFTable_Vehicle` `SkillId0/1/2`→Q/W/E, `MovingSkill`→R (`build_vehicle_ui.py`가 `EFTable_Skill` Icon/IconIndex → IconInfo로 `UI/Vehicle/Skills/skill_<id>.png` 10장 크롭, 카탈로그 `vehicles[].skills[{slot, skillId, iconAsset}]`). 6705 Q승리포즈/W휴식/E뒷발차기/R대쉬, 7104 Q달리기, 9370 Q밤하늘/W별빛 그네/E조용한 밤/R별빛 질주, 7209 R기분 좋은 질주. 스킬은 표시만이며 Server 계약이 없어 눌러도 동작하지 않는다.

## 3.8 퀵슬롯 5~0 + 클릭 운반 등록 (사용자 지시 3차)

- HUD 우측 윗줄 키 라벨 `6 7 8 9 0`(6번째 칸 비어 있음) → `SpecialSkill_1..6` = **5 6 7 8 9 0**.
- 용도: 아래줄 `Item_1..4`(1~4) = 소비 아이템, 윗줄 `SpecialSkill_1..6`(5~0) = 탈것(추후 탈출의 노래 등). `HUD_Layout.json` 끝에 `SpecialSkill_1..6_Icon`(White1x1, 같은 rect) append.
- 클릭 운반(`CQuickSlotDragView`, 신규 `Client/Public|Private/QuickSlotDragView.*`, 레이아웃 `Data/UI/Common/QuickSlotDrag_Layout.json` slot 1개): 아이콘을 **클릭**하면 아이콘 sprite가 마우스를 따라다니고, 다음 클릭이 퀵슬롯 위면 등록·그 외는 놓음, Esc도 놓음. 운반 중에는 마우스를 claim해 이동 명령이 나가지 않는다. 모든 창보다 뒤에 생성해 최상단에 그린다.
  - 인벤토리: 같은 슬롯에서 누르고 뗀 **일반 클릭**이 `Try_Consume_ItemPick`으로 아이템을 집는다(기존 press-hold 정렬 스왑·릴리스 드롭은 유지). 아이템은 `Item_1..4`에만 들어간다.
  - 탈것 창: 행의 아이콘(슬롯 테두리 rect) 클릭 → `Take_IconPick`. 탈것은 `SpecialSkill_1..6`에만 들어간다.
  - `CMainApp::Update_QuickSlotDrag`가 두 창의 pick을 모아 운반을 시작하고 드롭 클릭을 HUD slot rect로 판정한다. 바인딩은 `m_strItemQuickSlot[4]`와 같은 Client-local(`m_iSpecialQuickSlotVehicle[6]`).
- 키 5~0: 등록된 탈것을 `CPlayerController::Request_VehicleRiding`으로 탑승, 이미 그 탈것에 탑승 중이면 해제. 레벨별 컨트롤러 조회는 `Find_ActivePlayerController()`로 합쳤다(탈것 창 버튼 경로도 같은 함수 사용).

## 4. 데이터 흐름

```
VehicleUiCatalog.json ──┐
CActorCatalog::Find_Vehicle ─┴→ CVehicleWindowView rows (카탈로그에 없는 id는 행 제외)
클릭 → Take_RidingRequest(id) → CMainApp::Update_CombatHUD
   → 현재 레벨의 CPlayerController::Request_VehicleRiding(id)
   → IPlayerCommandSink::Request_SetVehicleRiding(seq, id) → Server
   → S2C_SET_VEHICLE_RIDING_RESULT → Update_VehicleRiding가 소비(기존)
   → PLAYER_SNAPSHOT.iVehicleId → HUD_PLAYER_STATE.iVehicleId
      → 창: 리본/(탑승중)/버튼 라벨,  HUD: Update_VehicleHud
```

UI는 packet/snapshot을 직접 만지지 않고 `CCombatHUDViewModel`만 읽는다.
