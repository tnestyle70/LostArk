# 전투 분석기(축소 모드 프레임) 결과 (2026-09-14)

브랜치 `feature/combat-analysis` — **`feature/vehicle-ui` 위에 쌓음**(창 드래그 헬퍼 `CUIWindowDrag`, `Update_SpecialQuickSlots` 훅을 쓴다). 탈것 PR이 먼저 머지되면 이 PR은 전투분석기 변경만 남는다. 계획·원작 조사는 `2026-09-14_전투분석기_PLAN.md`.

## 1. 사용자 결정

- 표시 항목: 원작(피해량 / DPS / 1분 피해량 / 1분 DPS) 대신 **피해량 / DPS / 준 무력화 / 카운터 성공**. 색은 원작 카테고리 1~4(초록·주황·자주·파랑) 순서 그대로.
- 표시 조건: 지금은 **전투 HUD와 같이 항상 표시**(레이드 중 조건은 눈으로 확인한 뒤 적용). X는 그 레이드 동안만 숨기고 다음 레이드 첫 타격에 다시 뜬다.

## 4. 검증

- `cl /Zs`: `PacketMessages.cpp`(Shared), `ServerCombatHitRuntime.cpp`(Server), `CombatAnalysisFrameView.cpp`·`CombatHUDViewModel.cpp`·`ClientReplication.cpp`·`MainApp.cpp`(Client) 오류 0. `git diff --check` OK. JSON parse OK.
- Product 빌드: 사용자가 VS에서 Server(18:16)·Client(20:02) 빌드. protocol이 바뀌었으므로 **Server와 Client를 같은 커밋으로 함께 빌드·재시작**해야 한다. `NetworkProtocolHarness`는 사용자가 요청하면 실행.
- 화면 확인: 사용자 — 캐릭터 선택에서 몬스터 소환·타격으로 프레임 표시와 피해량/DPS 갱신 확인함(무력화·카운터는 보스 패턴에서만 값이 생기므로 미확인).
- 같은 날 "이펙트가 전부 안 보임" 원인: 러너 빌드가 죽은 12:14에 `Shader_VtxEffectParticleKouku2816.cso`가 0바이트로 남고 이후 증분 빌드가 최신으로 오판 → 이펙트 코어 fail-closed. 빈 CSO 삭제 후 재빌드로 해결. 이 브랜치 코드와 무관.
