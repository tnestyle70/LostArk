# 캐릭터 머리 위 이름표·말풍선·칭호 원작 재구성 결과 (2026-09-14)

브랜치 `feature/nameplate` (origin/main). 계획·원작 조사는 `2026-09-14_이름표_PLAN.md`.

## 1. 사용자 결정

- 머리 위 HP바: **전원 표시**(본인·파티원·타 플레이어), 원작 fill 아트 그대로.
- 쿠크세이튼 아레나에도 이름표 표시. 캐릭터 선택은 닉네임을 정하기 전이므로 없음.
- 채팅 말풍선도 원작(`HeadStatus_Balloon`)으로 다시 만든다.
- 칭호 시스템을 이번에 넣는다. 원작 완성형 칭호 중 추천 17개 + 프로젝트 칭호 6개(161기 최후의 4인 / 최고의 팀장 / 이펙트의 천재 / 맵 제작의 신 / 161기 최고령 / 161기 반장). 앞/뒤 조합·획득 조건·검색·필터는 넣지 않는다.

  - 원작 fill 원색: Player 청록 / Party 자주 / Friend 연두 / Enemy 빨강. host 색 프리셋 값은 gfx에 없어 원색 그대로.

## 3. 칭호 시스템 (protocol 86)

```
Data/Titles/HonorTitles.json ──Publish-HonorTitles.ps1──▶ Server/Bin/DataFiles/HonorTitles/HonorTitles.bootstrap
        │                                                          │ CHonorTitleCatalog(Server) 멤버십 admission
        └─▶ CHonorTitleCatalog(Client) id→이름                        │
P창 「칭호변경」 → CHonorTitleWindowView → CMainApp → CPlayerController::Request_HonorTitle
  → IPlayerCommandSink → CNetworkManager::Send_SetHonorTitle → C2S_SET_HONOR_TITLE
  → ServerApp → ROOM_COMMAND::SET_HONOR_TITLE → CGameRoom::Handle_/Apply_SetHonorTitle
  → S2C_SET_HONOR_TITLE_RESULT(판정) + PLAYER_SNAPSHOT.iHonorTitleId(진실)
  → CClientReplication(m_HonorTitleByNetEntityId) → REPLICATED_PLAYER_VIEW.iHonorTitleId → 이름표
  → CCombatHUDViewModel HUD_PLAYER_STATE.iHonorTitleId → P창 칭호 행·칭호 창 「사용중」
```

- Shared: `HONOR_TITLE_ID`(u32, 0 = 없음), `PLAYER_SNAPSHOT.iHonorTitleId`, `C2S_SET_HONOR_TITLE{seq, world, id}`, `HONOR_TITLE_RESULT{ACCEPTED, REJECTED_SESSION, REJECTED_WRONG_WORLD, REJECTED_STALE_SEQUENCE, REJECTED_UNKNOWN_TITLE, REJECTED_SAME_STATE}`, `S2C_SET_HONOR_TITLE_RESULT{seq, world, result, activeId}`. `NETWORK_PROTOCOL_VERSION` 84 → **86**(85는 `feature/combat-analysis`가 쓴다 — 두 PR이 모두 머지되면 버전 줄이 충돌하므로 뒤에 머지되는 쪽이 86으로 맞춘다).
- Server: `CHonorTitleCatalog::Load()`가 bootstrap(`LOSTARK_HONOR_TITLE_BOOTSTRAP\t1\tN`, `TITLE\t<id>`) 없으면 방을 준비하지 않는다(탈것과 같은 정책). `SERVER_PLAYER.iHonorTitleId`는 모든 월드에서 변경 허용(장식). 월드 이동은 `SERVER_WORLD_TRANSFER_REQUEST.iHonorTitleId` → `ROOM_COMMAND.iCarriedHonorTitleId` → `Join/Stage_PlayerEntry`가 목적지 bootstrap에 있는 id만 유지. `GameRoom_Replication`이 snapshot에 싣는다.
- Client 창: `CHonorTitleWindowView`(`Data/UI/HonorTitle/HonorTitle_Layout.json`, `UI/HonorTitle/*.png`). 원작 `honorTitleWnd`(DefaultUIWindow_V2 452×800 at (820,181.9))에서 완성형 목록(`completeTitleList` (18,167), 행 395×32, 텍스트 `$YG760` 14px `#FFFFFF` (27,6), 「사용중」 배지 (272,5) 60×30 `#1BFF8C`), 「현재 칭호 : ○○」, 적용(106,y)/해제(227.95,y) 103×36만 남기고 창 높이를 12행에 맞춰 줄였다(탈것 창과 같은 1.2배). 휠로 스크롤, Esc/X 닫기, 제목 드래그. 열 때 현재 칭호 행 선택.
- P창: 칭호 행에 catalog 이름(없으면 빈칸), 행 오른쪽에 「칭호변경」 버튼(`CI_HonorTitleBtn`, 레이아웃에 append) → 칭호 창 토글. P창을 닫으면 칭호 창도 닫힌다. `CharacterInfoDisplay.json`의 표시용 `title` 문자열은 제거.
- `Tools/LpkPipeline/build_honor_title_data.py`가 `HonorTitles.json`·레이아웃·아트를 만들고, `Tools/GameplayPipeline/Publish-HonorTitles.ps1 -Mode Publish`가 bootstrap을 만든다(`BuildDomains.json` `honortitles.catalog`, `Invoke-BuildDomainOwner.ps1 -Owner Server`에 포함).
