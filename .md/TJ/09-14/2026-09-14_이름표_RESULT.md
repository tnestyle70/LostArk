# 캐릭터 머리 위 이름표·말풍선·칭호 원작 재구성 결과 (2026-09-14)

브랜치 `feature/nameplate` (origin/main). 계획·원작 조사는 `2026-09-14_이름표_PLAN.md`.

## 1. 사용자 결정

- 머리 위 HP바: 처음엔 전원 표시로 넣었으나 09-16 사용자 확인에서 원작 화면(본인 머리 위에는 게이지 없음, 칭호+닉네임 한 줄만)과 다르다는 판정을 받아 **제거**했다.
- 쿠크세이튼 아레나에도 이름표 표시. 캐릭터 선택은 닉네임을 정하기 전이므로 없음.
- 채팅 말풍선도 원작(`HeadStatus_Balloon`)으로 다시 만든다.
- 칭호 시스템을 이번에 넣는다. 원작 완성형 칭호 중 추천 17개 + 프로젝트 칭호 6개(161기 최후의 4인 / 최고의 팀장 / 이펙트의 천재 / 맵 제작의 신 / 161기 최고령 / 161기 반장). 앞/뒤 조합·획득 조건·검색·필터는 넣지 않는다.

## 2-1. 09-16 사용자 확인 뒤 수정

사용자 판정: "하늘색 형광 바가 머리에서 한참 위에 뜨고, 칭호-닉네임이 아주 작은 흰 글씨"였고 원작 캡처는 파란 칭호+닉네임 한 줄(그 위 녹색 줄은 길드명이라 프로젝트에는 없음)이다.

- HP 게이지 제거: `CWorldPlayerNameplateView`에서 `CUILayoutRuntime`·`Initialize`·관계별 아트를 없앴다. `build_head_status_ui.py`는 말풍선 아트·레이아웃만 만들고 `HeadStatus_Layout.json`·`HS_{Frame,Fill}_*.png`는 삭제했다(`UI/HeadStatus/`에는 `HS_Balloon_Normal.png`만 남는다).
- 앵커: 고정 +2.2m 대신 몸 모델의 눈 본(`b_fc_l/r_eye_ani`, 커스터마이즈 화면과 같은 본) 높이 × presentation scale + 0.16m(정수리)로 잡고, 본이 없으면 1.75m. 말풍선도 같은 `Try_GetHeadAnchor`를 쓰고 이름판 위(`Stack_Top_RefPx` = 17 ref px)에서 시작한다.
- 글씨: 크기는 원작 12px를 1080 stage 비율로 줄이지 않고 레이아웃 기준(1280×720) 12px × **1.2**(사용자 요청) = 14.4px로 쓴다. 색은 레퍼런스 캡처 화소에서 추정: **칭호 `#3AAFFF`(하늘색), 닉네임 `#EBE8C8`(연한 노란색)** — 캡처의 칭호 구간 최대 화소 (37,128,181), 닉네임 구간 (226,224,197)을 어두운 배경과의 혼합을 감안해 역산. host 색 프리셋 값은 추출 데이터에 없다. 두 부분을 한 줄로 측정해 중앙 정렬하고 색만 나눠 그린다.
- 탑승 시 위치: 앵커를 `CTransform` 위치가 아니라 `CCharacter::Try_Get_PresentationRootMatrix`(클래스 스케일 × 월드 × 좌석 오프셋)로 눈 본을 변환해 잡는다. 탈것에 올라가면 표현 루트만 좌석 높이만큼 올라가므로 이전 방식은 이름이 몸통 위치에 남았다.
- 칭호 목록의 '그'·'고'가 위로 붙어 보이는 것: 아틀라스 오류가 아니다. 원본 `HANYoonGothic760.ttf`를 32px로 직접 래스터하면 '그'·'고'는 잉크 박스 y 10~33(높이 23), '기'·'림'은 7~38(높이 31)로 글리프 자체가 짧고 기준선 위에 떠 있다(윤고딕 700 계열 탈네모꼴). `YG760.spritefont`와 `UI/Fonts/YG760_<n>.spritefont`의 오프셋도 이와 일치한다. 원작 UI도 같은 모양이므로 그대로 둔다.
- 칭호 창이 P창 위에 열려도 P창 텍스트가 칭호 창 위로 보이던 문제: 칭호 창이 `Set_TopWindowRect`를 등록하지 않아 P창 라벨이 가림 판정을 못 했다. 아바타북과 같은 방식으로 등록하고, 칭호 창이 열린 프레임에 `CCharacterInfoWindowView::Set_Covered(true)`를 준다.

## 3. 칭호 시스템 (protocol 89)

```
Data/Titles/HonorTitles.json ──Publish-HonorTitles.ps1──▶ Server/Bin/DataFiles/HonorTitles/HonorTitles.bootstrap
        │                                                          │ CHonorTitleCatalog(Server) 멤버십 admission
        └─▶ CHonorTitleCatalog(Client) id→이름                        │
P창 「칭호변경」 → CHonorTitleWindowView → CMainApp → CPlayerController::Request_HonorTitle
  → IPlayerCommandSink → CNetworkManager::Send_SetHonorTitle → C2S_SET_HONOR_TITLE
  → ServerApp → ROOM_COMMAND::SET_HONOR_TITLE → CGameRoom::Handle_/Apply_SetHonorTitle
  → S2C_SET_HONOR_TITLE_RESULT(판정) + PLAYER_SNAPSHOT.iHonorTitleId(진실)
  → CClientReplication(m_HonorTitleByNetEntityId) → REPLICATED_PLAYER_VIEW.iHonorTitleId → 이름표
  → CCombatHUDViewModel HUD_PLAYER_STATE.iHonorTitleId → P창 칭호 행·칭호 창 「사용중」
```

- Shared: `HONOR_TITLE_ID`(u32, 0 = 없음), `PLAYER_SNAPSHOT.iHonorTitleId`, `C2S_SET_HONOR_TITLE{seq, world, id}`, `HONOR_TITLE_RESULT{ACCEPTED, REJECTED_SESSION, REJECTED_WRONG_WORLD, REJECTED_STALE_SEQUENCE, REJECTED_UNKNOWN_TITLE, REJECTED_SAME_STATE}`, `S2C_SET_HONOR_TITLE_RESULT{seq, world, result, activeId}`. `NETWORK_PROTOCOL_VERSION` 87 → **88**(09-16 origin/main 리베이스 후; main은 그사이 전투분석기 85·debug world playback 86·87까지 올라갔다).
- Server: `CHonorTitleCatalog::Load()`가 bootstrap(`LOSTARK_HONOR_TITLE_BOOTSTRAP\t1\tN`, `TITLE\t<id>`) 없으면 방을 준비하지 않는다(탈것과 같은 정책). `SERVER_PLAYER.iHonorTitleId`는 모든 월드에서 변경 허용(장식). 월드 이동은 `SERVER_WORLD_TRANSFER_REQUEST.iHonorTitleId` → `ROOM_COMMAND.iCarriedHonorTitleId` → `Join/Stage_PlayerEntry`가 목적지 bootstrap에 있는 id만 유지. `GameRoom_Replication`이 snapshot에 싣는다.
- Client 창: `CHonorTitleWindowView`(`Data/UI/HonorTitle/HonorTitle_Layout.json`, `UI/HonorTitle/*.png`). 원작 `honorTitleWnd`(DefaultUIWindow_V2 452×800 at (820,181.9))에서 완성형 목록(`completeTitleList` (18,167), 행 395×32, 텍스트 `$YG760` 14px `#FFFFFF` (27,6), 「사용중」 배지 (272,5) 60×30 `#1BFF8C`), 「현재 칭호 : ○○」, 적용(106,y)/해제(227.95,y) 103×36만 남기고 창 높이를 12행에 맞춰 줄였다(탈것 창과 같은 1.2배). 스크롤은 원작 `DefaultEFScrollBarSmall_V2`(트랙 `V2Scrollbar_updownbtn_back` 18×198 ib / 썸 `V2Scrollbar_updownbtn_{normal,over}` 14×84 i1d / 화살표 `V2Scrollbar_{up,down}Btn_{normal,over}` 14×14 i6 — 아바타 도감 `scroll_*.png`와 픽셀 일치로 페이지 확인) 그대로: 휠 한 칸 = 1행, 화살표 클릭 1행, 트랙 클릭 12행, 썸 드래그. **휠은 WM_MOUSEWHEEL → `CUIInputRouter::On_MouseWheel`/`Get_MouseWheelNotches`로 받는다**: 창 위에서 마우스를 점유하면 `SetInputBlocked(mouse)`로 DirectInput 휠(`Get_DIMouseMove`)이 0이 되어 처음 빌드에서는 스크롤이 전혀 되지 않았다(사용자 지적). Esc/X 닫기, 제목 드래그. 열 때 현재 칭호 행 선택.
  - 같은 원인으로 커스터마이즈 화면의 아이콘 격자 휠 스크롤도 죽어 있었다(`Is_Clicked`가 hover만 돼도 마우스를 점유). `CCustomizingView`도 router 휠로 바꿨다.
- P창: 칭호 행에 catalog 이름(없으면 빈칸), 행 오른쪽에 「칭호변경」 버튼(`CI_HonorTitleBtn`, 레이아웃에 append) → 칭호 창 토글. P창을 닫으면 칭호 창도 닫힌다. `CharacterInfoDisplay.json`의 표시용 `title` 문자열은 제거.
- `Tools/LpkPipeline/build_honor_title_data.py`가 `HonorTitles.json`·레이아웃·아트를 만들고, `Tools/GameplayPipeline/Publish-HonorTitles.ps1 -Mode Publish`가 bootstrap을 만든다(`BuildDomains.json` `honortitles.catalog`, `Invoke-BuildDomainOwner.ps1 -Owner Server`에 포함).
