## 2. 데이터 현황 (우리 프로젝트)

- Client가 받는 `DAMAGE_EVENT`(protocol 83): target, amount, 위치, `isOutgoing`(플레이어가 준 피해면 true), 카드미로 문양. **공격자·스킬·치명타 없음.**
- Server는 `PushDamageEvent` 시점에 `hit.iSourcePlayerId`, `hit.iSkillId`를 알고 있으나 이벤트에 싣지 않는다. 치명타 판정은 Server에 없다.
- Client는 `CCombatHUDViewModel::Get_DamageEvents()`에 최근 128개만 보관(데미지 숫자 표시용).

## 3. 범위 선택지

| | A. Client만 | B. 공격자·스킬 ID 추가 (protocol 84) |
|---|---|---|
| 피해량 / 누적 DPS / 1분 DPS | `isOutgoing` 이벤트 합산 — **파티에서는 남의 피해도 섞인다** | 내 `PLAYER_ID`만 합산, 정확 |
| 치명타 적중률 | `-` (Server에 치명타 없음) | `-` (동일) |
| 스킬별 피해(전체 창, 후속) | 불가 | 가능 |
| 변경 범위 | Client 3~4 파일 | + `Shared` DAMAGE_EVENT 2필드·codec, Server `PushDamageEvent` 호출 5곳, Server/Client 동시 재빌드·재시작 |

권장: **B**. 축소 프레임만으로도 파티 플레이에서 A는 틀린 숫자를 보여주고, 전체 창(공격 정보 탭)으로 갈 때 결국 필요하다.

## 4. 구현 (B 기준)

1. `Shared/Public/Network/PacketMessages.h` `DAMAGE_EVENT`에 `PLAYER_ID iSourcePlayerId`, `SKILL_ID iSkillId`(둘 다 INVALID 기본) 추가, `PacketMessages.cpp` write/read U32 2개, `NETWORK_PROTOCOL_VERSION` 84.
2. Server `PushDamageEvent`(ServerCombatHitRuntime.cpp)와 다른 4곳(`GameRoom_BossStageActions`, `MonsterBrain`, `GameRoom_KoukuMiniGames`, 계약 테스트)에 소스/스킬 전달. 몬스터→플레이어 피해는 INVALID 유지.
3. Client `CCombatHUDViewModel`에 전투 분석 누산기: 첫 outgoing 히트에서 전투 시간 시작, 내 `PLAYER_ID` 히트만 누적 피해·초당(누적 시간 기준)·최근 60초 링버퍼 DPS. 일정 시간(원작 전투 종료 판정 대신 20초 무타격) 후 종료 상태 유지. 로컬 PLAYER_ID는 `CClientReplication`의 진입 승인 값을 ViewModel에 노출.
4. `Tools/LpkPipeline/build_combat_analysis_ui.py`: 아틀라스 19 영역 크롭 → `Client/Bin/Resources/UI/CombatAnalysis/*.png`, `Data/UI/CombatAnalysis/CombatAnalysis_Layout.json`(프레임 470×114 → ref ×2/3, 우측 하단 (957,558)), `CombatAnalysisUi.json`(문자열·스탯 순서·색 타입).
5. `CCombatAnalysisFrameView`(`CUILayoutRuntime`, STATIC, Layer_UI, `CUIWindowDrag` 제목줄 드래그): 제목 `전투 분석기`, 전투 시간 `mm : ss` `#FFD200`, 제목 타일 4개, 값 타일 4개(색 타입 1~4), 값 포맷 만/억 단위(`ui_unit_*`), 치명타 `-`, X로 닫기. 토글 키는 사용자 결정(원작 `sys.preferences.hotkey_combat_analyzer`는 기본키 미확인) — 기본값 제안 `J`.
6. 제외: 비교 기록(ghost), 최대화(전체 창), 기록 저장, 값 상승 플래시 `increaseMc`, 설정 버튼.
