# 2026-09-26 초상 디퍼드 렌더 RESULT

대응 PLAN: `.md/TJ/09-26/2026-09-26_초상_디퍼드_렌더_PLAN.md`
브랜치: `feature/portrait-deferred-render`

## 요청과 범위

MVP 창과 P키 캐릭터 정보창의 3D 초상이 인게임 월드에 서 있는 캐릭터와 다른 모습으로
나왔다. 커스터마이즈와 의상을 반영하지 않은 기본 모델처럼 보였다. 원인은 초상이 forward
`ScreenCutin` 패스로 그려지는 데 있었다. 플레이어 몸·장비의 재질은 SourceCharacter program이며
그 계산은 디퍼드 경로에만 구현되어 있어서, forward 패스는 같은 모델을 다른 재질로 그렸다.

초상을 같은 디퍼드 경로로 옮겨 필드와 같은 재질·조명·톤 곡선을 쓰게 한다.

## 구현

### 초상 요청 경계

`CRenderer`에 `PORTRAIT_REQUEST`와 `Request_Portrait`를 추가했다. 요청은 대상 RTV와 크기,
초상 카메라의 VIEW/PROJ, 그리고 피사체를 그리는 callable을 갖는다. `CGameInstance`는
`CRenderer`를 전방 선언만 하므로 구조체가 아니라 필드 단위로 중계한다.

`CCharacterPortraitRenderer`는 더 이상 직접 그리지 않는다. `Ensure_Target`은 색 텍스처와
RTV/SRV만 만들고(깊이 없음), `Render`는 카메라를 만든 뒤 `Request_Portrait`에 피사체 draw를
넘긴다. 피사체는 `Render_PreviewParts`를 **pass 0**으로 호출한다. 이 pass 번호가
`CPart_Body`/`CPart_Equipment::Render_Pass`의 월드 재질 분기를 타게 만드는 핵심이다.

### 프레임 안에서의 위치

`CRenderer::Draw`의 `Render_Shadow` 다음, `Render_NonBlend` 앞에서 `Render_Portraits`를 돌린다.
뒤따르는 `Begin_MRT(MRT_GameObject)`가 모든 타깃을 지우므로 월드는 초상이 쓴 내용과 무관하게
깨끗한 G-buffer에서 시작한다. 초상 실패는 큐만 버리고 월드 프레임은 계속한다.

초상 한 장의 순서는 다음과 같다.

```
Set_Transform(VIEW/PROJ) -> Refresh_CameraState()
Begin_MRT(MRT_GameObject, 프레임 DSV) -> DrawSubject() -> End_MRT()
Render_Lights()
Begin_MRT(MRT_SceneHDR) -> Render_Combined() -> End_MRT()
대상 RTV 바인드 + 초상 크기 viewport -> Render_Final(true)
```

### 최초 구현의 결함 네 개와 수정

처음 구현은 화면에서 검은 실루엣과 프레임 붕괴(Character Select 17.3, 베른 3.5), 월드의 검은
얼룩을 만들었다. 넷 다 코드에서 원인을 확인해 고쳤다.

| 증상 | 원인 | 수정 |
|---|---|---|
| 초상이 형상만 있고 새까맣다 | `Render_Lights`(Renderer.cpp)는 일반 광원 패스 뒤에 `CMaterial::Get_SourceCharacterFrameCount()`만큼 stencil mask와 `LIGHT_RECEIVER::SOURCE_CHARACTER` 패스를 더 돌린다. 주석대로 일반 패스는 marker 5 픽셀을 건너뛴다. 플레이어 몸·장비는 전부 SourceCharacter program이라 marker 5이고, 이 블록을 뺀 축약 광원 함수는 shade를 0으로 남긴다 | 축약본 `Render_PortraitLights`를 삭제하고 월드 `Render_Lights()`를 그대로 호출한다. SSAO만 구간 동안 끈다 |
| FPS 붕괴 | 같은 누적기가 프레임 단위이고 `Reset_SourceCharacterFrame`이 소비한다. 초상 지오메트리 패스가 캐릭터 재질을 등록했는데 축약본이 소비·리셋을 하지 않아, 뒤따르는 월드 `Render_Lights`가 초상 몫까지 물려받아 전체 화면 source-light 패스를 매 프레임 추가로 돌렸다. 장면이 무거운 베른에서 더 심했다 | 같은 수정. `Render_Lights`가 자기 안에서 `Reset_SourceCharacterFrame`을 호출한다 |
| 월드에 검은 얼룩 | `CTarget_Manager::Begin_MRT`는 `pDSV`를 넘기지 않으면 기존 DSV를 그대로 쓰고 깊이를 지우지 않는다. 초상 카메라 깊이가 프레임 DSV에 남아 뒤따르는 월드 지오메트리가 깊이 테스트에서 탈락했다 | 초상마다 프레임 DSV를 `Begin_MRT`에 넘겨 지우고, 루프 끝에서 월드용으로 한 번 더 `ClearDepthStencilView`한다 |
| 조명이 월드 카메라 기준 | `CPipeLine::Set_Transform`은 역행렬과 카메라 위치를 갱신하지 않는다. 그 유도는 `Refresh_CameraState`가 프레임당 한 번 한다. 광원·합성 패스는 `Get_InverseTransform`과 `Get_CamPosition`으로 월드 위치를 복원하므로 초상이 월드 카메라 기준으로 셰이딩됐다 | 초상마다 `Refresh_CameraState()`를 호출하고 루프 끝에서 원래 VIEW/PROJ 복원 후 다시 호출한다. 이를 위해 그 선언을 `CGameInstance`의 PipeLine public 섹션으로 옮겼다 |

### 배경 투명

`PS_MAIN_FINAL`은 알파를 항상 1로 쓴다. 초상 대상은 UI 텍스처이므로 피사체가 쓰지 않은
픽셀이 장면의 fog·ambient를 받으면 창에 배경이 깔린다. `Target_Depth`는 clear 색이
`(1,1,1,0)`이라 marker lane이 0인 것이 그대로 "여기엔 지오메트리가 없다"는 검사다.

`DEFERRED::PORTRAIT_RESOLVE`(pass 30)와 `PS_MAIN_PORTRAIT_RESOLVE`를 technique 끝에 추가했다.
기존 30개 pass 인덱스는 그대로다. marker lane을 픽셀 단위로 읽어 0이면 완전 투명을,
아니면 `Resolve_FinalFXAA` 결과를 쓴다. `Renderer.cpp`의 DEFERRED 인덱스 `static_assert`도
같이 확장했다(`PORTRAIT_RESOLVE = 30`, `END = 31`).

`Render_Final`은 80줄짜리 사본을 만들지 않고 `bool_t bPortrait = false` 분기를 받았다. 초상일
때는 screen post 체인이 돌지 않았으므로 `Target_SceneHDR`를 직접 읽고, bloom과 material debug
view를 끄고, 이 pass를 선택한다.

## 남은 경계

초상 한 장이 전체 프레임 해상도로 G-buffer·조명·합성·톤맵을 한 번 더 돈다. 누적기 누수를
막았으므로 추가 비용은 "캐릭터 한 명 분량의 광원 패스" 수준이지만 초상 개수만큼 곱해진다.
초상 크기 viewport로 줄이려면 디퍼드 체인의 모든 패스에 UV 창을 넣어야 한다. 광원·합성 패스의
full-screen quad는 viewport와 무관하게 UV 0..1을 쓰므로 viewport만 줄이면 G-buffer가 쓰인
영역과 읽는 영역이 어긋난다. 이는 별개 작업이다.

`Render_Lights`를 그대로 호출하므로 초상도 월드 그림자 맵을 읽는다. 캐릭터가 월드 위치에
서 있고 그림자 조회가 월드 위치 기준이므로 맞는 동작이다. 광원 절두체 컬링은 초상 카메라의
frustum을 쓴다(`Refresh_CameraState`가 함께 갱신하고 끝에 복원한다).

PLAN의 G05 — 이제 쓰이지 않는 `ScreenCutin` 패스를 `Shader_VtxAnimMeshBinary.hlsl`,
`Shader_VtxMeshBinary.hlsl`에서 제거하는 작업 — 은 하지 않았다. 다른 소비자가 남아 있는지
확인한 뒤 별도로 진행한다.
