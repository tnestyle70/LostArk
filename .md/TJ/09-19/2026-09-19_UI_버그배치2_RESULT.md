# 팀 테스트 UI 버그 2차 (2026-09-19)

브랜치 `feature/ui-bugbatch2-0919` (main 8dc16688 기준). 1차 배치(#413) 이후 제보된 8건.

## 1. 텍스트가 창 위로 뚫고 나오는 문제 — 근본 수정

### 원인
- `CGameInstance::Render()`는 `CRenderer::Draw()`(모든 UI 스프라이트, `RENDERGROUP::UI`) 다음에
  Level `Render()`(이름표·말풍선·레벨 팝업 텍스트)를 부르고, `CMainApp::Render()`의 UIText 단계가 그 뒤에
  나머지 텍스트를 그린다. 즉 **모든 텍스트가 모든 UI 스프라이트보다 나중에** 그려져, 어느 창의 글씨든
  다른 창 위로 올라온다.
- 그동안은 창마다 clip-out 사각형을 손으로 추가(`Add_OpenWindowTextClipOuts`, `Set_TopWindowRect`,
  창 목록 `ClipAbove`)해 때웠고, 새 창·팝업이 생길 때마다 뚫림이 재발했다.
- 1차 배치에서 팝업 자기 영역을 clip-out에 넣은 탓에 그 팝업 **자기 텍스트까지 지워졌다**
  (던전 진행 창, 파티초대 패널, 수락/거절 창 텍스트 누락 = 제보 5·6번).

### 수정: `CUITextOcclusion` (UI 텍스트 층 레지스트리)
- `Client/Public|Private/UITextOcclusion.*` (필터 `02.GameObjects\04. UI`).
- 층: `WORLD 0` < `HUD 100` < `WINDOW 200(+창 순번)` < `MODAL 300` < `PAGE 400`.
- 매 프레임 `Begin_Frame()`(입력 라우터와 같은 시점)에서 비우고, 보이는 UI 표면이 자기 화면 영역과 층을
  `Add_Occluder`/`Add_SlotOccluder`로 등록한다.
- 텍스트는 `CUITextLayerScope(층)` 안에서 그린다. 그 층보다 **높은** 층의 영역만 clip-out으로 적용되므로
  자기 창 글씨는 자기 창에 지워지지 않고, 위에 덮은 창 영역에서만 가려진다.
- 스코프 밖 텍스트는 `WORLD`로 취급(이름표·말풍선·데미지 숫자). 레벨 Render 직전에 `Apply(WORLD)`.
  층을 선언하지 않은 텍스트는 어떤 UI도 뚫지 못한다.
- 등록한 표면
  - WINDOW: 인벤토리(+0), 캐릭터정보(+1), 아바타도감(+2), 탈것(+3), 칭호(+4), 월드맵(+5), 환경설정(+6), 강화(+7)
  - HUD: 파티창(타이틀·행 심볼·HP바), 에스더 창, 관문 진행 위젯
  - MODAL: 파티 컨텍스트 메뉴·초대 팝업, 관문 진행/재시작 프롬프트, 베른 레이드 입장 창(전체 화면 딤),
    커스터마이징 화면(전체 화면)
  - PAGE: MVP 시상식(전체 화면)
- 텍스트 층: 전투 HUD·보스바·쿨다운·퀵슬롯·에스더·미니맵·채팅·파티창·데스/클리어 문구 = HUD,
  인벤토리·각 창·강화 = 각 WINDOW 순번, 모달류 = MODAL, MVP = PAGE, FPS = PAGE.
- 제거: `CUIInputRouter::Set_TopWindowRect`의 clip 설정, `ClipAbove` 창 루프, 1차의
  `Add_TextClipOuts()` 두 개(자기 텍스트를 지우던 원인).

## 9. ESC로 창 하나씩 닫기
- 증상: 인벤토리(I)·캐릭터 정보(P)·아바타 도감은 ESC로 닫히지 않았다. 탈것·칭호·월드맵 창은 각자 ESC를 읽어
  여러 창이 떠 있으면 한 번에 전부 닫혔다.
- 수정: 창별 ESC 읽기를 없애고 `CMainApp::Update_SystemOptionWindow`의 ESC 한 엣지로 모았다.
  `m_EscapeWindowOrder`가 인벤토리·캐릭터 정보·아바타 도감·칭호·탈것·월드맵을 연 순서대로 기억하고
  (`Sync_EscapeWindowOrder`, 매 프레임), ESC 한 번에 가장 나중에 연 창 하나만 닫는다(`Close_TopEscapeWindow`).
  아바타 도감·칭호 창은 캐릭터 정보 위에 열리므로 먼저 닫히고, 월드맵은 구멍 설명창이 있으면 그것부터 닫는다
  (`CWorldMapWindowView::Handle_EscapeEdge`).
- ESC 우선순위: 시스템 옵션 → MVP 화면 → 강화 창 → 스스로 ESC를 처리하는 것(퀵슬롯 아이콘 들기,
  Bern 발탄 입장 팝업, Debug 캐릭터 선택 레이드 미리보기)은 그 한 번만 가져간다 → 토글 창 하나 → 아무것도 없으면
  시스템 옵션 열기. 발탄 입장 팝업이 떠 있을 때 ESC가 시스템 옵션까지 여는 경우도 이것으로 막힌다.
- 파일: `MainApp.h/.cpp`, `InventoryView.h`(`Close`), `Level_Bern.h`(`Is_ValtanEntryModalOpen` public),
  `VehicleWindowView`·`HonorTitleWindowView`·`WorldMapWindowView`(창별 ESC 읽기와 그 때문에만 쓰던 dinput include 제거).
- 대상 외: 파티 창은 토글 창이 아닌 상시 패널, 스킬 창(K)은 현재 생성되지 않는 경로.
- 검증: MainApp(utf-8)·VehicleWindowView·HonorTitleWindowView·WorldMapWindowView·InventoryView·Level_Bern `cl /Zs` 통과,
  `git diff --check` 통과, 인코딩·CRLF 유지. 제품 빌드·실행 확인은 아직(사용자).

## 10. 시상식(MVP)을 서버 기여도로 구성
- 증상: 시상 화면이 고정 샘플(Test/Berserker/Bard/Sorceress)을 쓰고, 네 칸 모두 로컬 캐릭터 한 명을 세웠다.
- Shared(protocol 97): `S2C_RAID_MVP_RESULT`(world, gate, 참가자별 player/entity/class/닉네임, 보스 피해량,
  무력화, 카운터 성공 수, 생존 틱/교전 틱). 94 이하 peer와 섞어 실행할 수 없다(Server·Client 함께 빌드·재시작).
- Server: 보스 엔티티 `MvpLedger`에 `CServerCombatHitRuntime::Apply_PlayerToWorld` 보스 분기가 실제 피해·무력화·
  카운터를 기록하고, 첫 타격 이후 매 틱 `Tick_MvpLedgers`가 방 인원의 교전·생존 틱을 센다. 관문 보스가 죽으면
  장부를 방(`m_GateMvpLedger`)에 합치고, 쿠크 관문 클리어(`Notify_GateBossDeath`, 레이드 흐름의
  `Notify_KoukuRaidBossDeath`)와 발탄 클리어(보상 지급 지점)에서 방 전원에게 보낸다. 관문을 다시 올리면 비운다.
- Client: `CNetworkManager` 큐 → `IPlayerCommandSink::Consume_RaidMvpResult` → 쿠크/발탄 레벨.
  `CMvpAwardCatalog::Build_ServerPage`가 파티 합계 대비 비율로 칭호를 판정하고(`Compose_Page`), 핵심(core) 기여
  비율 합이 가장 큰 사람이 MVP다(support는 동점 판정만). 교전 내내 살아 있으면 생존 칭호. 페이지 순서
  (MVP, 오른쪽 세 칸)대로 `Collect_PlayerViews`에서 그 플레이어의 캐릭터를 찾아 각 칸에 세운다.
- 수치 표시: 원작 캡처(f1701)처럼 MVP 칸만 파티 대비 정수 비율("51%")을 찍고, 파티원 칸은 칭호·기여도 이름만 표시한다.
- 배지: 칭호와 별개의 업적이다(원작 `EFTable_MvpMedalGroup` Param). 서버가 사실값(부위 파괴 피해, 막타 수, 교전 중 HP가
  줄어든 횟수, 최저 HP 비율, 클리어 시 생존, 연속 카운터 최소 간격)을 보내고 클라이언트가 Param1로 판정한다.
  회피의 달인(피해 3회 이하), 기사회생(HP 20% 이하 후 생존), 피니셔(보스 막타), 카운터 스페셜리스트(15초 이내 카운터 2회,
  사용자 확인 해석), 헤비 스매셔(부위 파괴 피해 1위), 뿌리 깊은 거목(`KNOCKDOWN` 진입 3회 이하 + 교전 180초 이상,
  Param1 180000을 ms로 해석).
- 표시하지 않는 것: 서버에 회복·보호막·배틀 아이템·약점 공격·감금·광폭화 판정이 없어 해당 칭호·배지는 나오지 않는다.
- 서버 결과가 없을 때: 제품 경로는 시상 페이지를 띄우지 않는다. Debug 빌드의 테스트 클리어(쿠크 Debug 버튼,
  발탄 O키)만 샘플 페이지를 쓰고 로컬 캐릭터는 MVP 칸에만 세운다. 쿠크 Debug `Show MVP`는 마지막 서버 결과를 다시 연다.

## 11. 장비 장착·해제 (캐릭터 정보창 ↔ 인벤토리)
- 이전: 캐릭터 정보창 장비 13칸은 표시용 `CharacterInfoDisplay.json`의 직업별 고정 ID였고, 서버에는 장착 개념이 없었다.
- 조작: 원작 슬롯(`ARKNewSlot.as`)은 우클릭·더블클릭을 모두 게임 본체로 넘긴다. 좌클릭 한 번이 이미 퀵슬롯 집기라
  더블클릭과 겹치므로 우클릭으로 한다. 인벤토리 장비 우클릭 = 장착, 캐릭터 정보창 장비 우클릭 = 해제.
- Shared(97에 포함): `EQUIPMENT_SLOT`(13칸), `INVENTORY_ITEM_SNAPSHOT::eEquippedSlot`(장착 장비도 같은 인벤토리 목록에 남아
  스냅샷·월드 이동을 그대로 따라간다. (아이템, 칸) 쌍과 각 칸은 유일), `C2S_SET_EQUIPMENT`, `Equipment_SlotKind`.
- Server: `Items.bootstrap` v3가 equipSlot·characterClass를 싣는다(`-` = 없음). `Handle_SetEquipment`가 부위·직업·가방 여유를
  검사해 옮기고(교체된 장비는 가방으로) 결과와 무관하게 인벤토리 스냅샷으로 답한다. 직업 변경 시 다른 직업 장비는 가방으로.
  물약 사용과 지급은 가방 항목만 다룬다.
- 초기 장비(사용자 결정): 공용 장신구 7종(목걸이·귀걸이 A/B·반지 A/B·어빌리티 스톤·팔찌)은 원래 표시와 같은 칸에 착용된
  채로 시작한다. `ItemCatalog.json`의 `startingEquippedSlot`(necklace, earring1/2, ring1/2, stone, bracelet)이 정본이고
  `Items.bootstrap` v4 7번째 열로 서버에 가며, 새 입장(가져온 인벤토리가 없을 때) 물약과 함께 지급한다. publisher는 칸 종류·
  직업 무관·칸 중복을 검사한다. 무기·방어구 칸은 비어 있다.
- 발탄 클리어 보상: `Valtan.clearrewards.json` formatVersion 2가 직업별 목록을 갖는다. 워로드·창술사·도화가·차원술사가 각자
  원래 착용 표시였던 명예의 속삭임 6부위를 받는다(`ClearRewards.bootstrap` v2, `CLASS	ITEM` 24행). 건슬링어·슬레이어는
  보상이 없다(사용자 결정). 이전 목록(운명의 업화 6부위 전원 지급, 08-28 `f8aefd35`)은 카탈로그에만 남는다.
- Client: 인벤토리는 장착 중인 장비를 가방 목록에서 뺀다. 우클릭 장착 시 같은 종류 중 빈 칸(귀걸이·반지 두 칸), 둘 다 차 있으면
  첫 칸을 고른다. 캐릭터 정보창은 서버 인벤토리의 장착 항목을 그리고, 아바타 도감·칭호 창이 덮고 있으면 우클릭을 받지 않는다.
  표시용 JSON의 `equippedItemIds` 6개 블록과 그 로더는 삭제(아바타 `equippedAvatarItemIds`는 유지).
- 게시: `Publish-ItemCatalog.ps1 -Mode Publish`, `Publish-ValtanClearRewards.ps1 -Mode Publish` 실행 완료(로컬 Server/Bin).
  다른 PC는 두 publisher를 다시 실행하거나 `Invoke-BuildDomainOwner.ps1 -Owner Server`가 필요하다.
- 장비는 능력치·외형에 영향을 주지 않는다(표시·보관만).
