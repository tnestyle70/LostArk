## 4. 배경 — 어디가 움직이고 어디가 고정인가

한 화면 안에 성격이 다른 네 계층이 섞여 있다. 뭉뚱그리면 안 된다.

| 계층 | 정체 | 크기 | 움직임 |
|---|---|---|---|
| 틀(패널 아트) | `.gfx` 안 정지 DDS `centerMVPBG*.nopack` | 1189x1080 x2, 1280x1080 | **고정**. f35/f65에 한 번 배치되고 이후 모션 태그 없음 |
| 3D 캐릭터 4명 | 호스트가 넣어주는 텍스처 | 런타임 결정 | 실시간 3D |

| 파티원 3칸 배경 | 정지 DDS | 320x1080 | 고정 |

### 4.1 3D 캐릭터는 이미지 치환으로 들어온다

`.gfx`에는 캐릭터 그림이 한 장도 없다. `placeFlagHasClassName=true` +
`placeFlagHasImage=true`인 빈 자리 네 개가 있을 뿐이고, C++ 쪽이 그 className에 텍스처를 물린다.

```
MvpPlayerTexture        sprite 222 (MvpResultGFxRenderTarget) 안 (0,0)
MvpSubPlayerTexture_0   sprite 211 = otherStatItem0 의 renderTex0 (0,0)
MvpSubPlayerTexture_1   sprite 212 = otherStatItem1 의 renderTex1 (0,0)
MvpSubPlayerTexture_2   sprite 213 = otherStatItem2 의 renderTex2 (0,0)
Shared_MvpClassBigSymbol  sprite 275 (MvpResultFrame) 안 (485,616)  <- 클래스 심볼도 같은 방식
```

`MvpResultGFxRenderTarget`(char 222)은 그림이 전혀 없는 순수 영역 표시자다. `GFxRenderTarget`
컨트롤은 마우스 이벤트(RollOver/RollOut/Press/Release)를 네이티브로 넘기는 일만 한다. 즉 이
사각형이 **네이티브가 3D를 그려 넣을 자리**다.

### 4.4 배경은 레이드별이 아니다 — `기본` 채택 (2026-09-11 결정)

16개 배경 중 쿠크세이튼이나 발탄 이름을 단 것은 없다. `sys.mvp.background_how_to_get_*`를 보면

## 5. 화면 배치

### 5.1 최상위 앵커 — `mvp_fla/MainTimeline.as`

```
mvpResultFrame.widgetX        = 980
mvpResultFrame.widgetY        = 641
mvpResultFrame.pivotType      = "center"
mvpResultFrame.sortingLayer   = "3_topmostHUD"
mvpResultFrame.orderInLayer   = 2000
mvpResultFrame.positionU      = 1
mvpResultFrame.positionV      = 0
mvpResultFrame.fixedWidth     = 1080
mvpResultFrame.fixedHeight    = 1920
```

스테이지는 `displayRect` 38400x21600 twips = **1920x1080**, `frameRate` 40이다.

`positionU=1`은 이 경우 무시된다. `ark/layout/LayoutSetter.as:328`의 UV 분기 조건이
`widgetX == 0 && widgetX == 0`(두 번 다 X를 본다)이라 `widgetY`/`positionV`와 무관하게
`widgetX = 980`이 0이 아니면 UV 모드로 가지 않는다. 따라서 `widgetX/widgetY`가 그대로 쓰인다.

`pivotType = "center"`이므로 `LayoutUtil.setWidgetGlobalPosition`이 프레임의 바운딩 박스
중심을 (980, 641)에 맞춘다. 프레임 1의 바운딩 박스는 전체 화면 딤인 `modaldal`(char 226)이
지배하며 로컬 x -20..2580, y 0..1080이다. 중심은 (1280, 641.5)이므로

```
화면좌표 = 로컬좌표 - (300, 0.5)
```

가 된다. **이 -300은 필드에서 읽은 값이 아니라 위 규칙으로 계산한 값이다.** 아래 표에는 원본
로컬값과 계산된 화면값을 같이 적는다. 프로젝트 레이아웃 JSON은 1280x720 기준이므로 화면값에
1280/1920 = 0.666667을 곱해 쓰면 된다.

### 10.2 좌표계 — 오프셋이 MVP와 다르다

`epicGateCommonClear_fla.MainTimeline`:

```
widgetX = 0      widgetY = 0
positionU = 0.5  positionV = 0.5
pivotType = "center"
fixedWidth = 2560   fixedHeight = 1080
sortingLayer = "3_topmostHUD"
```

`widgetX == 0`이고 `positionU != 0`이므로 `LayoutSetter`의 UV 분기를 탄다. 거기서
`pivotOffsetX = fixedWidth * positionU = 1280`이 되어 **문서의 local (1280, 540)이 화면 중앙**에
놓인다. 즉

```
screen = (local - 320, local_y)      그다음 x2/3
```

MVP 문서는 `widgetX = 980`이라 UV 분기를 타지 않고 오프셋이 -300이다. **두 문서의 오프셋이
다르다.** 스테이지는 둘 다 `displayRect` 1920x1080이다.

### 12.6 MVP 배지 등장 연출 (2026-09-12)

사용자가 "파티 배지는 처음부터 있는데 MVP 것만 새로 박힌다"고 지적했고, 그대로 데이터에 있었다.

기본값이라 이 리스트에는 적용되지 않는다 — 실제로는 고정 스태거다.

### 13.7 사용자 화면 확인 2차 교정 (2026-09-12)

레퍼런스 `D:/ClaudeWork/Extracted/MVP/frames/f1701.png`과 대조해 5건을 확인했다.

#### 글자 선명도 — 원인은 폰트 아틀라스 배율

`.spritefont` 헤더를 직접 읽어 실측했다.

| 아틀라스 | lineSpacing | `가` 글리프 |
|---|---|---|
| `YoonGasiIIM.spritefont` | 32.1 | 27×27 |
| `YG760.spritefont` | 41.8 | 30×32 |

`Draw_Label`이 `(fFontPx * fUiScale) / Measure_Text("Ag").y`로 직접 배율을 냈기 때문에
1920 기준 화면 배율이 이렇게 나온다.

| 라벨 | 저작 pt | 배율 | 증상 |
|---|---|---|---|
| MVP 제목 | 110 | **3.43× 확대** | 27px 글리프를 93px로 늘림 |
| 준 피해 / 준 무력화 | 16 (YG760) | **0.38× 축소** | 밉맵 없는 축소라 획이 뭉개짐 |
| 길드명 | 20 (YG760) | 0.48× 축소 | 같은 증상 |
| 기여도 수치 | 44 | 1.37× | 약간 흐림 |

`UILabelFont::Resolve`가 이미 이 문제를 위해 존재하는데(10~20px 사전 다운샘플 변형 선택)
이 화면만 쓰지 않고 있었다. 세 갈래로 고쳤다.

1. `Draw_Label`이 `UILabelFont::Resolve`를 거치게 했다. 16pt는 `YG760_20`을 1:1로 집는다.
2. `BAKED_SIZES`에 25를 추가하고 `YG760_25` / `YoonGasiIIM_25`를 구웠다(20pt 라벨용).
3. 20px 위로는 다운샘플할 원본이 없으므로 **TTF에서 다시 래스터라이즈**했다.
   `font.lpk`에 `YoonGasiIIM.ttf`와 `HANYoonGothic760.ttf`가 그대로 들어 있다.

새 도구 `Tools/FontPipeline/bake_spritefont.py`가 DXTK `.spritefont`(BC2)를 굽는다.
폰트 아틀라스는 흰색 + 커버리지 알파라 BC2의 4비트 알파 블록에 그대로 들어가고
컬러 블록은 상수 흰색이므로 탐색이나 손실이 없다. 문자 집합은 기존 파일에서 복사해
크기마다 글리프가 달라지지 않게 한다.

굽는 중 세 번 틀렸고 셋 다 기존 파일과의 실측 대조로 잡았다.

- Pillow `textbbox`는 잉크 상자가 아니라 펜 기준 레이아웃 상자라 모든 글리프의 X 오프셋이
  0이 되고 서브렉트가 어드밴스만큼 부풀었다. 렌더한 비트맵의 `getbbox()`로 바꿨다.
- DXTK `ForEachGlyph`는 펜을 `XOffset` → `서브렉트 폭 + XAdvance` 순으로 밀고 `XOffset`을
  되돌리지 않는다. `XAdvance = advance - width`로 저장했다가 `- XOffset`을 빠뜨려
  글자 간격이 벌어졌다. 기존 파일과 펜 전진량을 대조해 확인했다.
- **BC2 컬러 절반을 상수 흰색으로 넣었다.** 화면에 `MVP` 대신 흰 박스 3개가 떴다.
  기존 아틀라스를 디코딩해 보니 `c0=0xFFFF c1=0x0000` 램프에 인덱스로 커버리지를 실어
  RGB가 알파를 따라간다 — SpriteBatch의 기본 블렌드가 프리멀티플라이드이므로
  아틀라스도 프리멀티플라이드여야 한다. RGB가 상수 1이면 글리프 상자 안 모든 텍셀이
  불투명 흰색으로 그려진다. 알파 절반은 4비트 커버리지 그대로, 컬러 절반은 같은 값을
  램프의 네 단계로 양자화하도록 고쳤다.

이 세 번째 결함은 알파만 보던 첫 검증을 그대로 통과했다. 그래서 검사를 도구로 만들었다.
`Tools/FontPipeline/verify_spritefont.py`가 포맷·stride·코드포인트 순서·서브렉트 범위와
**컬러 절반이 알파를 따라가는지**를 검사한다. 기존 배포 18개와 그 시점까지 구운 10개 전부 OK이고,
컬러 절반을 일부러 상수 흰색으로 되돌린 사본은 FAIL로 잡는 것까지 확인했다.

### 13.8 폰트 전환이 만든 두 결함과 교정 (2026-09-12)

13.7의 폰트 교체 직후 두 번 더 틀렸다. 둘 다 사용자 화면 관찰로 드러났고
레퍼런스와의 수치 대조로 확정했다.

#### 결함 1 — `MVP` 자리에 흰 박스 세 개

BC2 컬러 절반을 상수 흰색으로 넣었다. 기존 아틀라스를 디코딩해 비교하니 명확했다.

```
기존 YoonGasiIIM_20   c0=0xFFFF c1=0x0000   (alpha,red) = (0,0) (255,255) (204,170) (85,85)
내 Latin128 (결함)     c0=0xFFFF c1=0xFFFF   (alpha,red) = (0,255) (255,255) (17,255)
```

SpriteBatch 기본 블렌드가 프리멀티플라이드이므로 아틀라스도 RGB에 커버리지를 담아야
한다. RGB가 상수 1이면 글리프 서브렉트 안 모든 텍셀이 불투명 흰색으로 그려진다.
컬러 절반을 `c0=흰색 / c1=검정` 램프로 바꿔 커버리지를 네 단계(255/170/85/0)로
양자화해 넣도록 고쳤다.

이 결함은 알파만 보던 첫 검증을 그대로 통과했다. 그래서 검사를 도구로 만들었다 —
`Tools/FontPipeline/verify_spritefont.py`가 포맷·stride·코드포인트 순서·서브렉트
범위와 **컬러 절반이 알파를 따라가는지**를 검사한다. 배포 18개와 새로 구운 14개
전부 OK, 컬러 절반을 일부러 되돌린 사본은 FAIL로 잡는 것까지 확인했다.

#### 결함 2 — 컨텐츠명이 MVP를 파고듦

`UILabelFont`로 넘기면서 다른 창들이 쓰는 `EM_TO_LINE_SPACING = 1.25`를 그대로
가져다 붙였다. 이 화면의 `CanvasPt()` 값은 em이 아니라 이미 line spacing이다 —
이전 코드가 `Measure_Text().y`(= 아틀라스 line spacing)로 나누고 있었으므로.
그래서 모든 라벨이 1.25배로 커졌다.

레퍼런스 대조로 확정했다. 파티 열 이름 x좌표로 캡처 배율을 먼저 구하고 폭을 비교했다.

```
캡처 배율 (파티 열 734/942/1159 -> 915/1181/1448) = 1.250
MVP 폭      기대 206  실제 265  -> 1.28배
컨텐츠명 폭   기대 235  실제 300  -> 1.28배
```

계수를 빼고 실제 상수로 겹침을 재계산했다.

```
수정 전  컨텐츠명 아래 527.0  MVP 위 525.6  간격 -1.4  겹침
수정 후  컨텐츠명 아래 525.2  MVP 위 533.7  간격  8.5  OK
```

같은 작업에서 `BAKED_SIZES`에 22와 28을 추가해(`LARGEST_BAKED` 28) 25~32 구간의
배율 틈을 메웠다. `SMALLEST_LATIN_DISPLAY`는 40에서 36으로 낮췄다 — 그 아래에서는
family 아틀라스(32px)가 최소 디스플레이 단계보다 1:1에 가깝다.

#### 최종 배율

세 해상도에서 라벨 12종이 고르는 아틀라스와 배율을 대조했다.

| 해상도 | 1:1로 그리는 라벨 | 최악 배율 |
|---|---|---|
| 1600×900 | 8 / 12 | 0.92 (기여도 수치) |
| 1920×1080 | 9 / 12 | 1.15 (MVP 제목) |
| 1280×720 | 10 / 12 | 0.91 (기여도 수치) |

교체 전 최악이 3.43배(MVP 제목)와 0.38배(기여도 항목)였다.
