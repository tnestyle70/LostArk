# 2026-09-06 캐릭터 커스터마이징 PLAN

원작 `charactercustomizing` 화면을 우리 6개 클래스(건슬링어 제외 5개)에 그대로 옮긴다.
데이터 출처와 추출 도구는 `2026-09-06_커스터마이징_원작데이터_추출_RESULT.md`, UI 배치는
`2026-09-06_커스터마이징_원작추출_REFERENCE.md`를 따른다. 진입 위치는 사용자 결정대로
`클래스 선택 → 커스터마이징 → 이름 입력`이다.

## 1. 원작 동작 실측

| 기능 | 원작 구현 | 우리 적용 |
|---|---|---|
| 얼굴 세부 슬라이더 18개 | 얼굴 AnimSet의 additive 시퀀스 `add_<slider>_ui`. 3프레임이고 1번 프레임이 항등(중립), 0·2번이 양끝. 가중치 0.5가 기본 | PSA에서 본별 3키를 JSON으로 뽑아 `Set_BoneLocalMatrix`로 합성 (G1) |
| 얼굴형·눈·코·입 프리셋 | MorphTargetSet 45개(FT), 프리셋별 가중치 | MorphTarget raw → 얼굴 wmodel 정점 델타 적용 (G3) |
| 체형 | AnimTree SkelControl 13개(본 scale 최대 2.0, spine1 높이·허벅지 이동) | 같은 본 이름에 scale/translation 합성 (G2) |
| 헤어 교체 | 종족별 `EFDLItem_PC_xx_NN_HAIR` 목록 | 헤어 메시 쿠킹 + `Apply_EquipmentPreview` (G4) |
| 피부·머리·눈·화장 색 | 재질 파라미터 scalar 15 / vector 14 | 런타임 tint API (G5) |
| 표정 | `add_fc_smile/angry/cry` additive | 슬라이더 문서에 `--include-expressions`로 포함 가능 (후순위) |
| 화면 | `charactercustomizing.gfx` 좌·우·하단 패널 | `CUILayoutRuntime` 슬롯 + 슬라이더/탭 (G6) |
| 드래그 회전·피직스 | - | 카메라 yaw 드래그, 기존 본 체인 (G6) |

슬라이더 문서 생성: `python Tools/CharacterCustomizing/build_face_sliders.py <pc_xx_00_face_ani.psa> <RACE>`.

## 3. G1 계약

### Data/Customizing/FaceSliders/FT.facesliders.json (`lostark.face-sliders` v1)

```json
{
 "schema": "lostark.face-sliders", "formatVersion": 1, "race": "FT",
 "source": "pc_ft_00_face_ani.psa", "neutralFrame": 1, "positionUnit": "cm",
 "sliders": [
  { "id": "cheek_pull", "sequence": "add_cheek_pull_ui",
    "bones": [ { "bone": "b_fc_r_cheek_d_cm",
                 "keys": [ {"position":[x,y,z],"rotation":[x,y,z,w]}, {...중립...}, {...} ] } ] }
 ]
}
```

슬라이더 18개: cheek_pull, cheekbone_height, cheekbone_pull, eye_angle, eye_height, eye_scaleh, eye_scalev, eye_width, eyebrow_angle, eyebrow_height, jaw_angle, jaw_height, jaw_pull, mouthlip_height, nose_height, nose_length, nose_scale, jaw_scale. 각 슬라이더는 실제로 움직이는 `_cm` 본만 담는다(2~12개).

### Client

- `Client/Public/FaceSliderDocument.h`, `Client/Private/FaceSliderDocument.cpp`
  `FACE_SLIDER_DOCUMENT::Load(race, outError)`: `CProjectDataRoot::Resolve` → `CDataJson::Parse` → schema/version/race/neutralFrame/슬라이더 ID 중복/키 3개/유한값/단위 쿼터니언 검증 → 통과 시에만 `*this` 교체.
- `Client/Public/FaceCustomizeApplier.h`, `Client/Private/FaceCustomizeApplier.cpp`
  `CFaceCustomizeApplier::Initialize(model, doc)`: 본 이름을 `Find_BoneIndex`로 해석, 없는 본은 건너뛰고 본이 하나도 없는 슬라이더는 버린다.
  `Set_Weight/Get_Weight/Reset_Weights`, `Apply(model)`: 가중치 w를 트랙 t=w·2로 바꿔 키 0-1 또는 1-2를 lerp/slerp, 델타 = 회전·이동 행렬. 같은 본을 여러 슬라이더가 건드리면 델타를 누적한다. 본의 현재 local이 마지막으로 쓴 값과 다르면 애니메이션이 다시 포즈한 것이므로 그 값을 base로 갱신하고, `local = delta * base`를 `Set_BoneLocalMatrix`로 쓴 뒤 한 번 `Refresh_BoneCombinedMatrices`. 매 프레임 누적되지 않는다.
- `CHARACTER_SPEC::pFaceSliderRace` (기본 nullptr). `Spec_LanceMaster`만 `"FT"`.
- `CCharacter`: `m_FaceSliderDocument`, `m_FaceCustomize`. `Initialize`에서 본 체인 초기화 뒤 `Load_FaceSliders()`(실패는 로그만 남기고 캐릭터 생성은 유지). `Late_Update`에서 본 체인보다 먼저 `Apply`. public `Has_FaceSliders/Get_FaceCustomize/Set_FaceSliderWeight/Reset_FaceSliders`.
- `CLevel_CharacterSelect::Render_SelectionPanel`(Debug): `Face Customize (Debug)` 헤더에 슬라이더 18개와 Reset.
- `Client.vcxproj`/`.filters`: 두 쌍을 `02.GameObjects\00. Character`에 등록.

### 검증

- 실행한 것: `cl /Zs` (Character, FaceSliderDocument, FaceCustomizeApplier, Logic_LanceMaster, Level_CharacterSelect), JSON parse, vcxproj/filters XML parse, `git diff --check`.
- 사용자 확인: Product 빌드(Engine 헤더가 main에서 바뀌어 Engine부터) → Character Select 창술사 → `캐릭터 생성`으로 커스터마이징 화면을 열고 얼굴 세부 슬라이더로 눈 간격·코 높이·턱 등이 움직이는지. 회전 방향이 원작과 반대면 쿼터니언 부호 규약 문제이므로 `Evaluate_Delta`에서 켤레로 바꾼다.

## 4. 나머지 탭 데이터 소재

여섯 탭의 원작 데이터가 실제로 무엇이 얼마나 있는지는
`2026-09-06_커스터마이징_데이터슬라이스_인벤토리.md`에 정리했다. 요약하면 음성만 데이터 테이블이 없고
나머지는 다 있으며, 노출 목록을 정하는 규칙 오브젝트가 FT/WR 두 종족분만 있는 것이 제약이다.
착수 순서는 G3 메시 프리셋 -> G5 재질 tint -> G4 헤어 -> 꾸미기 순을 권한다.
