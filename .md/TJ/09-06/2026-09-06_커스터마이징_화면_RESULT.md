# 2026-09-06 캐릭터 커스터마이징 화면 RESULT

원작 `charactercustomizing.gfx` 배치를 그대로 옮긴 제품 커스터마이징 화면을 만들고,
G1에서 만든 얼굴 슬라이더(`CFaceCustomizeApplier`)를 그 화면의 실제 슬라이더에 연결했다.
Debug ImGui 슬라이더와 임시 Face preview 체크박스는 제거했다. 확인은 이 화면에서 한다.

## 1. 진입 경로

```
Lobby -> Character Select(클래스 선택) -> "캐릭터 생성" 버튼 -> 커스터마이징 화면
  -> "외형 결정" -> 기존 캐릭터 이름 입력 창 -> 확인 -> Bern
  -> "뒤로가기" -> 클래스 선택으로 복귀
```

`CreateCharacterButton`(제품 버튼)과 Debug `Create Character` 버튼 모두 같은
`Request_CreateCharacterButtonClick()` 한 경로를 쓴다. 이 요청을
`CLevel_CharacterSelect::Update_Customizing`이 소비해 커스터마이징을 열고, 이름 입력 창은
기존 `Open_CreateCharacterModal` 그대로 그 다음 단계로 뜬다. 이름 입력·IME·검증·`Stage_Creation`
경로는 손대지 않았다.

## 3. 조작

| 입력 | 동작 |
|---|---|
| 좌드래그(우측 패널·하단 바 밖) | 카메라 궤도 회전. yaw 무제한, pitch -12~40도 |
| 휠 | 거리 1.1~6.0m. 가까울수록 주시점이 머리 쪽으로 올라가 얼굴이 잡힌다 |
| 우측 탭 | `얼굴`만 동작. 나머지 6개는 데이터가 없어 흐리게 표시하고 클릭을 받지 않는다 |
| 얼굴 세부 탭 | 눈 / 눈썹 / 광대 / 턱 / 코 / 입 |
| 슬라이더 | 막대 어디를 눌러도 잡히고, 0~1 가중치를 캐릭터에 즉시 적용 |
| 무작위 얼굴 | 모든 슬라이더를 0.15~0.85로 |
| 얼굴 초기화 / 전체 초기화 | 모든 슬라이더를 중립 0.5로 |

## 4. 슬라이더 배치 근거

원작 `CharCustom_Right_TabFaceDetailPart0~5`의 슬라이더 depth와 y좌표에서 읽었다.

| 파트 | 그룹 | 행 | 원작 y | 우리 slider id |
|---|---|---|---|---|
| 눈 | 눈 크기 | 가로 / 세로 | 26 / 56 | `eye_scaleh` / `eye_scalev` |
| 눈 | 눈 위치 | 간격 / 높이 | 119 / 149 | `eye_width` / `eye_height` |
| 눈 | 회전 | 각도 | 211 | `eye_angle` |
| 눈썹 | 눈썹 형태 | 높이 / 각도 | 26 / 56 | `eyebrow_height` / `eyebrow_angle` |
| 광대 | 광대 형태 | 돌출 / 높이 | 26 / 56 | `cheekbone_pull` / `cheekbone_height` |
| 턱 | 턱 크기 | 크기 / 높이 | 26 / 56 | `jaw_scale` / `jaw_height` |
| 턱 | 턱 모양 | 돌출 / 각도 | 119 / 149 | `jaw_pull` / `jaw_angle` |
| 코 | 코 형태 | 크기 / 높이 / 돌출 | 26 / 56 / 86 | `nose_scale` / `nose_height` / `nose_length` |
| 입 | 입 형태 | 높이 | 26 | `mouthlip_height` |

추출한 18개 중 `cheek_pull`만 이 화면에 자리가 없다. 원작에서 볼(cheek_d) 관련 조작은
얼굴 세부가 아니라 꾸미기 탭의 볼 터치 쪽이라 여기에는 붙이지 않았다. 코 3행의 `돌출`을
`nose_length`에 붙인 것은 원작 슬라이더 이름 `NosePull`과 남은 코 슬라이더 하나를 대조한 것이며,
실제 움직임 방향은 화면에서 확인이 필요하다.

## 5. 종족별 얼굴 슬라이더

다섯 종족의 얼굴 AnimSet PSA에서 `add_*_ui` 시퀀스를 전부 뽑아 문서를 만들었다. 슬라이더 ID 18개는
다섯 종족이 모두 동일하다.

| 클래스 | 종족 | 문서 | 슬라이더 | 움직이는 본 |
|---|---|---|---|---|
| 창술사 | FT | `Data/Customizing/FaceSliders/FT.facesliders.json` | 18 | 33 |
| 슬레이어 | WR_F | `WR_F.facesliders.json` | 18 | 33 |
| 도화가 | SP | `SP.facesliders.json` | 18 | 41 |
| 환수사 | SP_M | `SP_M.facesliders.json` | 18 | 33 |
| 워로드 | WR | `WR.facesliders.json` | 18 | 33 |

각 문서가 요구하는 본이 해당 클래스의 body `.wmodel`에 전부 있는지 바이트 단위로 대조했고,
다섯 클래스 모두 누락 0이다. `CHARACTER_SPEC::pFaceSliderRace`를
`Logic_Slayer`=`WR_F`, `Logic_Artist`=`SP`, `Logic_DimensionMaster`=`SP_M`,
`Logic_Warlord`=`WR`에 연결했다(창술사는 이미 `FT`). 건슬링어는 요청대로 제외라 `nullptr`이며
얼굴 탭에 안내 문구만 나온다.

생성 명령:

```
python -X utf8 Tools/CharacterCustomizing/build_face_sliders.py <pc_xx_00_face_ani.psa> <RACE>
```

PSA 위치는 `D:\ClaudeWork\Extracted\CustomizeMesh_Extracted\races\<RACE>\...\AnimSet\`이다.

## 7. 사용자 확인이 필요한 것

Debug 제품 빌드는 이미 끝났다(`Client/Bin/Debug/Client.exe`). Server를 켜고 Client 실행 ->
Lobby -> `Character Select` -> 클래스 선택 -> `캐릭터 생성`.

1. 우측 패널·상단 안내판·하단 생성 바가 원작 위치에 뜨는지
2. 드래그 회전과 휠 확대로 얼굴이 잡히는지, 헬멧이 벗겨져 얼굴이 보이는지
3. 눈/눈썹/광대/턱/코/입 슬라이더가 실제로 해당 부위를 움직이는지, 방향이 원작과 같은지
   (클래스를 슬레이어·도화가·환수사·워로드로 바꿔가며 각 종족 문서도 함께)
4. `외형 결정` -> 이름 입력 -> 확인이 기존대로 Bern 진입까지 이어지는지
5. `뒤로가기`로 클래스 선택 화면과 카메라가 원래대로 돌아오는지

슬라이더 방향이 반대로 보이면 `CFaceCustomizeApplier::Evaluate_Delta`의 쿼터니언 부호 규약
문제이므로 켤레로 바꾼다.
