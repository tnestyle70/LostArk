# MVP 수상 화면 직업 심볼 추출

레퍼런스 `D:/ClaudeWork/Extracted/MVP/frames/f1701.png`에는 직업 문양이 두 군데 있다.

- MVP 왼쪽의 크고 흐린 워터마크
- 우측 세 열의 이름 위 작은 금색 아이콘

둘 다 아직 화면에 없다.

## 1. 큰 문양 체인 — 해석 완료

```
mvp.gfx d194 classMc
  -> Shared_MvpClassBigSymbol   (componentsv2)
       프레임 라벨 class_N 에서 MvpClassIcon_NN 을 자기 오프셋으로 배치
  -> MvpClassIcon_NN            (shareimagev2)
```

호스트가 플레이어 직업에 해당하는 라벨로 `gotoAndStop` 한다. 라벨마다 오프셋이
다르므로 문양들은 공통 원점에 정렬돼 있지 않다.

`Tools/LpkPipeline/build_mvp_class_symbols.py`가 `componentsv2.xml`에서 40개
라벨과 오프셋을 뽑아 `Data/UI/MVP/MvpClassSymbols.json`에 저장한다.

```
class_1   MvpClassIcon_01  offset(-33,  3)
class_2   MvpClassIcon_02  offset(  0,  2)
class_3   MvpClassIcon_03  offset(  4,  7)
...                                  총 40
```

덤프 형식 주의: `componentsv2.xml`은 태그당 한 줄이고 속성 순서가 일정하지 않다.
`PlaceObject3Tag`는 `characterId`가 아니라 `className`으로 대상을 가리키며,
좌표는 `<matrix>` 자식 줄에 twips로 들어 있다. 속성 순서를 가정한 정규식은
0건을 돌려준다.

넣지 않았다. 번호는 연속이 아니며 `class_39`가 통째로 없다.

## 4. 작은 아이콘 — 세트가 섞여 있다

우측 열의 `classMc`(char 203)도 같은 `class_N` 라벨 체계지만 배치 대상이 두 종류다.
20개는 `goldClassIcon_*` 임포트, 나머지는 mvp.gfx 자체 `DefineShapeTag`다.

| 직업 | 출처 |
|---|---|
| 도화가 | `goldClassIcon_YinyangMaster` (shareiconimage) |
| 차원술사 | `goldClassIcon_WM_M` (shareiconimage) |
| 워로드 | mvp.gfx shape 178 |
| 창술사 | mvp.gfx shape 202 |

shape는 `FILLSTYLE bitmapId` → `DefineSubImage` → `DefineExternalImage2`로 따라간다.

**함정**: mvp.gfx의 `imageID`가 두 공간에서 겹친다. `idType=9`(1024×1024 아틀라스)와
`idType=0`(960×540 단독 프레임)이 같은 번호를 쓴다. 아틀라스 쪽만 골라야 한다.

## 5. 배치 — gfx 실측

`depth 194 classMc` (MvpResultFrame)

```
스테이지 (485, 616), alpha 0 으로 배치
f100 → f115 16단계 선형 페이드인, 마지막 키프레임이 colorTransform 을 떼어 불투명으로 끝난다
```

`depth 27 classMc` (열 스프라이트 내부)

```
열 로컬 (135, 673), scale 0.73526, 68x68 셀 -> 화면 50x50
자체 페이드 없음. 열 전체 등장 모션에 얹혀 간다
```

열 스프라이트 자체가 y=0에 놓이므로 열 로컬 y가 곧 프레임 로컬 y다.

## 6. 구현

**생성기** `Tools/LpkPipeline/build_mvp_class_symbols.py`
→ `Data/UI/MVP/MvpClassSymbols.json`

componentsv2(라벨·오프셋) + shareimagev2(아이콘 크기) + shareiconimage(금색 아이콘 목록)
+ mvp(배치·페이드) 네 소스를 읽는다. 직업 지정만 외부 입력이며
`PLAYABLE_CLASS_LABELS`에 그 사실을 적어 둔다.

| 직업 | 라벨 | 크기 | 자체 오프셋 |
|---|---|---|---|
| 워로드 | class_9 | 193×181 | (-5, 7) |
| 도화가 | class_23 | 178×179 | (3, 8) |
| 창술사 | class_25 | 180×209 | (4, -7) |
| 차원술사 | class_41 | 184×206 | (0, -7) |

크기가 제각각이고 공통 원점 정렬이 아니다.

**런타임**

- `MVP_CLASS_EMBLEM` — 큰/작은 asset, 자체 오프셋, 크기, `classKey`
- `MVP_AWARD_PARTICIPANT.strNetworkClassId` → `Compose_Page`가 `Find_ClassEmblem`으로 해결
- `CMvpAwardCatalog::Load_ClassSymbols` / `Get_EmblemPlacement`
- `CMvpResultView::Render_ClassEmblem` — 메달과 같은 `Ensure_RuntimeSlot` 패턴

`Ensure_RuntimeSlot`은 같은 id가 있으면 no-op이라 슬롯이 처음 만들어질 때의 텍스처를
계속 쓴다. 그래서 슬롯 id에 `classKey`를 넣었다. 같은 이유로 메달 슬롯 id에도
메달 번호를 넣었다 — 이전에는 행 위치만 써서 재생할 때마다 직전 판의 메달이 남았다.

(`MvpClassIcon_{09,23,25,41}.png`, `MvpClassIconSmall_{09,23,25,41}.png`)
