# 2026-09-03 PLAN — 파티 레이드 입장 전원 수락 투표

Bern NPC 레이드 입장에서 파티장이 `입장하기`를 누르면 파티원 전원에게 수락/거절 창이 뜨고,
전원이 수락해야만 선택한 레이드(발탄 / 쿠크세이튼)로 파티 전체가 이동하도록 만든다.

작성 규칙: `.md/GB/local.md`. Server authority · Client 표현 분리, parse→validate→stage→commit,
저장 ID는 pointer/tag/index 금지. 이 문서는 구현자가 그대로 반영하는 코드 정본이며 G 단위로
전체 코드를 채운다. 이 커밋 시점에는 G0(실측)·G1(Shared 계약)까지 확정 코드를 싣고 G2~G5는
계약·삽입 위치·불변식을 확정한 설계로 둔다. 각 G 구현 시 그 G의 전체 코드를 이 문서에 채운다.

### 확정한 gap

- (A) 리더 확정 즉시 전원 전송 → **전원 개별 수락 투표**로 바꾼다.
- (B) 쿠크세이튼 탭 선택 시 `WORLD_ID::KAKULSAYDON_ARENA`로 이동. 현재 NPC→world 고정 매핑은

- (C) 파티원은 입장 UI를 열지 않았어도 프롬프트만으로 수락/거절 창이 떠야 한다.

### enum

파일: `Shared/Public/Network/PacketMessages.h`
작업: 추가
기준점: `enum class PARTY_TRANSFER_RESULT`(1801) 정의 블록
위치: 그 enum 정의 바로 아래
추가할 대상: `enum class RAID_ENTRY_VOTE_RESULT`
필요한 이유: 투표 종료 사유를 Client에 typed로 통지 (문자열/매직넘버 금지)
연결되는 부분: `S2C_RAID_ENTRY_RESULT.eResult`, Server 투표 종료, Client 결과 표시

```cpp

	enum class RAID_ENTRY_VOTE_RESULT : std::uint8_t
	{
		ALL_ACCEPTED = 0,   // 전원 수락 -> Server가 이어서 batch 전송을 stage한다.
		DECLINED,           // 한 명 이상 거절
		TIMEOUT,            // 제한 시간 내 미응답
		CANCELLED,          // 발의자 이탈 / 파티 해산 등으로 무효화
		END
	};

	// 발의자(리더)가 어떤 레이드로 갈지 고르는 값. NPC placement가 아니라 UI 탭이 소유하며
	// Server가 이 값으로 target WORLD_ID를 결정한다(Client가 world를 직접 지정하지 않는다).
	enum class RAID_ENTRY_TARGET : std::uint8_t
	{
		VALTAN = 0,
		KAKULSAYDON,
		END
	};
```

## G2. Server 투표 authority (설계 — 구현 시 전체 코드)

### 상태 (GameRoom.h, "Same-room party state" 근처)

```cpp
	struct RAID_ENTRY_PROPOSAL
	{
		std::uint32_t iProposalId = 0;              // Room 로컬 단조 증가
		PARTY_ID      iPartyId = INVALID_PARTY_ID;  // 이 투표를 소유한 파티(단독은 전용 처리)
		LostArk::Shared::RAID_ENTRY_TARGET eTarget = LostArk::Shared::RAID_ENTRY_TARGET::VALTAN;
		std::string   strNpcPlacementId;            // near-NPC 재검증용
		std::vector<PLAYER_ID> Voters;              // 발의 시점 파티 멤버 스냅샷
		std::unordered_set<PLAYER_ID> Accepted;
		std::uint32_t iDeadlineTick = 0;            // fixed-tick 만료
	};
	std::vector<RAID_ENTRY_PROPOSAL> m_RaidEntryProposals;  // 파티당 최대 1
	std::uint32_t m_iNextRaidEntryProposalId = 1u;
```

멤버 변수 의미:
- `m_RaidEntryProposals`: owner container. 파티당 0/1개. 종료 시 제거.
- `iProposalId`: Server 발급 식별자. 프롬프트/응답/결과가 이 값으로 join. wrap 없음(방 수명 내).
- `Voters`: 발의 시점 멤버 스냅샷(투표 중 합류/이탈에도 대상 고정). `Accepted`는 그 부분집합.
- `iDeadlineTick`: fixed 30Hz tick 기준 만료. tick 루프가 초과 시 TIMEOUT 종료.

### 함수 (GameRoom.cpp)

- `Handle_RaidEntryPropose(sessionId, C2S_RAID_ENTRY_PROPOSE)` — 한 줄 책임: 발의를 검증하고
  투표를 연다. **솔로 특례 없음: 무파티는 인원 1명짜리 투표로 동일 처리**한다(본인 수락 = 전원 수락).
  흐름: 세션→player 조회 → Bern/생존/near-NPC(`Handle_ConfirmNpcEntry`의 검증 재사용) →
  파티가 있으면 leader(members.front()) 확인, 아니면 `REJECTED_NOT_LEADER` → 열린 proposal 있으면 무시 →
  `RAID_ENTRY_PROPOSAL` 생성(Voters = 파티 멤버 스냅샷, 무파티면 `{ 본인 }`, deadline=now+N tick,
  id 발급) → Voters 전원에게 `S2C_RAID_ENTRY_PROMPT` 전송 →
  `S2C_RAID_ENTRY_VOTE(0/total, bClosed=false)` broadcast. 실패 시 상태 변경 없음.
  솔로(Voters 1명)도 같은 경로로 프롬프트가 본인에게 떠서 수락하면 즉시 전원 수락→전송.
- `Handle_RaidEntryRespond(sessionId, C2S_RAID_ENTRY_RESPOND)` — 한 줄 책임: 개별 응답을 반영하고
  종료 조건을 판정한다.
  흐름: proposalId로 proposal 조회(없으면 무시) → 응답자가 Voters에 있는지 → 거절이면 즉시
  `Close_RaidEntryVote(DECLINED)` → 수락이면 `Accepted`에 추가 →
  `S2C_RAID_ENTRY_VOTE(accepted/total)` broadcast → 전원 수락이면
  `Close_RaidEntryVote(ALL_ACCEPTED)` 후 **기존 batch 전송 stage 재사용**.
- `Close_RaidEntryVote(proposal, RAID_ENTRY_VOTE_RESULT)` — 한 줄 책임: 결과를 전원에 통지하고
  proposal을 제거한다. ALL_ACCEPTED면 target world를 `eTarget`으로 정해
  `SERVER_WORLD_TRANSFER_REQUEST`를 `Handle_ConfirmNpcEntry`와 동일 규칙으로 stage
  (batch=Voters, isAlreadyStaged 재검사). 그 외에는 통지만.
- tick 루프(기존 room tick, `~10228` 몬스터 despawn 루프와 같은 위치)에
  `Expire_RaidEntryProposals(currentTick)` 추가 — deadline 초과 proposal을 `TIMEOUT`으로 close.
- player leave / 파티 해산 처리에 `Cancel_RaidEntryProposalsInvolving(playerId)` 추가 —
  발의자·voter 이탈 시 `CANCELLED`.

`Handle_ConfirmNpcEntry`의 batch stage 부분(3851~)을 `Stage_PartyWorldTransfer(batchMemberIds,
targetWorldId, requestSeq)` 헬퍼로 뽑아 propose(단독)·vote 통과 두 경로가 공유한다. 기존 함수는
헬퍼 호출로 동작이 동일해야 한다.

target world 결정: `eTarget==VALTAN → WORLD_ID::VALTAN_ARENA`,
`eTarget==KAKULSAYDON → WORLD_ID::KAKULSAYDON_ARENA`. NPC placement의 기존 매핑은 near-NPC 검증
에만 쓰고 실제 target은 `eTarget`이 소유한다(G4).

### command 라우팅

`GameRoom.cpp:1833` 부근 command dispatch(`Handle_ConfirmNpcEntry` 등록된 그 switch)에
`C2S_RAID_ENTRY_PROPOSE → Handle_RaidEntryPropose`, `C2S_RAID_ENTRY_RESPOND →
Handle_RaidEntryRespond`를 추가. **입장은 전부 propose→투표로 통일**하므로 기존
`C2S_CONFIRM_NPC_ENTRY`/`Handle_ConfirmNpcEntry` 즉시-전송 경로는 제거한다(솔로도 1명 투표로
동일 처리 — 두 번째 전송 경로를 남기지 않는다). `Handle_ConfirmNpcEntry`의 near-NPC 검증과
batch stage 코드는 `Validate_NpcEntry(...)`/`Stage_PartyWorldTransfer(...)` 헬퍼로 뽑아 propose가
재사용한다. Shared의 `C2S_CONFIRM_NPC_ENTRY`/PacketType도 소비자가 사라지면 함께 정리한다.

### contract test

`Server/Private/ServerGameplayContractTests.cpp`에:
- 파티장 propose → 전원 prompt 수신, 비리더 propose는 REJECTED_NOT_LEADER.
- 전원 수락 → 정확히 1건 batch 전송 stage, target world가 eTarget과 일치.
- 한 명 거절 → 전송 stage 0, DECLINED 통지.
- 타임아웃 → 전송 stage 0, TIMEOUT 통지.
- voter 이탈 → CANCELLED, 전송 없음.
- 중복 propose(열린 투표 존재) 무시.

### CRaidEntryPreviewView 변경

- `Get_SelectedTarget()` 추가: `m_iSelectedRaid`(=탭)를 `RAID_ENTRY_TARGET`로 매핑

### 실패 rollback

프롬프트 수신 실패(비정상 payload), respond 전송 실패, 결과 DECLINED/TIMEOUT은 confirm 창만
닫고 입력 정지 없이 Bern에 남는다. 자동 재발의 없음.

## G4. 타겟 레이드 (발탄 / 쿠크세이튼) — 실측 결과 저비용

2026-09-03 실측: `KAKULSAYDON_ARENA` 전송 경로는 **이미 완비**돼 있어 별도 world transfer 개통이
필요 없다. 발탄과 동일한 `SERVER_WORLD_TRANSFER_REQUEST` 경로를 target world만 바꿔 쓴다.

증거:
- `WORLD_ID::KAKULSAYDON_ARENA`(`PacketType.h:38`), `LEVEL::KAKULSAYDON_ARENA`
  (`Client_Defines.h:24`) 정의됨.
- `CGameRoom::Handle_DebugEnterKakulSaydonArena`(`GameRoom.cpp:3088`)가 이미
  `transfer.eTargetWorldId = WORLD_ID::KAKULSAYDON_ARENA`로 `SERVER_WORLD_TRANSFER_REQUEST`를
  stage(3132) → `S2C_ENTER_ACCEPTED` → 레벨 전환. Debug Character Select 경로가 이 체인 전체를
  이미 검증한다.
- ServerApp가 `KAKULSAYDON_ARENA` shared simulation을 stage(`ServerApp.cpp:2513`).
- `Handle_ConfirmNpcEntry`도 같은 `SERVER_WORLD_TRANSFER_REQUEST`에 `eTargetWorldId`를 담는다.

따라서 이 G는 매핑뿐이다:
- 입장 UI 탭 → `RAID_ENTRY_TARGET`은 G3 `Get_SelectedTarget()`가 소유(발탄→VALTAN, 쿠크→KAKULSAYDON).
- Server `Close_RaidEntryVote`/`Stage_PartyWorldTransfer`가 `eTarget`으로 `eTargetWorldId`를 결정
  (`VALTAN→VALTAN_ARENA`, `KAKULSAYDON→KAKULSAYDON_ARENA`). near-NPC 검증은 기존대로 하되 target은
  NPC 고정 매핑이 아니라 `eTarget`이 소유한다.
- 파티 batch 로직은 world 무관하게 그대로 재사용된다.

주의: Kakul은 Debug Character Select typed transfer로도 진입하는 경로가 있으므로, Bern 파티 입장이
같은 shared simulation/room에 올바르게 합류하는지(중복 room 아님) contract test로 확인한다.
