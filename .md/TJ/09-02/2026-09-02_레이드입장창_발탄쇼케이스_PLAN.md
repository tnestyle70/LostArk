# 레이드 입장창 발탄 라이브 쇼케이스 PLAN (2026-09-02)

## 배경 — 원작 구조 확정

`epicgatecommanderbgtexture`는 `texture2d`가 아니라 **`eftexturerendertarget`**이다
(`OVSG0A3WEODR2YWJ6OMH7C.upk`, UI 루트 패키지). 원작은 군단장 입장창의 "움직이는 컬러
아트"를 구운 에셋이 아니라 **엔진이 매 프레임 라이브로 렌더한 씬**(보스 모델 + 맵)을
렌더 타깃에 담아 Scaleform에 `img://`로 물려준다. 33,902패키지 전수 스윕에서 구운
프레임 시퀀스가 안 나온 이유다. 등장(펑)→손 펼침 루프→퇴장은 그 씬 안의 스폰
이펙트 + 애니메이션 클립이다.

쿠크세이튼은 모델이 아직 작업 중이므로 **모델과 맵이 완성된 발탄으로 먼저** 같은
구조를 시도한다.

## 이미 있는 것 (정찰 결과)

- RT: `Add_RenderTarget` / `Add_MRT` / `Begin_MRT(tag, pDSV)` / `End_MRT` (Engine)
- SRV 꺼내기: `CTarget_Manager::Get_SRV(tag)` — 단 `CGameInstance` 중계가 없어 릴레이 1개 추가 필요
- UI에 꽂기: `CUI_Sprite::Set_Texture(ComPtr<ID3D11ShaderResourceView>)` (이번 마이그레이션 때 추가)
- 발탄 모델 admission: `CValtanPresentationAssetService::Ensure_Prototypes(device, context, levelIndex)`
  → `Get_BodyModelPrototypeTag()`. `CClientReplication`이 쓰는 정식 lazy-commit 경로이고
  Effect Tool도 발탄 모델을 프리뷰용으로 stage하는 선례가 있다 (서버 우회 아님 — 표현 전용).
- 셰이더: `Client/Bin/ShaderFiles/Shader_VtxAnimMesh.hlsl`은 G-buffer(`PS_OUT` 5-MRT) +
  Shadow 패스뿐. **포워드 단일 타깃 패스가 없다** — 이번에 추가한다.

## 범위 결정

- **1차 대상: Character Select의 O키 디버그 프리뷰만.** 발탄 프로토타입이 그 레벨에서
  이미 lazy-admission 가능하고, Bern 제품 흐름은 건드리지 않는다(load scope 결정 불필요).
  Bern 반영은 별도 결정.
- **1차 연출: 등장 페이드인 + idle 루프.** "펑" 스폰 이펙트/퇴장은 Effect 시스템 연결이
  필요한 후속. 맵 배경도 1차에서는 정적 아트 유지(모델만 라이브).
- RT 크기 **960×674** (슬롯 1201×843과 같은 비율, 메인 DSV 1280×720을 재사용하려면
  높이 ≤ 720이어야 함 — 전용 DSV 생성 API가 없으므로 뷰포트 축소로 해결).

## 구현 항목

### 1. Engine — SRV 릴레이 (public 헤더 변경)
`CGameInstance::Get_RT_SRV(const wstring_t& strTargetTag)` →
`m_pTarget_Manager->Get_SRV(...)` 중계 한 줄. **Engine → Client 정본 Product 빌드 필수.**

### 2. Client 셰이더 — 쇼케이스 포워드 패스
`Shader_VtxAnimMesh.hlsl`에 `PS_MAIN_SHOWCASE` + `pass Showcase` 추가.
- VS는 `DefaultPass`와 동일(본 스키닝 그대로).
- PS: `diffuse * (ambient + max(0, dot(N, -LightDir)))`, `SV_TARGET0` 하나.
  광원 방향/앰비언트는 셰이더 상수 두 개(쇼케이스 전용, 다른 패스와 공유 안 함).

### 3. Client — `CRaidBossShowcase` (신규 GameObject)
- `CGameObject` 파생. 소유 레벨 레이어(`Layer_UI`)에 clone, 팝업 열릴 때만 활성.
- 활성 시 매 프레임 `RENDERGROUP::PRIORITY`에 등록. PRIORITY는 G-buffer 시작 전이므로
  자체 `Begin_MRT("MRT_RaidShowcase")` → 뷰포트 960×674 → 발탄 모델을 Showcase 패스 +
  **자체 카메라 행렬**(오브젝트가 직접 바인드, 파이프라인 무변경)로 드로우 → `End_MRT`
  → 뷰포트 복원.
- 모델: `Ensure_Prototypes(...)` 성공 후 `Get_BodyModelPrototypeTag()` 프로토타입을
  컴포넌트로 clone. 준비 전/실패 시 비활성(정적 아트 유지, fail-soft).
- 애니메이션: 모델 클립 목록에서 idle 계열 이름 탐색해 루프 재생. 클립 갱신은 기존
  `CModel` 애니메이션 업데이트 사용(툴 프리뷰 lane과 동일).

### 4. RT 등록
`CMainApp` 초기화(또는 showcase 최초 활성)에서
`Add_RenderTarget(TEXT("Target_RaidShowcase"), 960, 674, DXGI_FORMAT_R8G8B8A8_UNORM, 투명검정)`
+ `Add_MRT(TEXT("MRT_RaidShowcase"), TEXT("Target_RaidShowcase"))`.

### 5. 팝업 연결 (`CRaidEntryPreviewView`)
- 발탄 탭 선택 + showcase 준비됨 → 포트레이트 슬롯에 `Set_Texture(Get_RT_SRV(...))`,
  아니면 기존 정적 `_lock` 아트로 복귀.
- 페이드인: 슬롯 tint 알파를 준비 완료 시점부터 ease.

### 6. 등록/검증
- `Client.vcxproj`/`.filters`에 `RaidBossShowcase.cpp/.h` 추가(기존 필터 카테고리에만).
- 검증: Engine→Client 정본 Product 빌드 → 사용자가 Character Select에서 O키 →
  발탄 탭 → 모델이 idle로 움직이는지 육안 확인(사용자 전용 판정).

## 리스크

- PRIORITY 패스에서의 상태 오염: Begin/End_MRT와 뷰포트 복원을 반드시 짝 맞춤.
- 발탄 모델 lazy 커밋 타이밍: 동기 비용이 크면 팝업 열림 프레임이 튈 수 있음 —
  1차는 디버그 프리뷰라 허용, 필요 시 열기 전 프리워밍.
- 본 상수 바인딩: VS를 DefaultPass와 공유하므로 기존 경로 그대로 흐름.
