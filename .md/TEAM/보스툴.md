# Valtan Boss Tool

## 한 문장 정의

Valtan Boss Tool은 보스 Pattern 하나를 실제 Server 제품 경로로 반복 재생하면서, 지금 실행 중인 Stage와 그
Stage가 호출하는 Animation, Effect, Camera, Hit/Motion, World event를 한 화면에서 확인하는 검증 도구다.

`단순함은 궁극의 정교함이다.` 기능 범위는 완전하게 닫되 첫 화면에는 작업자가 지금 필요한 선택,
재생, 결과만 남긴다.

## 본질

Valtan Boss Tool은 두 번째 보스 런타임이 아니다.

```text
canonical Valtan Data
  -> CValtanPatternTree strict joined view
  -> stable patternId
  -> CValtanPatternAuditionService
  -> Server fixed tick / snapshot / lifecycle
  -> Client presentation
```

Tool이 animation, Effect, camera, wall destruction을 각각 직접 실행하지 않는다. Tool이 Server에 제출하는
identity는 stable boss placement와 `patternId`뿐이다. 실제 Stage 전이와 연결 재생은 제품 런타임이 한다.

## 첫 화면이 답해야 하는 질문

1. 지금 Server에서 어떤 Pattern과 Stage가 재생 중인가?
2. 선택한 Stage는 어떤 Animation, Effect, Camera, 판정, 이동, World event를 호출하는가?
3. 같은 Pattern을 다시 검증하려면 무엇을 누르는가?

기본 화면은 `Live`, Pattern 목록, `Play Selected`, `Repeat`, `Stop After Current`, 선택 Stage의 연결 요약만
보여 준다. player가 죽었을 때만 `Revive Player`를 문맥 행동으로 보여 준다. occurrence 원문, Effect
resource, camera keyframe, owner 역추적은 하나의 접힌 `Why / Advanced diagnostics` 아래에 둔다.

## Pattern 목록 정본

`Play Selected`·`Repeat`·`Next Pattern...`·Pattern Flow·`All Effects -> Valtan`은 같은
split-owned 패턴 집합을 사용한다. 정본은 `Valtan.gameplay.json.patterns`와 대응 presentation이다.
`CValtanPatternTree::Build_PlayablePatternInventory`가 strict join된 정의에서 목록을 만들며,
허용할 ID 배열이나 필수 개수를 따로 관리하지 않는다.

```text
gameplay.patterns + presentation.patterns
  -> strict Product join / stable patternId
  -> Core: manualAuditions 밖의 authored 정의
  -> Animator: MANUAL_SERVER_AUDITION, manualAuditions 저작 순서
  -> Derived: DERIVED_SERVER_PATTERN, manualAuditions 저작 순서
```

각 분류의 숫자는 현재 데이터의 표시값이며 추가·삭제를 막는 조건이 아니다.
`VALTAN_SEQUENCE_FRONT_BACK_FRONT`는 퇴출됐다. Valtan Boss Tool에서 저장·재시작하는 순서의 유일한 저작 정본은
`Data/Valtan/Valtan.gameplay.json`의 `decisionModel.scriptedSequence`다. 이 object가 `patternIds`의 순서와
반복 Pattern, `interStepPursuitMs`를 직접 소유하며 별도 Flow JSON이나 `flowId` resolver를 사용하지 않는다.
publisher는 같은 candidate에서 generated `ValtanPatternRotations.json`을 exact 투영한다. 현재 정본이 31개면
Product도 31개여야 한다. 외부 검증 명령은 `Validate` 하나이며 기존 Product를 저장 선행조건으로 삼지 않고,
candidate를 검증·투영한 뒤 generated parity를 postcondition으로 확인한다.

stable ID unique, entry/stage identity, exact resolve와 manual 소유 metadata를 검증한다.
legacy Product에만 있는 행을 선택 목록에 섞지 않는다. 실패하면 부분 목록이나 대체 행을 보이지 않고
이전 유효 목록을 보존한다. 전체 등록 패턴 수와 한 Flow의 1~255슬롯 U8 전송 용량은 서로 다른
계약이며 256슬롯은 저장·Product 투영·Client 전송·Server catalog에서 일관되게 거부한다.

전체 graph는 Server 관측과 resource owner 진단을 위해 내부에 유지한다. legacy-only Pattern이 실제로
재생되면 상단 Live에만 `live only; outside All Effects list`로 표시한다. FIST_IN_OUT과
ENTRANCE_CINEMATIC도 유효한 authored 정의이므로 공용 목록에서 선택할 수 있다. 입장 cinematic을
저장 Flow에 넣을 때는 첫 슬롯에 한 번만 둘 수 있고, 생략한 경우 자동으로 추가하지 않는다.
독립 도넛은 계속 `Independent Effect -> Play Server Owner`에서도 같은 owner를 검증할 수 있다.

새 패턴은 gameplay/presentation의 같은 stable ID와 실행 소유자를 함께 등록한다. 기존 클립/행동을
조합한 새 정의는 manualAuditions의 DERIVED_SERVER_PATTERN으로 표현할 수 있다. animation intake에서
승격하는 MANUAL_SERVER_AUDITION은 기존 source chain/clip 연결 검증을 함께 유지한다. 목록의 C++ 상수나
숫자를 수정할 필요는 없다. 검증·Product 투영과 Server revision 적용은 기존 경로로 수행한다.

## Next Pattern과 저장 Flow

`Next Pattern...`은 현재 Product, 자신이 시작한 Ordered Flow 또는 isolated Pattern 다음에
실행할 **한 칸**을 Server에 예약한다. idle에서도 선택할 수 있다.
선택 대상은 위 공용 inventory와 동일하다. Next의 표시 정렬만 기존 source sequence 순서를 유지한다.
첫 isolated Play의 준비/reset은 유지하지만 Next 예약·교체·취소·승격은 현재 위치, HP, 자원,
cooldown, 파괴된 벽·바닥을 초기화하지 않는다. 마지막 판정과 월드 변경이 commit되고 현재
Pattern이 정상 완료된 뒤 다음 tick에 시작한다. 살아 있는 플레이어가 없으면 명시적 revive까지 기다린다.

Flow 중 Next를 선택하면 현재 Pattern은 끝까지 실행하고 남은 Flow 대신 선택한 Pattern을 재생한다.
Next는 Repeat를 끄지만 저장 배열에 삽입하거나 기본 순서를 수정하지 않는다. 다른 owner와 충돌하거나
시작 명령이 미확정이면 이유를 표시하고 이전 실행을 유지한다. Tool을 닫아도 공용 service가 상태를 유지한다.

`Save Flow`는 현재 slot을 `decisionModel.scriptedSequence` typed draft로 바꾼 뒤 gameplay owner와 generated
Product를 한 canonical writer transaction으로 원자 저장한다. 물리 commit receipt가 성공한 뒤 editor reopen이나
candidate apply가 실패해도 저장을 `Nothing was saved`로 되돌리지 않고 별도 상태로 표시한다.
`Boss Verification -> Current Patterns`는 성공한 canonical baseline을 즉시 표시한다. 같은 저장 revision의
candidate/2PC는 실행 중인 Flow를 바꾸지 않으며, 그 Flow는 pinned 이전 revision으로
`Restart Flow (Fresh Arena)` 전까지 종료한다.

`Load Flow`는 `Valtan.gameplay.json`의 saved sequence를 다시 읽을 뿐 Server playback을 바꾸지 않는다.
`Restart Flow (Fresh Arena)`는 최신 saved candidate와 Server-active gameplay definition revision이 같은지
확인하고 saved sequence를 다시 읽은 뒤 Server의 walls/floors/props/collision/navigation/combat objects를
복구한다. reset이 성공한 같은 revision으로 **화면 01, 배열 첫 슬롯**부터 새 FLOW_START를 제출한다. slot ID의
숫자로 정렬하지 않으며 반복 Pattern, sparse slot ID와 사용자 순서를 보존한다. Boss Verification의
`Restart Saved Pattern (Fresh Arena)`도 saved slot이 정확히 하나일 때 이 transaction을 공유한다. 잘못된
저장본, parity 불일치, reset/새 시작 거절, 다른 owner 충돌은 새 playback을 시작하지 않는다.

canonical source revision은 lowercase SHA-256 compare-and-swap이다. writer가 commit 직전 authoring owner revision을
다시 확인하고 다르면 전체 요청을 거부한다. 생성물 drift는 source CAS에 포함하지 않고 같은 candidate에서 복구한다.
projection, publish 또는 apply가 실패하면 물리 commit 결과와 runtime activation을 구분하며 기존 실행 generation을 유지한다.
Client와 Server는 Shared가 선언한 동일 protocol version으로 빌드한다.

## Winters Engine ImGui 규칙

- 선택 대상은 Pattern 하나, Stage 하나다.
- 핵심 행동은 선택 옆에 두고 결과 또는 실패 이유를 바로 아래 한 줄로 남긴다.
- Live는 한국어 Pattern 이름을 먼저 보여 주고 stable ID는 tooltip/진단으로 내린다.
- Repeat 중 다른 Pattern을 선택하면 다음 반복을 즉시 해제하고 현재 Server occurrence만 정상 종료한다.
- 선택이 없거나 Server snapshot이 없으면 짧은 empty state로 끝낸다. fallback 대상을 추측하지 않는다.
- raw JSON editor, 중복 Balance 수치, 의미 없는 slider, 빈 tab, 미래 기능 placeholder를 두지 않는다.
- 읽기 정보는 `Animation / Effect / Camera / Hit·Motion / World / Next`의 짧은 연결 요약으로 먼저 보인다.
- 전문 authoring은 기존 Animation Tool, Effect Tool, Camera authoring seam으로 넘긴다.

`Valtan Logic Pattern`은 F1의 Valtan Boss Tool과 동급인 독립 대형 창이다. 단, 소유자는 여전히 하나의
`CValtanBossTool`이며 두 번째 parser, pattern tree, Server audition service를 만들지 않는다.
Valtan Boss Tool의 요약 button으로도 같은 창을 열 수 있다.

Valtan Logic Pattern은 현재 선택 또는 실제 재생 중인 Pattern 하나를 읽기 전용으로 투영한다.
Stage role과 실제 clip, authored branch, cross-pattern target, counter proxy/arc, confirmed-damage
threshold/progress, bind/silence action, part policy와 damage profile을 보여 준다. 현재 action은 live
Server snapshot으로 강조한다. 연속 snapshot의 source/target과 저작 edge가 단 하나로 맞을 때만
observed branch history에 exact로 남기고, 같은 target을 가리키는 edge가 여러 개면 outcome을
추측하지 않는다. 이 창은 branch, Stage, Pattern이나 Server 상태를 편집하지 않고
world/preview input owner를 가져가지 않는다.

## Effect Tool과의 경계

Effect 작업자는 `All Effects -> Valtan`에서 한국어 Pattern을 보고 다음 두 경로를 즉시 비교할 수 있다.

```text
Play Server
  = 같은 CValtanPatternAuditionService에 owner patternId를 one-shot 제출

Open Editor / Play Effect (+ Owner Animation)
  = 기존 Model View authoring timeline에서 로컬 편집·샘플링
```

Effect Tool의 `Play Server`는 이동 비용을 줄이는 얇은 바로가기다. 별도 packet, 별도 lifecycle, 별도
Server replay engine을 소유하지 않는다. 일반 연결 Effect마다 같은 버튼을 반복하지 않고 Pattern마다
한 번만 둔다. 목록 밖 owner를 가진 독립 Effect만 `Play Server Owner`로 exact owner Pattern을 실행한다.

Valtan Boss Tool은 전체 검증 workflow인 `Repeat / Stop / Revive / live graph / 원인 진단`을 계속 소유한다.
Effect Tool은 one-shot Server 비교와 Effect 편집만 소유한다. 저장하지 않은 Effect 편집은 Server 재생에
포함되지 않으며, Server 재생은 현재 Model View 문서와 timeline을 초기화하지 않는다.

## 작업 흐름

1. Valtan Arena에서 `F1 -> Valtan Boss Tool`을 연다.
2. 한국어 이름으로 Pattern을 선택하고 `Play Selected`를 누른다.
3. `F1 -> Valtan Logic Pattern`에서 live node, 분기 조건과 observed branch history를 확인한다.
4. live Stage와 연결 요약으로 문제가 Animation, Effect, Camera, 판정, World event 중 어디에 속하는지
   찾는다.
5. Effect 문제면 `Effect Tool -> All Effects -> Valtan`에서 같은 Pattern을 찾는다.
6. `Open Editor`와 Model View timeline으로 Effect를 튜닝한다.
7. 같은 Pattern 행의 `Play Server`로 실제 Arena 결과를 다시 비교한다.
8. 전멸로 죽으면 Valtan Boss Tool의 `Revive Player`로 살아난 뒤 남은 Pattern 검증을 이어 간다.

제품·audition 공통 순서를 바꿀 때는 `Pattern Flow -> Ordered Slots 편집 -> Save Flow`의 Product publish 성공 뒤
`Boss Verification -> Current Patterns`가 즉시 같은 순서를 보여 주는지 확인하고
`Restart Flow (Fresh Arena)`로 그 동일 revision의 01부터 fresh arena 실행을 시작한다. 실행 중
`Next Pattern...`에서 다른 Pattern을 선택하면 현재 Pattern 종료 뒤 reset 없이
이어지는지 확인한다.

## 확장 규칙

- 새 보스는 stable Pattern/Stage view와 Server audition 계약이 실제로 생긴 뒤 추가한다.
- 연결 추가·교체·삭제는 관련 정본을 `parse -> validate -> stage -> commit`하는 별도 transaction으로
  구현한다. ImGui에서 여러 JSON을 임의 부분 수정하지 않는다.
- 인접 Tool이 Server shortcut을 요구하면 같은 typed service를 호출하는 얇은 context action만 허용한다.
- Tool 수가 늘어도 verdict/lifecycle queue 소비자는 공용 service 하나여야 한다.
- Client local preview를 Server 합격 증거로 표시하지 않는다.

## 완료 판정

자동 검증은 stable ID, parser join, service lifecycle, publisher, build까지 판정한다. Animation과 Effect의
visual fidelity, camera 연출, 벽·바닥 파괴 결과는 사용자가 실제 Debug Server + Client에서 육안 확인한
뒤에만 PASS다. Flow UI도 사용자가 `Save Flow Product publish 성공 -> Product-synced Current Patterns 즉시 갱신 ->
같은 revision으로 Restart Flow (Fresh Arena) -> arena 복구 -> 01 재생`과 Valtan Logic Pattern의 live Pattern/Stage/관측 branch 강조를 직접 확인하며, 에이전트는
Client를 자율 실행하거나 visual PASS를 대신 선언하지 않는다.
