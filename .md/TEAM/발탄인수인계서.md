# 발탄 1페이즈 패턴 정본 인수인계서

## 1. 이 문서가 고정하는 북극성

발탄의 몸 애니메이션, Server 판정, Product Effect를 서로 다른 임시 목록에서 맞추지 않는다.
1페이즈 작업자는 다음 authoring 정본에서 같은 `patternId -> stageId -> actionId` 타임라인을 본다.

```text
Data/Valtan/Valtan.pattern.json
        |
        +-- Server pattern projection
        |     Data/Encounters/Valtan/ValtanEncounter.json
        |     Data/Encounters/Valtan/ValtanCombatObjects.json
        |
        +-- Client presentation projection
        |     Data/Animation/Authored/Valtan/Valtan.patternbindings.json
        |     Data/Animation/Authored/Valtan/Valtan.patterneffectcues.json
        |     Data/Actors/BossCatalog.json combatObjectVisuals
        |
        +-- stable reference only
              Data/Balance/DamageProfiles.json
              Data/Encounters/Valtan/ValtanCinematicCamera.json
              Data/Encounters/Valtan/ValtanWorldEvents.json
```

제품 Server와 발탄 Arena는 master JSON을 별도 런타임으로 직접 읽지 않는다. publisher가 검증한 기존
typed projection을 계속 소비한다. Animation Tool과 Effect Tool은 이 authoring 정본과 같은 projection을
fail-closed로 결합해 각각 body-animation 전체 타임라인과 독립 Effect 목록을 보여 준다.

독립 Effect 정본 entry는 다음 두 개다.

- `valtan.independent-effect.target-axe` -> `effect.valtan.sky-axe.active`
- `valtan.independent-effect.donut-in-out` -> `effect.valtan.carrier-v1.attack.fist-in-out.inner.clip-01`

`INDEPENDENT EFFECT`는 복사본을 만드는 폴더가 아니다. 같은 stable Effect asset을 단독으로 열고 재생하는
library view다. 패턴 stage에는 사용 reference만 남고 같은 asset의 편집 행을 이중으로 만들지 않는다.
각 entry는 선언한 `ownerPatternId/ownerStageId`에 **정확히 한 번** 참조되어야 한다. 현재 도끼는
`HIGH_JUMP/AIRBORNE`, 도넛은 `FIST_IN_OUT/INNER`만 owner다. 도넛은 INNER에서 unified Effect를 한 번
시작하고 `OUTER.effectRefs`는 비워 둔다. 여기에 같은 independent ID를 다시 넣으면 projector와 Client exact
join이 모두 실패하도록 닫혀 있다. 실제 Arena cue와 Effect Tool authoring preview는 모두 `stopPolicy: natural`인
Effect의 문서 lifetime을 다음 stage까지 유지하므로 unified INNER -> OUTER visual을 한 번의 spawn으로 재생한다.
명시적 `CUE_END`만 source end window에서 계속 종료된다.

일곱 managed pattern 중 `boss.flag.counterable`을 여는 패턴은 없다. 이를 억지로 counterable로 바꾸지 않고,
master의 `counterReactionLayers`가 기존 Product에서 실제로 counterable인 네 stage를 reference-only layer로
정확히 가리킨다. 세 단계 `VALTAN_TRIPLE_COUNTER`와 `VALTAN_CENTER_GRAB_COUNTER_64/COUNTER_WINDOW`의
window/success/failure action은 기존 Encounter와 `Valtan.patternbindings.json`의 clip을 그대로 사용한다.
이 layer는 Animation/Effect Tool에 표시되지만 일곱 패턴 admission이나 Phase-1 랜덤 풀을 늘리지 않는다.

## 3. 정본 필드의 담당 경계

### 보스 패턴 담당자

다음 값을 master에서 조정한다.

- pattern selection: health bar 범위, phase, weight, 최대 연속 사용, 사거리
- Server stage: duration, hit shape, hit schedule, push/knockdown, `serverDamageProfileId`
- target/aim policy, stage motion, combat-object spawn action
- `WALL_CONTACT`, `TIMEOUT`, `PART_DESTROYED` 같은 branch graph
- camera/world 연출의 stable reference ID

Effect asset path와 animation clip을 Server 코드나 bootstrap에 넣지 않는다. 수치 변경 뒤 gameplay publisher와
Server 재시작까지 해야 실제 Arena에 적용된다.

1페이즈 일반 패턴의 선택 정본은 master `normalSelection`이다. 160~130, 130~109 두 health band 모두
`WEIGHTED_POOL`이며 후보는 `WHIRLWIND / DASH_CHARGE / FOUR_SLASH / FIST_IN_OUT / HIGH_JUMP` 정확히 다섯
개다. `selectionWeight`, range, armor/phase, cooldown, 최대 연속 사용 조건은 각 managed pattern 행이 소유한다.
기존 `ValtanPatternRotations.json`의 이 구간 ordered list가 먼저 재생되지 않으므로 weight 변경은 다음 normal
선택부터 실제 Server 랜덤 경로에 반영된다. 130/109 health-bar mechanic queue는 항상 이 랜덤 선택보다 우선한다.

master에는 raw 피해량을 중복 저장하지 않고 다음 stable damage profile을 저장한다. 실제 값은
`Data/Balance/DamageProfiles.json`의 `damageRatePercent`이며 방어력 등을 적용한 최종 피해량은 Server가 계산한다.

### 애니메이션 담당자

각 stage의 `animation.occurrences`만 조정한다.

- `clip`, `sourceStartMs`, `playMs`, `playRate`
- 유한 반복 횟수 `repeatCount`
- stage 끝 처리 `endPolicy`: `EXACT`, `HOLD_LAST_POSE`, `LOOP_TO_STAGE_END`
- `LOOP_TO_STAGE_END` 구간의 단 하나인 looping remainder를 표시하는 `repeatUntilStageEnd`
- 원본/프로젝트 조정 근거인 `mappingBasis`

`presentationSources`는 해당 pattern이 사용할 수 있다고 승인한 원본 `sourceActionId/sequenceIndex` 목록이다.
primary sequence 외 반응 animation을 결합할 때도 먼저 여기에 role과 함께 선언한다. Animation Tool의
`Valtan Pattern Master`가 실제 튜닝·전체 재생 화면이며, 기존 1~67 `Valtan Pattern Reference`는 원본 후보를
찾는 read-only 근거 화면이다.

기존 binding의 boolean `loop`는 숫자 반복 횟수가 아니다. `repeatCount`는 유한한 동작 반복의 의미를 기록하고,
`occurrences`는 실제로 재생할 stable occurrence를 순서대로 명시한다. publisher는 master에 없는 clip을
암묵적으로 복제하지 않는다. `repeatCount > 1`이면 그 수와 같은 개수의 동일 clip occurrence가 있어야 하며,
Animation/Effect Tool은 그 count를 재생 경계로 소비한다. `repeatUntilStageEnd`만 기존 binding의 boolean
`loop`로 투영한다.

`EXACT`는 모든 source cut의 `playMs / playRate` 합이 Server stage와 2ms 이내로 같아야 한다.
`HOLD_LAST_POSE`는 명시적으로 마지막 pose를 stage 끝까지 유지한다. `LOOP_TO_STAGE_END`는 `playMs: 0`이며
`repeatUntilStageEnd: true`인 occurrence 하나만 남은 wall time을 채운다. 설명 없는 underfill이나 loop는
publisher와 Tool admission에서 거부한다.

돌진 WINDUP의 현행 세 occurrence는 같은 600ms를 세 번 재생한 것이 아니라 `600 + 600 + 2450ms`다.
이번 정본은 이 실측을 숨기지 않고 `repeatCount: 3`과 세 source cut을 함께 보존한다. 정확히 `600ms x 3`으로
바꾸려면 pose jump와 telegraph cue를 함께 다시 승인하고 WINDUP 총시간도 1800ms로 바꿔야 한다.

### Effect 담당자

master에서는 stable `effectRef`와 독립 Effect 사용 위치만 확인한다. 실제 element, Revolution, Life Time,
anchor transform은 `Data/Effects/Authored/*.effect.json`에서 조정한다.

각 `CUE_BINDING`의 `cueProjection`은 cue가 붙는 정확한 `clipOccurrenceId`와 source-local 시작/끝 시간을
master가 소유한다. cue의 stage/action owner나 source window를 제품 cue JSON에서 따로 고치지 않는다.

- All Effects의 패턴 `Play Authoring Timeline`으로 전체 body sequence를 먼저 재생한다.
- 패턴의 저장 Effect를 선택한 뒤 전체 timeline을 재생하면 그 Effect의 stage-global cue offset,
  anchor/follow/local transform/stop window를 유지한 채 body와 함께 튜닝한다.
- `INDEPENDENT EFFECT`의 도넛(`SERVER_PATTERN_STAGE`)은 같은 full-pattern Product cue 경로를 쓰고,
  도끼(`SERVER_COMBAT_OBJECT`)는 Server가 복제하는 world combat-object root 경로를 쓴다.
- 실제 추적 위치, 무작위 선택, damage와 hit는 Server pattern/combat-object 담당이다.
- Effect Tool의 world proxy는 시각 저작 보조이며 Server gameplay 정답이 아니다.
- 현재 Effect 문서가 구조상 valid하지만 drawable element가 없는 경우에도 `Play Authoring Timeline`은 막히지 않는다.
  Effect만 재생 불가 상태로 알리고 body animation 전체 타임라인은 animation-only로 계속 재생한다. 반대로
  `Play Saved Effect`는 drawable이 될 때까지 fail-closed인 것이 정상이다.

이번 복구 기준 authored element inventory는 도넛 24, HIGH_JUMP TAKEOFF 3, LAND 24, sky axe 6이며 stable-ID
누락/중복은 0이다. 이는 영구적으로 element 삭제를 금지하는 숫자가 아니라 현재 pull의 회귀 기준이다. 의도적인
추가/삭제는 successor lineage와 Effect Tool inventory test를 같은 변경에서 갱신하고, Open/Save가 일부 보이는
row만 남겨 문서를 축소하지 않았는지 publish 뒤 authored/runtime equality로 확인한다.

### UI 담당자

UI damage font는 master나 DamageProfiles에서 예상 숫자를 다시 계산하지 않는다. Server가 방어력, 피해 profile,
실제 hit를 적용한 뒤 보낸 `DAMAGE_EVENT.iAmount`를 표시한다. master의 `serverDamageProfileId`는 pattern 담당자가
어떤 profile을 튜닝하는지 찾기 위한 stable reference다.

### 작업자별 한 번의 수정 루프

| 담당 | 수정하는 정본 | 자동 검증 | 사람이 보는 최종 화면 |
|---|---|---|---|
| 보스 패턴 | `Valtan.pattern.json`의 gameplay/selection/branch와 필요 시 `DamageProfiles.json` | master Publish/Validate, gameplay balance Validate, `Server.exe --contract-test` | Server 재시작 뒤 Arena의 선택 빈도, 이동, collider, 실제 피해/그로기 |
| 애니메이션 | master의 `presentationSources`, stage `animation.occurrences`, `repeatCount`, `endPolicy` | master focused harness, pattern-tree/Animation Tool Python tests | Animation Tool `Valtan Pattern Master` 전체 timeline과 dash 세 branch |
| Effect | `Data/Effects/Authored/<effectId>.effect.json`; master에는 stable ref/owner만 | Effect publisher Validate와 Effect Tool Python test | All Effects의 전체 pattern timeline 또는 독립 도끼/도넛 단독 preview |
| UI | Server snapshot/event를 소비하는 UI presentation | 관련 protocol/HUD harness | `DAMAGE_EVENT.iAmount`와 boss 상태 표시 |

`Data/Encounters/Valtan/ValtanEncounter.json`, `ValtanPatternRotations.json`, `ValtanCombatObjects.json`,
`Valtan.patternbindings.json`, `Valtan.patterneffectcues.json`은 projector 제품이다. 이 파일만 직접 고친 뒤 master를
그대로 두면 다음 publish에서 되돌아가거나 drift validation에 실패한다. 각 담당자는 pull 뒤 먼저 master Validate로
현재 join을 확인하고, 한 정본 수정 -> Publish -> Validate -> 담당 harness -> 사용자 수동 확인 순서로 끝낸다.

## 4. 패턴별 중요한 구현 계약

### 돌진과 그로기/부위 파괴

```text
WINDUP
  TIMEOUT -> CHARGE

CHARGE
  WALL_CONTACT -> GROGGY
  TIMEOUT      -> RECOVERY

GROGGY
  ENTER/EXIT   -> boss.flag.groggy on/off
  PART_DESTROYED -> PART_BREAK
  TIMEOUT        -> RECOVERY

RECOVERY / PART_BREAK
  TIMEOUT -> pattern finish
```

벽 충돌 코드는 배열의 다음 stage를 추측하지 않고 위 `WALL_CONTACT` branch를 사용한다.

### 고공 점프와 추적 도끼

`serverMotion.travelStageId`는 `LAND`다. TAKEOFF가 정점까지 상승하고 AIRBORNE은 6초 동안 정점을 유지하며,
LAND가 잠근 target 위치로 하강한다. AIRBORNE의 Server action은
`combatobject.valtan.high-jump.target-axe`만 생성한다. Client Effect ID는 BossCatalog의 visual mapping이 소유한다.

현재 도끼 생성 기준은 `LOCKED_TARGET_PER_ALIVE_PLAYER`다. AIRBORNE 진입 edge에서 살아 있고 낙하 중이 아닌
플레이어마다 combat object를 한 개씩 transaction으로 생성한다. object lifetime은 AIRBORNE과 같은 6000ms지만,
추적은 6000ms 내내 지속되지 않는다. Server fixed tick은 같은 target의 유효 위치를 **첫 timed pulse 1200ms까지**
갱신하고, 첫 pulse를 발사하면 follow flag를 끈 뒤 마지막 위치에 고정한다. 대상이 그 전에 유효하지 않게 되면
마지막 유효 위치를 유지한다. 판정은 1200ms에 한 번, CIRCLE 3.5m이며 BossCatalog가
`combatobject.visual.valtan.high-jump.target-axe.v1 -> effect.valtan.sky-axe.active`를 연결한다.

지속 추적, 일정 간격 다중 pulse, 임의 arena 좌표 선택은 구현되어 있지 않다. 랜덤 위치 도끼를 추가할 때는

## 6. 의도적으로 남긴 콘텐츠 확인점

- `휠윈드 1.2초`는 전체 패턴이 아니라 SPIN stage 1.2초로 해석했다.
- `VALTAN_FLOOR_WIPE_130`의 stable ID와 trigger는 130줄을 유지한다. 이전 표시명 `115줄`은 데이터와 모순이라
  중립 표시명으로 교체했다. 실제 trigger를 115로 바꾸려면 rotation/health-bar mechanic 검증과 함께 별도 승인한다.
- 돌진 WINDUP은 세 번이라는 의미와 실제 세 source cut을 모두 저장했다. 동일 600ms 세 번으로 아직 바꾸지 않았다.
- 4연속 공격은 이름과 맞게 Server contact를 총 4회로 복원했다.
- 도끼는 플레이어별 1개 생성과 첫 1200ms pulse까지의 추적까지만 구현되어 있다. 6초 지속 추적이나 랜덤 위치
  생성으로 해석하지 않는다.
- 도넛 independent owner는 INNER 한 곳뿐이다. OUTER 판정은 Server stage로 계속 존재하지만 같은 Effect ref를
  OUTER에 한 번 더 넣지 않는다.
- 도넛은 INNER에서 natural cue를 한 번 시작하고 문서 lifetime으로 OUTER까지 이어진다. 같은 Effect를 OUTER에서
  다시 spawn하지 않는다. 실제 색·크기·발생 시점의 visual fidelity만 사용자 timeline/Arena 확인 대상으로 남는다.
- Carrier V1 historical receipt는 수정하지 않는다. Product Effect의 의도적 element 추가·대체·삭제는
  `Valtan.carrier-v1-successor-lineage-receipt.v1.json`과 두 materializer test를 같은 변경에서 갱신한다.
- 새 Data/Effect 원본이나 successor receipt를 추가했으면 `Sync-EffectDataProject.ps1`을 실행하고 `-Check`가
  통과하는 `Client.vcxproj/.filters`까지 같은 PR에 넣어 SLN pull/build 계약을 유지한다.

이 항목들을 바꾸면 master, projection, validator, Server/Effect harness를 같은 PR에서 갱신한다.
