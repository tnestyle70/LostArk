# 01 · 카테고리 트리 (문제지)

> **답 없음. 키워드만.** 이 문서를 읽어서 배울 건 하나도 없다 — 그게 설계다.
> 사용법: spine → 챕터 유도 → 노드 재생성 → 실패한 노드만 `02_정답지`에 쓴다.
> 좌표(A) · 축(C) · 로그는 `00_좌표계_INDEX.md`.

---

## 0. 트리의 사용법

```
1. 도메인 spine 4줄만 본다
2. 챕터를 유도한다 (목록 안 보고). 그다음 대조.
3. 챕터 하나 고른다 → 노드를 유도한다. 그다음 대조.
4. 노드 하나 → 90초 구두 재생성 → 정답지로 채점
5. 실패한 노드만 02에 쓴다. 성공한 건 아무것도 안 쓴다.
```

**트리는 저장물이 아니라 좌표계다.** 200개 노드를 외우는 건 불가능하다(WM 4슬롯).
가능한 건 **spine에서 유도**뿐이다. 챕터 목록이 안 떠오르면 spine으로 돌아가라.

**노드 표기**
`▢` 미시도 · `△` 부분 · `✓` 성공(정답지에 안 씀) · `✗` 실패(→ 02에 씀)
`[Cن]` = 걸린 축 · `[Wxx/Sxx/Nxx]` = 소환하는 좌표 · `⚑` = 면접 초빈출

# D1 · 컴퓨터구조

### spine
```
전자는 유한 속도로 움직인다
  → 계산은 싸지는데 이동은 안 싸진다 (Dennard 종료 + memory wall)
    → 계층으로 숨긴다      → D1-2 메모리 계층
    → 병렬로 우회한다      → D1-4 병렬
      → 일관성 문제        → D1-3 코히런스/메모리 모델
      → 표현의 문제        → D1-5 수의 표현
  → 명령 하나가 어떻게 도는가가 전제 → D1-1 실행 모델
  → 측정 없으면 전부 추측  → D1-6 관측
```

## D1-1 · 실행 모델 `[C5]`
- ▢ fetch → decode → execute → memory → writeback ⚑
- ▢ register file / ALU / control unit / program counter
- ▢ ISA: x86-64(CISC) vs ARM(RISC), micro-op 디코딩, μop 캐시
- ▢ 파이프라인, 스테이지 분할이 왜 처리량을 올리나
- ▢ 해저드 3종: 구조 / 데이터(RAW WAR WAW) / 제어
- ▢ 포워딩(bypass), 스톨/버블
- ▢ 분기 예측: 정적 → 2-bit → TAGE. **미스 패널티 15~20cyc** ⚑ `[W02]`
- ▢ 예측이 왜 분기 없는 코드(`lerp`/`step`/cmov)를 정당화하나
- ▢ OoO: Tomasulo, 예약 스테이션, ROB, 레지스터 리네이밍
- ▢ 슈퍼스칼라, 발행 폭, **IPC의 정의와 한계** ⚑
- ▢ ILP의 벽 → 왜 더 이상 IPC로 못 밀고 코어로 갔나 `[C3]`
- ▢ 투기 실행의 대가: Spectre / Meltdown (개념만)

## D1-2 · 메모리 계층 `[C2]` ⚑⚑⚑
- ▢ **지연 수치 카드**: 레지스터 ~0 / L1 ~4 / L2 ~12 / L3 ~40 / DRAM **200~400cyc** / NVMe ~100μs ⚑
- ▢ 캐시 라인 **64B**. 태그 / 인덱스 / 오프셋 분해
- ▢ 연관도: direct-mapped / N-way set / fully. 충돌 미스
- ▢ 교체: LRU, pseudo-LRU
- ▢ 쓰기: write-back vs write-through, write-allocate, 쓰기 버퍼
- ▢ 미스 3종: compulsory / capacity / conflict
- ▢ 프리페처: 하드웨어 스트라이드 감지, `_mm_prefetch`, 언제 역효과인가
- ▢ 지역성 2종(시간/공간), 스트라이드가 왜 중요한가
- ▢ **AoS vs SoA** — ECS의 존재 이유 ⚑ `[W02]`
- ▢ **false sharing**, `alignas(64)` 패딩 ⚑ `[W03]`
- ▢ DRAM 내부: 뱅크/로우/컬럼, 로우 히트, tRCD/CL/tRAS
- ▢ NUMA: 로컬/리모트 지연, 스레드-메모리 친화

## D1-3 · 코히런스와 메모리 모델 `[C3]` ⚑⚑
- ▢ MESI / MOESI 상태 전이
- ▢ 스누핑 vs 디렉터리 기반
- ▢ 캐시 라인 핑퐁 — false sharing의 하드웨어 정체
- ▢ **store buffer → StoreLoad 재정렬** (유일하게 x86에서 살아남는 재정렬) ⚑
- ▢ **x86-TSO vs ARM 약한 모델** — "x86에서 우연히 도는 코드" ⚑
- ▢ fence: mfence / lfence / sfence, 컴파일러 배리어 vs CPU 배리어
- ▢ `lock` prefix, LOCK XADD, cmpxchg
- ▢ CAS strong vs weak, 왜 weak이 루프 안에서 더 싼가
- ▢ **C++ memory_order 6종** + release/acquire 손 추적 ⚑ `[W03]`
- ▢ seq_cst의 실제 비용

## D1-4 · 병렬 `[C3]`
- ▢ SIMD: SSE / AVX2(256) / AVX-512, 레인 수 계산
- ▢ 정렬 로드 vs 비정렬, 게더/스캐터
- ▢ 자동 벡터화 조건 4가지, **앨리어싱이 왜 벽인가**, `restrict` `[C4]`
- ▢ SMT / 하이퍼스레딩 — 왜 게임에서 논쟁적인가
- ▢ 암달의 법칙 / 구스타프손
- ▢ **GPU**: SM / warp(32) / lane, SIMT ⚑
- ▢ warp 다이버전스 — 왜 셰이더 분기가 비싼가 `[W08]`
- ▢ occupancy, 레지스터 압력, 점유율 vs 지연 은닉
- ▢ 메모리 코얼레싱
- ▢ CPU↔GPU: **PCIe 대역폭 비대칭**, 업로드 힙, 커맨드 큐, 1~2프레임 지연 ⚑ `[W06]`

## D1-5 · 수의 표현 `[C1]`
- ▢ IEEE754: 부호 / 지수 / 가수, float 24비트 유효
- ▢ 비정규수(denormal) 페널티, FTZ/DAZ
- ▢ NaN, ±0, 무한대, 비교의 함정
- ▢ **결정론 파괴자**: FMA 유무, x87 80비트, `/fp:fast` vs `/fp:precise` ⚑ `[S01]`
- ▢ 부동소수점 오차 누적, 재결합 불가
- ▢ 엔디안, 구조체 정렬/패딩, `#pragma pack(1)`이 왜 안티패턴인가 ⚑
- ▢ 2의 보수, 부호 오버플로 = UB, 부호 없는 랩어라운드

## D1-6 · 관측
- ▢ 성능 카운터(PMU): cache-miss, branch-miss, IPC 측정
- ▢ Tracy / VTune / PIX — 각각 뭘 보나 `[W03]`
- ▢ roofline 모델: 연산 집약도 vs 대역폭 한계
- ▢ **측정 없는 최적화가 왜 도박인가** ⚑

# D2 · 운영체제

### spine
```
하드웨어는 하나, 프로그램은 여럿
  → 시간을 나눈다   → D2-3 스케줄링 (+ D2-2 실행 단위)
  → 공간을 나눈다   → D2-5 가상 메모리
  → 보호한다        → D2-1 커널 경계
  → 나누면 공유가 생긴다 → D2-4 동기화
  → 나누면 대화가 필요하다 → D2-7 IPC
  → I/O는 느리다    → D2-6 I/O 모델
```

## D2-1 · 커널 경계 `[C4]`
- ▢ Ring 0 / Ring 3, 특권 명령
- ▢ syscall / sysret, **전환 비용 ~100ns~수백ns** ⚑
- ▢ 유저→커널 경로: NTDLL stub → KiSystemCall → SSDT → 실행체
- ▢ 모놀리식 vs 마이크로커널, Windows의 하이브리드 위치
- ▢ HAL, 실행체, 커널, 드라이버 계층
- ▢ **왜 시스템 콜을 줄이는 게 최적화인가** ⚑

## D2-2 · 실행 단위 `[C3][C4]` ⚑⚑
- ▢ **프로세스(주소공간 + 핸들테이블) vs 스레드(스택 + 레지스터 + TLS)** ⚑
- ▢ **파이버 = 협력적, 유저 모드, 커널 모름** ⚑ `[W04]`
- ▢ PCB / TCB, Windows: EPROCESS / ETHREAD / KTHREAD
- ▢ **컨텍스트 스위치 비용 분해**: 레지스터 저장 + (프로세스 간이면) TLB flush + **캐시 오염** — ~1~5μs ⚑
- ▢ 왜 파이버 스위치가 스레드 스위치보다 100배 싼가 `[W04]`
- ▢ 파이버 스위치의 심장: **`mov rsp`** `[W04]`
- ▢ 스레드 생성 비용 → 스레드 풀의 존재 이유
- ▢ **TLS**: `__declspec(thread)`, TLS 슬롯, 구현 (TEB → TLS 배열)
- ▢ **TLS × 파이버 함정** — 파이버가 스레드를 옮기면 `[W04]` ⚑
- ▢ 스택: 커밋 vs 예약, 가드 페이지, 파이버 스택 크기 선택

## D2-3 · 스케줄링 `[C3]`
- ▢ 선점 vs 협력, 퀀텀/타임 슬라이스
- ▢ MLFQ / CFS / EEVDF 한 줄씩
- ▢ **Windows**: 우선순위 0~31, 동적 부스트, 퀀텀 길이, ideal processor, affinity mask
- ▢ 우선순위 역전 → 우선순위 상속
- ▢ 컨보이 효과
- ▢ **게임: 워커 = 논리 코어 수인 이유 / 코어 피닝의 득실** ⚑ `[W03]`
- ▢ 스핀 vs 양보(`SwitchToThread`/`Sleep(0)`/`Sleep(1)`)의 차이

## D2-4 · 동기화 `[C3]` ⚑⚑⚑
- ▢ 레이스의 정체: **LOAD → ADD → STORE 가 원자적이 아님** ⚑
- ▢ **원자성 / 가시성 / 순서 — 서로 다른 세 문제** ⚑ (대부분 여기서 틀림)
- ▢ 임계 구역, 상호 배제의 정의
- ▢ Peterson 알고리즘 — **왜 실제 하드웨어에서 깨지는가** `[D1-3]`
- ▢ 하드웨어 프리미티브: TAS / CAS / XADD / XCHG
- ▢ 스핀락: 순진한 구현 → TTAS → 백오프 → `_mm_pause`
- ▢ **CRITICAL_SECTION** = 유저모드 스핀 + 커널 이벤트 폴백, spin count ⚑
- ▢ **SRWLOCK** = 읽기-쓰기, 더 가볍고 재귀 불가
- ▢ **Mutex(커널 오브젝트)** — 프로세스 간 가능, 그래서 비쌈 ⚑
- ▢ **Semaphore** = 카운팅. 언제 뮤텍스가 아니라 세마포어인가 ⚑
- ▢ **Event** (수동/자동 리셋), `SetEvent`/`WaitForSingleObject`
- ▢ `WaitOnAddress` / `WakeByAddressSingle` — futex의 Windows판
- ▢ futex (Linux 대조): 무경합 시 유저모드
- ▢ 조건 변수, **왜 while 루프로 감싸는가**(spurious wakeup) ⚑
- ▢ 읽기-쓰기 락, 쓰기 기아
- ▢ **데드락 4조건**: 상호배제 / 점유대기 / 비선점 / 순환대기 ⚑
- ▢ 락 순서 규칙, 락 계층, `try_lock` 백오프
- ▢ 라이브락, 기아
- ▢ **진행 보장 3단계**: wait-free ⊂ lock-free ⊂ obstruction-free ⚑ `[W03]`
- ▢ **ABA 문제 → generation 카운터 해법** ⚑ `[W01]`
- ▢ 해저드 포인터 / RCU / epoch 기반 회수 (개념)
- ▢ SPSC 링버퍼 설계 — 왜 CAS가 필요 없나 `[S02]`
- ▢ **락을 안 쓰는 최선의 방법 = 공유를 안 하는 것** ⚑ `[S01]`

## D2-5 · 가상 메모리 `[C4]` ⚑⚑
- ▢ 왜 존재하나 5가지: 격리 / 재배치 / 오버커밋 / 공유 / 보호 ⚑
- ▢ **4단계 페이징** PML4 → PDPT → PD → PT, 48비트 (→57비트 LA57)
- ▢ 페이지 = 4KB. 왜 하필 4KB인가
- ▢ **TLB**, TLB reach 계산, 미스 비용 ⚑
- ▢ 대형 페이지 2MB/1GB — 언제 이득, 언제 손해
- ▢ ASID / PCID — 왜 프로세스 스위치가 더 비싼가 `[D2-2]`
- ▢ **페이지 폴트: minor(소프트) vs major(하드)** — 비용 차이 자릿수 ⚑
- ▢ demand paging, **COW(copy-on-write)** ⚑
- ▢ 교체 정책: LRU 근사, clock, working set, **스래싱**
- ▢ **VirtualAlloc: reserve vs commit** ⚑ `[W05]` ← 아레나 할당자의 근거
- ▢ MEM_RESET, 가드 페이지, 스택 자동 성장 메커니즘
- ▢ **메모리 매핑 파일** — 에셋/PAK 로딩 `[W12]`
- ▢ 주소 공간 레이아웃, ASLR, 페이지 권한(R/W/X), DEP

## D2-6 · I/O 모델 `[C3]` ⚑⚑
- ▢ **4분면: 블로킹/논블로킹 × 동기/비동기** ⚑
- ▢ **readiness 모델(select/poll/epoll) vs completion 모델(IOCP)** = "읽어도 돼" vs "읽어놨어" ⚑ `[S02]`
- ▢ select의 O(n) → epoll의 O(1), 레벨 vs 엣지 트리거
- ▢ **IOCP 구조**: 커널 큐 + 스레드 풀 + 동시 실행 제한 ⚑
- ▢ **GetQueuedCompletionStatus가 LIFO인 이유 — 캐시 온도** ⚑ `[S02]`
- ▢ 워커 = 코어 × 2 의 근거와 반론
- ▢ **OVERLAPPED 수명** — 완료 전에 죽으면 `[C4]` `[S02]` ⚑
- ▢ WSA_IO_PENDING은 에러가 아님, `CancelIoEx`
- ▢ AcceptEx / WSARecv / WSASend, **동시 WSARecv 1개 규칙**
- ▢ 인터럽트 → ISR → DPC, 폴링으로의 회귀(NAPI/DPDK)
- ▢ zero-copy: `TransmitFile`, scatter/gather `[C2]`

## D2-7 · IPC `[C3]`
- ▢ 왜 IPC인가: 격리의 대가
- ▢ 익명 파이프 / 네임드 파이프, 메시지 vs 바이트 모드
- ▢ **공유 메모리 + 동기화 오브젝트** — 가장 빠르고 가장 위험 `[C2]`
- ▢ 메일슬롯 (레거시)
- ▢ 로컬 소켓 / loopback — 왜 편하고 왜 느린가
- ▢ Windows ALPC, COM / RPC 마샬링
- ▢ 시그널 (Linux 대조), 왜 Windows엔 없나
- ▢ **게임 맥락**: 언제 프로세스를 나누나 (안티치트 / 크래시 격리 / 에디터-런타임)

# D3 · 윈도우 시스템 프로그래밍

### spine
```
Windows 커널은 객체 지향이다
  → 모든 것이 오브젝트, 접근은 핸들로  → D3-1 핸들
  → 핸들은 수명이 있다 [C4]            → D3-1 RAII
  → 코드는 PE로 존재하고 로더가 붙인다  → D3-2 모듈
  → 호출은 스택 위에서 일어난다        → D3-3 스택/규약
  → 데이터는 힙에서 산다              → D3-4 힙/할당자
  → 그리고 언젠가 죽는다              → D3-5 크래시
```

## D3-1 · 핸들과 오브젝트 `[C4]` ⚑
- ▢ 오브젝트 매니저, 네임스페이스(`\Device`, `\BaseNamedObjects`)
- ▢ **HANDLE = 프로세스별 핸들 테이블의 인덱스** ⚑
- ▢ 참조 카운트: 핸들 카운트 vs 포인터 카운트
- ▢ 핸들 상속, `DuplicateHandle`
- ▢ **RAII 래퍼**: `unique_handle` + 커스텀 딜리터, `INVALID_HANDLE_VALUE` vs `nullptr` 함정 ⚑
- ▢ 커널 오브젝트 vs GDI/USER 오브젝트 (다른 세계)
- ▢ 핸들 누수 탐지: Process Explorer, `!handle`
- ▢ **좌표 연결**: EntityHandle이 index+generation인 것과 Windows HANDLE의 유사/차이 `[W01]`

## D3-2 · 모듈과 로딩 `[C1][C4]` ⚑⚑
- ▢ **PE 포맷**: DOS 스텁 → NT 헤더 → 섹션 테이블 → 섹션(.text/.data/.rdata/.bss/.reloc)
- ▢ RVA vs 파일 오프셋 vs VA
- ▢ **IAT / EAT**, 임포트 바인딩, 지연 로드(delay-load)
- ▢ 로더: 정적 링크 vs `LoadLibrary`, **DLL 검색 순서**, DLL 하이재킹
- ▢ 재배치 섹션, preferred base, ASLR와의 관계
- ▢ **DLL 경계에서 할당/해제 금지 — CRT 힙이 별개** ⚑ `[C4]` (초빈출)
- ▢ **DllMain 로더 락** — 왜 DllMain에서 뭘 하면 안 되나 ⚑
- ▢ 정적 라이브러리 vs DLL 트레이드오프
- ▢ C ABI가 DLL 경계에서 필요한 이유 (이름 맹글링/ABI 불안정) `[C1]`
- ▢ 심볼: PDB, 이름 맹글링, dbghelp, 심볼 서버

## D3-3 · 스택과 호출 규약 `[C1]` ⚑⚑
- ▢ **함수 호출 6단계** (인자 배치 → call → 프롤로그 → 본체 → 에필로그 → ret) ⚑
- ▢ 스택 프레임: 리턴 주소, saved RBP, 지역 변수, RBP 체인
- ▢ **Win x64 규약: RCX RDX R8 R9 → 나머지 스택, shadow space 32B, 16B 정렬, RAX 반환** ⚑
- ▢ x64엔 왜 `__cdecl`/`__stdcall` 구분이 사라졌나
- ▢ **스택이 힙보다 빠른 이유 3가지** ⚑
- ▢ 언와인드 정보 `.pdata`/`.xdata`, 프레임 포인터 생략(FPO)
- ▢ SEH vs C++ EH, `__try/__except`, 왜 섞으면 안 되나
- ▢ **zero-cost 예외의 진짜 의미** (던지지 않으면 0, 던지면 매우 비쌈) ⚑
- ▢ 스택 오버플로 메커니즘, 가드 페이지, `_chkstk`
- ▢ **파이버 스택 = 이 전부를 수동으로 하는 것** `[W04]`

## D3-4 · 힙과 할당자 `[C4][C2]` ⚑⚑
- ▢ **malloc 내부**: 청크 헤더, 프리 리스트, 빈(bin) — **free가 크기를 아는 법** ⚑
- ▢ Windows 힙: `HeapAlloc`, **LFH(Low Fragmentation Heap)**, 힙 핸들, 힙 락
- ▢ `new`/`delete` vs `malloc`/`free` — 생성자 + `operator new` 분리 ⚑
- ▢ **placement new** ⚑ `[W05]`
- ▢ **단편화 내부 vs 외부** — 게임에서 왜 치명적인가 ⚑
- ▢ **할당자 = 수명 계약** ⚑ `[C4]`
  - ▢ Linear/Arena — 해제 없음, 프레임 끝에 통째 리셋 `[W05]`
  - ▢ Stack — LIFO만
  - ▢ Pool — 고정 크기, 프리 리스트, 캐시 밀집 `[W05]`
  - ▢ Frame/Double-buffered — 이번 프레임 / 저번 프레임
- ▢ **align up 코드** `(p + a - 1) & ~(a - 1)` — 손으로 쓸 수 있나 ⚑
- ▢ alignment가 필요한 이유 4가지, `_aligned_malloc`
- ▢ `operator new` 오버로드, STL allocator, `pmr`
- ▢ 메모리 태깅 (시스템별 사용량 추적)
- ▢ 누수 탐지: CRT `_CrtDumpMemoryLeaks`, ASAN, Application Verifier

## D3-5 · 크래시와 디버깅 `[C4]` ⚑⚑
- ▢ **크래시 주소 패턴 카드** ⚑
  - `0x00000000` nullptr / `0xCCCCCCCC` 미초기화 스택 / `0xCDCDCDCD` 미초기화 힙
  - `0xDDDDDDDD` 해제된 힙 / `0xFEEEFEEE` 해제된 힙(HeapFree) / `0xBAADF00D` 미초기화 LocalAlloc
- ▢ 미니덤프: `MiniDumpWriteDump`, `SetUnhandledExceptionFilter`, 덤프 타입
- ▢ PDB 관리 — 릴리즈 빌드에 심볼 남기기, 심볼 서버
- ▢ **릴리즈 전용 버그**: UB = 최적화 라이선스, 타이밍, 미초기화 값 `[D5]` ⚑

- ▢ PageHeap / Application Verifier — UAF를 즉시 터뜨리기
- ▢ ETW, 성능 카운터, WPA
- ▢ **재현 불가 버그 → 결정론 replay로 푸는 접근** `[N05]` `[S01]`
