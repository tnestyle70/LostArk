# 00 · 좌표계 INDEX

> **이 문서에는 답이 하나도 없다.**
> 좌표 · 질문 · 축 · 로그 칸만 있다. 읽을 게 없으므로 재독이 불가능하다. 그게 설계다.
> 답은 §4 정답지 링크에 있고, **채점할 때만** 연다.

```
1. §2에서 좌표 하나를 고른다 (오늘 것 + 간격 도래한 것)
2. 이 문서만 열어둔 채로, 빈 파일에 §3 답안 포맷으로 재생성한다
```

## 1. 축 (AXES) — 생성기

카테고리 기준은 **주제가 아니라 역할**이다. 축은 유도 규칙이고, 좌표는 그 규칙이 코드로 굳은 지점이고, 사전은 채점표다.

축은 외우는 게 아니라 **유도에 쓰는 것**. 좌표에서 막히면 "이게 어느 축이지?"를 먼저 묻는다.

| # | 축 | 한 줄 | 먹는 도메인 |
|---|---|---|---|
| **C1** | **기준계** | 절대 좌표는 없다. 모든 표현은 어떤 기준계에 상대적이다. | 선형대수, 좌표변환, 쿼터니언, 접선공간, 직렬화/ABI/엔디안, IR/SSA, 리소스-뷰, **면접관의 base commit** |
| **C2** | **이동 > 계산** | 데이터를 옮기는 게 계산보다 비싸다. | 캐시/메모리계층, SoA/ECS, false sharing, 대역폭, 압축, 델타, LOD, zero-copy, DB 인덱스, PCIe |
| **C3** | **공유는 비싸다** | 동시성 비용은 공유량에 비례한다. | 메모리순서/atomic, lock-free, work-stealing, 격리 vs 공유, 단일스레드 로직, MVCC, 파티션, GMP |
| **C4** | **수명은 선언된다** | 수명은 관찰되지 않는다. 프로그램이 선언해야 한다. | RAII, 소유권/스마트포인터, 할당자, generation/ABA, VirtualAlloc, HANDLE, Overlapped 수명, GC 대조, 트랜잭션 |
| **C5** | **이산화와 오차** | 연속은 예산 밖이다. 근사하고 오차를 통제한다. | 고정틱, 적분기, 물리, 샘플링/앨리어싱/TAA, IEEE754, 양자화, 보간, 몬테카를로, 미적분 |
| **C6** | **가지치기** | 탐색 공간은 항상 예산보다 크다. 안 보는 법이 실력이다. | 복잡도, 컬링(frustum/occlusion/Hi-Z), early-Z, alpha-beta, BVH, 휴리스틱, NP-hard, EXPLAIN |
| **C7** | **권위와 정합성** | 진실은 하나여야 한다. | server authority, 결정론/replay, ACID, 멱등성, dual-write, CAP, 안티치트, reconciliation |

**횡단 규칙 (축 아님, 의무)** — **모든 답변에 숫자가 들어간다.** 캐시미스 200~400cyc / 시스템콜 / 16.6ms / 30Hz=33.3ms / p99. 숫자 없는 답변은 미완성.

### 유도 예시 (이게 축을 쓴다는 뜻)
> C3에서 Chase-Lev 전체 유도: 공유가 비용 → 워커마다 자기 덱(공유 0) → 부하 불균형 발생 → 남는 놈이 훔치게 → 훔치기는 드물다 → **비대칭 설계**: 주인은 한쪽 끝 싸게, 도둑은 반대 끝 CAS → 마지막 1개에서만 만남 → **거기만 fence**.
>
> 이걸 외운 게 아니라 축에서 뽑아냈으면 통과. 못 뽑으면 그 좌표는 암기로 들어온 것 → 축에 재연결.

## 2. 좌표 (COORDINATES) — 문제지

**챕터 = 좌표.** 주제가 아니다. 좌표는 네 코드의 한 지점이고, 거기서 축을 유도하고 사전으로 채점한다.

`대조` 칸: **수렴** = 독립적으로 같은 답 → 설계 정당성의 외부 증거. **발산** = 제약이 다름 → 그 차이를 설명하면 진짜 이해. **경계 필수**: 아날로지가 깨지는 지점을 반드시 같이 적는다.

### 왜 25개인가 (경계 규칙)

네 원래 리스트가 혼란스러웠던 이유: **세 종류가 한 줄에 섞여 있었다.**

| 종류 | 예 | 어디로 |
|---|---|---|
| 학문 분류 | C++, OS, 네트워크, 수학, 알고리즘 | → **§4 사전** (정답지) |
| 산출물 | Winters Engine, NYPC 봇, C&S | → **§2 좌표** (문제지) |
| 도구 이름 | Kafka, Redis, AWS, Go | → 사전의 잎. 좌표 아님 |

산출물은 지식과 **나란한 항목이 아니라 교집합**이다. Winters Engine은 C++의 형제가 아니라 C++ ∩ OS ∩ 그래픽스 ∩ 네트워크 ∩ 수학이다. 그래서 하나의 리스트로는 절대 정합하게 안 나뉜다. **네 머리가 아니라 리스트가 범주 오류였다.**

- "IOCP는 OS야 네트워크야 서버야 윈도우 프로그래밍이야?" → 전부. 학문 분류로는 결정 불가. **좌표(S02)로는 하나.**
- "NYPC 봇을 어디에?" → 산출물이니 A3. 네 직관이 맞았고, 이유는 그게 지식이 아니라 **Stockfish/OpenAI Five처럼 지식의 결정체**라서다.
- "AWS는?" → 도구. 좌표가 아니라 S06/S07의 배포 형태. 별도 챕터 금지.

## 3. 답안 포맷

### 3-A. 좌표 답안 = 인과 5칸 / 90초  ← **주력**
질문 형태: *"이거 왜 이렇게 했어요?"* (= 3번 턴의 빈칸추론. 지문은 네 코드)

| 칸 | 초 | 내용 | 실패 신호 |
|---|---|---|---|
| ① 문제 | 15 | **하드웨어/요구사항 사실로 시작.** "16.6ms 안에 X를 해야 하는데" | 기능 설명으로 시작하면 실패 |
| ② 순진한 해법과 실패 | 20 | "그냥 하면 Y ms" — **숫자 필수** | 대안을 모르면 = 그때 근거 없이 결정한 것 |
| ③ 메커니즘 | 25 | 뭘 했고 어떻게 되나 — **숫자 필수** | 코드 낭독이면 실패 |
| ④ 대조 | 15 | "언리얼은 A로 푸는데 제약이 달라서(범용 vs 전용) 우리는 B" | **base commit 접속점. 빼면 전송 안 됨** |
| ⑤ 대가 | 15 | "대신 C를 잃었고, D 상황이면 이 선택이 틀립니다" | **없으면 세일즈맨. 있으면 엔지니어** |

> ⑤가 제일 중요하다. 트레이드오프를 말할 수 있다는 게 그 결정을 실제로 내렸다는 유일한 증거다.

### 3-B. 지식 답안 = 기존 5단계 / 90초  ← 보조
정의 10s → 원리 30s → 숫자 20s → 프로젝트 연결 15s → 트레이드오프 15s

**차이가 핵심**: 3-B는 지식에서 출발해 프로젝트로 **착지**한다. 3-A는 코드에서 출발해 원리로 **이륙**한다. 방향이 반대고, 3-A가 주력이다. 착지는 우연처럼 보이고, 이륙은 필연처럼 보인다.

## 5. 로그 · 간격

**간격이 곧 중량이다.** 성공률 ~80%에서 부하가 최대다. 무한 반복은 성공률을 100%로 수렴시키고 그때부터 0kg이다.

```
성공 → 간격 ×2.5   (1 → 3 → 7 → 18 → 45 → 90일)
부분 → 간격 유지
실패 → 1일로 리셋 + 막힌 축 기록
```

`log.csv` — **문서에 쓰지 마라. 그것도 생성이다.**
```csv
날짜,좌표ID,판정,다음간격,막힌축,비고
2026-07-16,W03,부분,1,C3,fence 위치는 나왔는데 마지막 1개 경합을 유도 못함
```

`막힌축` 칸이 전부다. 실패를 **축으로 분류**한다. 특정 축에 몰리면 진짜 구멍(→ 그 축의 유도 훈련), 흩어져 있으면 그냥 간격 문제(→ 간격만 조정).

### 판정 기준

| 판정 | 조건 |
|---|---|
| **성공** | 5칸 전부 + 숫자 있음 + 90초 안 + **정답지 안 봄** |
| **부분** | 유도는 됐는데 숫자/대조/대가 중 하나 누락 |
| **실패** | 유도 자체가 안 됨 → **이 노드는 암기로 들어왔다. 축에 재연결이 필요하다** |

**최종 판정 (도메인 밖 전이 테스트)**: 준비 안 한 좌표를 물었을 때 답이 나오는가.
나오면 생성기가 있는 것. 준비한 것만 나오면 그림을 외운 것.
