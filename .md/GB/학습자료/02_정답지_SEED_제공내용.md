# 02 정답지 SEED 사용자 제공 내용

2026-10-11 대화에 직접 붙여넣은 내용을 문단과 표로 복원한 참고 사본이다. 원문의 강한 표현과 규칙을 보존하며, 현재 학습 운영은 [프로젝트학습기준](../프로젝트학습기준.md)을 따른다.

## 원문

# 02 · 정답지 (SEED — 네가 쓴다)

> **이 파일은 비어 있는 게 정상이다.**
> 여기 쓰이는 건 **재생성에 실패한 노드뿐**이다. 성공한 노드는 절대 쓰지 않는다.
> 이미 아는 걸 적는 건 순수 낭비이고, 그게 문서 100개를 만든 그 동작이다.

## 0. 규칙

```text
트리(01)에서 노드 하나 → 90초 구두 재생성 → 녹음
✓ 성공 → 아무것도 안 쓴다. 로그에 한 줄만. 간격 ×2.5.
△ 부분 → 빠진 칸만 쓴다 (전체 재작성 금지)
✗ 실패 → 이 파일에 항목 추가 + "막힌 축" 필수 기재
```

**이 파일의 두께 = 네 무지의 지도.** 얇아지는 게 목표다. 두꺼워지면 경보다. 보통 필기는 아는 걸 적지만, 이건 **네거티브 이미지**다.

### 무엇으로 채점하나 (우선순위)

```text
1. 네 코드 ← ground truth. 좌표 노드는 여기서 끝난다
2. 기존 문서 100개 ← 00 INDEX §4 사전 링크. 읽지 말고 diff만
3. 나(Claude) ← 반례 던지기용. 마지막
```

### 절대 금지

- 트리를 보고 **미리** 정답지를 채우기 ← 이게 101번째 문서다
- 실패하지 않은 노드를 "정리 차원에서" 적기
- 이 파일을 처음부터 읽기 (실패 항목만 간격에 따라 재인출)

## 1. 항목 포맷

````markdown
### [노드 이름]

`D2-4` `[C3]` `[W03]`
- **실패 회차**: 1 | **막힌 축**: C3 | **다음 간격**: 1일

**막힌 지점** (한 줄, 구체적으로)
> 무엇을 못 유도했나. "잘 모르겠다"는 금지. "비대칭 설계까지는 나왔는데
> 마지막 1개일 때 주인과 도둑이 만나는 지점을 유도 못 함" 처럼.

**축에서의 유도** (← 이게 본체. 사실 나열이 아니라 사슬)
> C3(공유는 비싸다)에서 시작해서 이 노드까지 오는 길.
> 이 사슬이 안 써지면 아직 이해 못 한 것 → 사슬만 남기고 사실은 버려도 된다.

**숫자**
> 없으면 미완성.

**대조** (해당되면)
> UE / Go / Linux는 같은 문제를 어떻게. 수렴? 발산? **경계는 어디서 깨지나.**

**재인출 기록**
| 날짜 | 판정 | 비고 |
|---|---|---|
````

**핵심**: 사실을 적는 게 아니라 **유도 사슬**을 적는다. 사실은 다시 잊는다. 사슬은 다시 유도된다.

## 3. 축별 실패 집계 (← 진단 대시보드)

한 주에 한 번만 갱신. 실패가 **한 축에 몰리면** 그 축 자체가 구멍이고, **흩어져 있으면** 축은 멀쩡하고 그냥 간격 문제다. 대응이 완전히 다르다.

| 축 | 실패 수 | 판정 |
|---|---|---|
| C1 기준계 | 0 | |
| C2 이동 > 계산 | 0 | |
| C3 공유는 비싸다 | 0 | |
| C4 수명은 선언된다 | 0 | |
| C5 이산화와 오차 | 0 | |
| C6 가지치기 | 0 | |
| C7 권위와 정합성 | 0 | |

**해석**

- 한 축에 3개 이상 → 그 축의 **유도 훈련**. 노드를 더 파는 게 아니라 축에서 노드 5개를 연속으로 뽑아보는 것.
- 전 축에 고르게 1~2개 → 정상. 간격만 조정.
- 특정 좌표(Wxx/Sxx)에서 반복 실패 → **그 결정을 근거 없이 내렸다는 뜻.** 지식 문제가 아니라 설계 부채. 면접에서 터질 자리.

## 4. 알려진 빈 노드 (정직하게 유지)

> 모르는 걸 안다고 표시하는 것보다, **모른다고 적어두는 게** 훨씬 싸다.
> 면접에서 "그건 안 해봤습니다, 대신 인접한 X는 했고 이런 차이가 있습니다"가 얼버무리는 것보다 항상 낫다.
