# 클로드에게 보낼 작업 요청

첨부한 `2026-09-14_KOUKU_MARIO_VISUAL_RECOVERY_PLAN.md`를 읽고 마리오 색 공 미표시와 맵 재질 문제를 조사·수정해줘.

예전에 보이던 빨강·파랑·노랑 공이 지금은 실제 플레이와 자유시점 모두에서 보이지 않아. 줄무늬 공은 보여. 조명·재질 복원 작업 이후 발생한 것으로 의심하고 있고, 팀장도 재질 복원 문제라고 지적했어. 하지만 최종 원인은 아직 확정되지 않았으니 이 계획서의 가설을 정답으로 취급하지 마.

실제 작업 저장소는 `C:/Users/USER/source/졸업팀폴/LostArk`야. 현재 다른 작업의 미커밋 변경이 많으니 시작 시 AGENTS/CLAUDE/관련 규칙·PLAN/RESULT와 diff부터 확인하고, 내 카드미로·컷신·조명·배치 작업을 덮어쓰지 마. 다른 PC라면 실제 실행 프로젝트 경로부터 대응시켜줘.

우선 실제 stage/layout → WorldSequence 준비·commit → Play뿐 아니라 다음 Update의 Apply → 공의 runtime Visible/suppression → 개별 렌더 culling → 재질 bind/pass/draw 중 처음 실패하는 지점을 확인해줘. 로그가 부족하면 대상 ID에 제한된 최소 Debug 진단을 넣어서 내가 재생했을 때 원인을 알 수 있게 준비해줘. 직접 Client/UI를 실행하거나 캡처하지 말고, 사용자 재생이 필요할 때는 정확한 실행 경로와 확인할 로그를 알려줘.

원인을 재현하면 해당 부분만 수정해줘. 색 공 117개를 전부 표시로 바꾸거나 stage/layout을 Client에서 임의로 만들지 마. 원래 case 선택, 파괴된 공 숨김, 퇴장·재진입 정책을 유지해줘. 조명·culling 전체 끄기, 공 전체 unlit/알파 강제 설정, 다른 관문을 포함한 재질 일괄 변경으로 덮지 마.

색 공 표시와 맵 재질은 따로 검증해줘. 맵은 실제 문제가 있는 표면의 placement/asset/material slot과 원본 MIC·UV·RNM·조명 입력을 대응시켜 손실된 경로만 복구해줘. 색 공이 보인다고 전체 맵 재질 복원까지 완료라고 하지 마.

계획서는 조사 후 수정 분기를 선택하는 실행계획이지 이미 확정된 코드 정답지가 아니야. 실제 원인이 결정되면 같은 PLAN에 수정 대상의 전체 반영 코드·데이터 블록을 기록하고 구현해줘. 확인되지 않은 값이나 원본 자료를 지어내지 마.

데이터만 수정하면 필요한 publisher·재진입을 확인하고, C++/HLSL 수정이면 정상 증분 Product Build를 사용해줘. Clean/Rebuild·중간 산출물 삭제·전체 셰이더 강제 skip은 하지 마. Area publish가 다른 미저장/미게시 작업까지 덮지 않도록 먼저 확인해줘. Resources 바이너리는 Git에 넣지 마.

끝나면 실제 원인과 증거, 수정 파일, 빌드·게시 결과, 내가 확인할 순서, 아직 미검증인 화면을 나눠 알려줘. 기존 로그로 원인을 확정할 수 없으면 근거 없는 수정 대신 진단 가능한 상태까지 준비한 뒤 필요한 재생을 요청해줘.
