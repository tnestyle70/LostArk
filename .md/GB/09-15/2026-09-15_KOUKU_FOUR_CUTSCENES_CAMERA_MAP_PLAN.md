이번 설명서는 이전의 ‘원본검토/디버그 패턴 4개 추가’ 방식을 폐기한다. **현재 시퀀스가 실제 사용하는 카메라와 맵 애니메이션을 원본과 먼저 비교하고, 같은 것은 유지하며, 확인된 오류만 기존 연결에서 고친다. 그 다음 현재 모델 크기로 인해 틀어진 구도를 보정한다.** 목적은 원본 자료 재설치 자체가 아니라 기존 연출을 정확히 진단하고 맞추는 것이다.

## G02. 비교표를 먼저 만들고 같으면 쓰지 않는다

각 실제 CAMERA/WORLD 대상에 아래 표의 항목을 채운 뒤 수정 여부를 결정한다.

`Pattern/occurrence → shot 또는 instance/template/target → 원본 package/group/track/clip → 시간·좌표 대응 → 현재 설정 → 동등 여부/최대 오차 → 차이 원인 → 유지/복구/구도 보정/확인 필요`

| 판정 | 의미 | 처리 |
|---|---|---|
| 원본과 동등 | 변환·재생 조건을 고려한 실제 경로/동작이 일치 | 기존 ID·참조·키·clip 유지. 추가·재쿠킹·Save/revision 증가하지 않음 |
| 원본 이식 오류 | 누락, 잘못된 참조, parent/단위/축/reverse/곡선/시간 변환 오류가 확인됨 | 영향 대상만 기존 연결에서 수정. 빠진 target/shot은 필요한 최소 항목만 보완 |
| 의도된 기존 보정 | 모델/무대 크기나 편집 시간에 맞춘 사용자 보정 | 원본과 다르다고 삭제하지 않음. 이유·소비자를 확인해 유효하면 유지 |
| 데이터는 같고 구도만 다름 | 현재 스케일·배치 등으로 화면의 피사체 위치/크기가 달라짐 | 원본 재설치 없이 G04의 카메라 보정 대상으로 분리 |
| 의미/원인 미확정 | 자료나 원본 평가 의미를 충분히 입증하지 못함 | 덮어쓰지 않고 근거·추가 확인 항목 보고. 관련 없는 비교는 계속 |

동등 판정은 JSON 문자열이나 이름, 프레임 수만 비교하는 것이 아니다. 원본 키가 baked clip으로 변환됐거나 샷이 키 한도 때문에 분할돼도 평가 결과가 같을 수 있다. 실제 source key 시각, 구간 중간, 빠른 변화 구간을 비교하고 최대 위치/회전/FOV/pose/시간 오차와 허용 오차 근거를 적는다. float 직렬화 오차와 실제 시각적 오차를 구분한다. 모든 대상에 넓은 임의 오차를 적용해 동일하다고 처리하지 않는다.

재실행해도 같은 결과에 추가 쓰기가 없어야 한다. 대상이 모두 같고 구도 보정도 필요 없다면 ‘변경0’이 정상 완료다. 중복 Pattern/shot/instance/object/clip 생성으로 작업량을 만들지 않는다.

## G03. 좌표·시간을 맞춰 원본과 비교한다

### 카메라

활성 Director, 원본 parent/dummy, relative-to-initial, 위치/회전 곡선과 접선, roll/up, FOV, 컷/진입/복귀 blend를 함께 비교한다. UE cm/Z-up→프로젝트 m/Y-up·handedness, 수평 FOV→실제 viewport용 수직 FOV 변환을 한 번만 적용한다. source aspect와 현재 viewport를 별도로 확인한다.

`영상 PTS → 원본 event/Matinee 시각 → 현재 패턴 시각 → shot 로컬 시각`을 만든다. 현재 편집된 P4의 오프셋과 시간 늘림/줄임이 있을 수 있으므로 이를 먼저 읽고 역대응한다. 원본0초와 패턴0초를 무조건 같게 두지 않는다. 전체 영상 길이나 과거 +12.258초를 일괄 적용하지 않는다.

원본 컷 수와 기술적 샷 분할 수를 구분한다. 빠른 줌에서 고정150ms 샘플이 놓치는 곡선은 적응형 표본으로 검증한다. 분할 경계 pose/FOV는 연속이어야 하고 원본 컷 경계는 억지로 smooth하지 않는다. 음수 preroll Director는 최초 활성 샷 결정에 사용한다. FOV180° 등 표현 한계는 별도 보고하고 clamp 결과를 원본 완전 일치라고 쓰지 않는다.

### 맵 애니메이션

배치/instance/키의 상대·절대 좌표, modelPreScale/instance scale/키 scale/부모·뼈 scale, pivot, 회전축, visible, clip identity, trim, 시작, speed, reverse, loop, hold를 비교한다. 모델 안에 구운 이동과 WorldSequence 이동의 중복 적용을 검사한다. source actor/parent 조인 없이 비슷한 이름으로 새 객체를 추가하지 않는다.

원본에 존재하지 않는 static 맵 동작을 만들지 않는다. 배우의 비행·쓰러짐이나 FX를 맵 애니메이션으로 분류하지 않는다. 기존 clip과 원본 clip의 프레임 수가 다르더라도 재표본/endpoint 차이인지 실제 pose 차이인지 먼저 확인한다.

## G04. 원본 복구와 현재 모델 크기에 맞춘 구도 보정을 분리한다

원본과 데이터가 같아도 현재 피사체가 커졌다면 카메라를 원본으로 다시 설치해도 해결되지 않는다. 비교가 끝난 뒤 현재 모델 크기·위치·원점과 실제 해당 시각의 pose를 읽어 구도 차이를 확인한다. raw camera 불일치, 렌더 aspect 차이, model/instance/bone scale 중복, 잘못된 parent 평가를 먼저 배제한다.

보정 순서는 다음과 같다.

1. 배우·소품별 유효 scale과 위치, 카메라 로컬/월드 좌표, source→현재 시간 대응을 기록한다. 애니메이션 중 바뀌는 높이/폭도 포함한다.
2. 원본 화면의 얼굴/몸통/책 모서리/무대 중심 등 기준점을 잡고 현재 화면의 점유율·잘림·시선 중심을 비교한다. 모델 종류와 형태가 다르면 단일 scale 비율로 모든 컷을 맞추지 않는다.
3. **카메라의 거리·높이·바라보는 지점부터** 필요한 부분만 보정하고 FOV/roll/곡선/전환은 근거가 있을 때 조정한다. 모델 중심이 아닌 월드 원점 기준으로 카메라 좌표를 단순 배율 확대하지 않는다.
4. 첫/중간/끝 및 컷 경계에서 피사체가 잘리지 않고 궤적과 전환이 자연스러운지 사용자가 확인한다. 카메라 timing 오류는 해당 트랙 안에서 고치되 배우/암전 시각을 움직이지 않는다.
5. 책/테이블 등 맵 소품의 원본 동작이 맞다면 그대로 둔다. 피사체가 커졌다는 이유만으로 모든 맵 키/속도를 바꾸지 않는다. source 이식 오류나 확인된 소품 pivot/배치 보정 필요가 있을 때만 해당 target을 수정한다.

원본 곡선과 최종 구도 보정값은 결과 기록에서 분리한다. 저장 전/원본 정규화/복구 후/구도 보정 후 값을 남겨 되돌릴 수 있어야 한다. 현재 데이터 계약에 없는 새 override 속성을 소비자 없이 추가하지 않는다. 기존 shot 키에 최종값을 저장할 수 있으며 원본 대비 delta는 검증 자료에 보관한다. 다시 생성해도 승인된 보정을 덮어쓰지 않는다.

사용자 화면이 아직 없으면 수치에 근거한 보정안을 준비하고 확인 경로를 제공한다. 화면에 딱 맞는지 에이전트가 대신 PASS를 선언하지 않는다. 배우 크기를 원복하거나 조명/암전을 끄는 방식으로 구도를 맞추지 않는다.

### 현재 지원과 추가 구현 요구를 분리한다

현재 Map Tool `WorldSequenceToolPanel.cpp:266`은 preview targetId를 uint64로 해석하고, `:776` 이후 DEPLOY 외 binding을 MAP placement로 찾는다. 따라서 문자열 ID `world.object.kouku.gate2.intro.table`인 OBJECT_RESOURCE는 그 preview 경로에 ID만 넘겨도 동작하지 않는다. Table을 Deploy로 복제하거나 Save Animated Props로 저장하라고 하지 않는다. 뼈 동작 내부 변경은 필요한 소품만 재쿠킹하는 일이며 transform 키 편집과 구분한다. 이 편집 연결에 C++ 변경이 필요하면 구현 전에 정확한 함수별 패치/소비자/검증을 계획에 추가한다.

### Save 전에 확인할 실제 부작용

- **Map Tool World Sequence의 Save는 World 단독 저장이 아니다.** `WorldSequenceToolPanel.cpp:1311`→`MapTool.cpp:796`→`Save_AllAuthoring():591`이며, dirty Deploy·Map/World·SpawnGroups·Gameplay·Navigation·Destruction도 저장할 수 있다. 범위 밖 draft를 임의 Save/Discard하지 않는다. 이런 draft가 있으면 먼저 사용자에게 알리고 저장 범위를 분리한 뒤 진행한다. '아무튼 Save하고 확인'하지 않는다.
- **Object Save는 source-only가 아니다.** `WorldObjectTool.cpp:624`가 전투/Sequence 두 Composition의 emission 참조를 동기화할 수 있고, `:676,699`에서 WorldSequences Publish를 자동 시작한다. 연결 전투 참조가 있으면 `:729`→`MainApp.cpp:7476`에서 `Publish_AllPatterns()`까지 이어질 수 있다. 저장 전에 두 Composition의 대상 소비자, emission 변경 여부, 자동 게시 대상과 runtime 차이를 읽기 전용으로 확인한다. 제외 도메인 변경/게시가 수반되면 자동 Save를 진행하지 않고 영향과 필요한 승인을 보고한다. 위반을 피하려고 전투 연결을 지우거나 Publish를 우회하지 않는다.
- **Sequence 자체 Save와 Object Save를 구분한다.** Sequence의 로컬 Save 설명은 맞지만 이를 Object/Map Tool의 모든 Save에 일반화하지 않는다. Object 자동 게시 중에 수동 publisher를 병렬 실행하지 않는다. 파일 저장, 게시 종료 코드, 다음 재생 reload는 서로 다른 단계다.
- 동일 값에는 저장하지 않는 원칙은 그대로다. 다른 대상 수정 때문에 문서 revision이 한 번 증가한 것은 동일 행 재생성과 구분한다. no-op인 행 값/ID는 유지하고, 전체 문서 변경0일 때 revision도 유지한다.

기존 Pattern ID/이름/Gate/배우/child Pattern 연결, `enterCombatOnFinish`, 자동선택 및 전투 트리거는 유지한다. CAMERA/WORLD의 잘못된 참조만 필요할 때 수정한다. 기존 샷의 `activation`, AUTO volume, `sequenceInstanceId`를 일괄 PATTERN_ONLY/빈 값으로 바꾸지 않는다.

수정할 shot/template/model/placement가 다른 패턴·게임 AUTO에도 공유되면 먼저 소비자를 적는다. 영향 소비자 모두가 이번 대상이면 범위와 회귀 검증을 명시해 기존 정의를 수정한다. 무관한 소비자나 게임 진행에 영향을 주면 자동 전파하지 않는다. 영향 분리를 위한 최소 전용 리소스/참조 분기 또는 공유 적용 중 어느 쪽인지 사용자에게 확인한다. 이는 새 디버그 패턴4개를 만드는 것과 다르다. 승인받아 전용 샷을 만들 때만 PATTERN_ONLY와 AUTO 연결 제거를 적용한다.

공유 map placement의 영구 Transform 변경도 다른 연출에 영향을 준다. 기존 WORLD target의 모션/미리보기 보정을 우선 사용하고 Stop/Restore를 확인한다. 전역 mapplacements 변경이 필수면 영향/중복/가시성 검증 후 별도 승인받는다. 리소스 정의만 복사하면 배치까지 격리된다고 가정하지 않는다.

## G07. 적용 순서·복구·검증

1. 현재 저장본/미저장 draft/다른 세션 변경을 확인하고 수정 전 파일 및 대상 값의 복구 자료를 out 아래 보관한다. 툴 목록에 백업 패턴을 추가하지 않는다.

3. 동일 항목은 no-op으로 두고 근거가 확인된 이식 오류만 수정한다. 의도된 보정과 미확정 항목을 원본 값으로 일괄 초기화하지 않는다.
4. 현재 모델 scale/pose로 구도 문제를 분리하고 카메라 보정안을 작성·검증한다. 원본 복구 diff와 구도 보정 diff를 구분한다.

6. 재실행해 동일 리소스/패턴 증가와 불필요한 revision/재쿠킹이 없는지 확인한다. 실패 시 이번 수정만 복원하며 외부 Save를 덮어쓰지 않는다.
