## 원본 구조와 복원 단위

```text
Action LOA (profile, actionId)
  -> ordered stage
       -> Anim notify -> 실제 CModel clip
       -> PlayParticleEffect / DefaultParticle -> ParticleSystem
            -> emitter -> LOD -> Required/Spawn/Lifetime/module
                 -> material graph + texture / mesh
       -> PlayDecalEffect / TrailGhostEffect / PawnMaterialParam
       -> HidePawn / light / ViewShake / AKEvent
       -> Effect / movement / stage transition (gameplay reference)
```

원본은 animation clip 하나에 완성된 Effect 한 개가 붙는 구조가 아니다. 같은 stage가 clip, particle, 무기 mesh particle, decal, 잔상, 재질 변화, 숨김, 조명, sound를 별도 notify로 소유한다. 동일 clip도 action·stage에 따라 notify가 달라지므로 `clipName -> Effect` 한 열만으로 full restore하면 다른 패턴의 연출을 섞게 된다.

특히 Action의 `Effect` 6,142건은 피해·상태용 gameplay reference다. 이 이름을 렌더링 Effect 파일 6,142개로 세면 안 된다. 로컬 XmlData에는 Action과 ParticleSoundNew만 있고, Skill/SkillEffect/NPC 전투 정의가 없어서 projectile의 생성·피해·분기·owner를 원본 수치 그대로 복구할 근거가 부족하다. 원본 payload는 보존되어 있지만 transition 값의 실행 의미는 이전 추출에서도 미검증이다.

원본 추출기가 명시적인 object reference를 찾지 못한 notify도 **221건** 남아 있다. NOTIFIES CSV의 resolutionStatus와 원본 unsupportedUnresolved를 함께 봐야 한다. 직접 경로가 기록된327개 particle의 graph 누락0과, 이221건의 미해결은 서로 다른 수치다.

원본 그래프를 찾았다는 것과 현재 renderer가 모든 module/material을 구현했다는 것은 별개다. 이번 조사는 경로·참조 전수 확인이며 native full-restore renderer admission, 각 texture의 물리 closure, in-game 색·모양을 PASS로 판정하지 않았다.

## 수명을 clip 길이에 맞추면 안 되는 근거

원본 notify의 `localTimeSeconds + durationSeconds`가 동일 stage의 Anim 끝보다 5ms 이상 뒤인 항목은 PlayParticleEffect **1,492건**, PawnMaterialParam **378건**, PlayDecalEffect **30건**, TrailGhostEffect **24건**이다. 이 수치는 선언된 animation span 비교이며 실제 보이는 꼬리 길이, 재생 실패 또는 현재 잘림 건수는 아니다. 반복·대기·분기 stage와 duration0의 natural lifetime도 별도로 해석해야 한다.

직접 예시는 `MN_RPCZ_00 / 42197100 / stage-001`이다. `Att_Battle_14_02` 길이는0.666667초지만 `Par_U_RPCZ_EnergyBalloon_01_LOC_INT`와 `TransColor` duration은2.6초이고 Paralyzation marker가2.4초에 있다. 따라서 clip 길이만큼 Effect를 잘라 맞추는 방식은 이 원본 계약을 잃는다. Stage clock·notify window·particle natural lifetime·owner cancellation을 따로 복원해야 한다.

캐릭터의 누락 원인 전체를 이 가설로 확정할 수는 없다. 이번 항목은 보스 원본에서 clip 길이와 연출 수명이 다른 직접 근거다. 현재 캐릭터 cue 종료 정책과 rendering/material/attach 실패는 통합 조사에서 별도로 확인한다.

## 캐릭터 full restore 방식으로 확장할 때의 실제 작업 단위

1. `(profileId, sourceActionId, sourceStageId, sourceNotifyId)`별 occurrence를 기준으로 짤패턴 하나를 고른다. 같은 clip의 다른 action 연출을 섞지 않는다.
2. 원본 ParticleSystem 전체 emitter/LOD/module/material closure를 기존 Effect full.restore 경로에 만든다. mesh와 texture만 골라 만든 현재 V2 수동 저작 그룹을 원본 완료로 승격하지 않는다.
3. action stage clock에 particle/decal/trail/material/light/sound/visibility를 각각 연결한다. 본체·WEAPON bone·world·projectile/소환체 anchor와 소유 수명을 명시한다.
4. clip의 EXACT/HOLD/LOOP window, Effect의 natural tail/deactivate/cancel, 성공·실패·중단·restart·seek의 복구를 각각 확인한다. 무기와 몸체 숨김·재질 변화도 같은 occurrence 종료에서 원래 값으로 복구한다.
5. 현재 Server gameplay가 이미 있는 패턴에 presentation을 먼저 연결하고, 새 일반기는 Server action/이동/피해·소환 owner까지 같은 단위로 구현한다. source SkillEffect가 없는 판정 수치는 프로젝트 저작임을 남긴다.
6. 최소 compiler/JSON/publisher 검증과 사용자의 실제 Effect 재생·중단·재시작·끝까지 육안 관찰을 분리한다. 지금은 조사만 했으며 위 연결을 구현했다고 기록하지 않는다.
