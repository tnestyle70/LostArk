# 렌더링·이펙트 복원 V2

### native static 배경의 ambient 입력과 dragon local space

Lance ALT V의 바위 배경은 설치 메시가 빠진 상태가 아니라 Mesh carrier가 native PS의 ambient/sky
입력을 채우지 않는 결함이 확인됐다. native782~800 Mesh만 현재 committed scene directional ambient를
`g_LanceVAStaticAmbient`로 전달한다. 원본 shader 수식은 유지하며 이 연결을 원작 연출의 전체
환경조명 복원 완료로 취급하지 않는다. UE skylight hemisphere는 현재 scene owner가 없어 0을 유지한다.
실제 native786 product shader의 통제된 texture/ambient 수치 readback으로 0→색→0 전환을 검증했다.
Warlord17250의 static 배경도 같은 Lance native family를 사용하므로 이 입력 연결을 함께 소비한다.
클래스 이름만 보고 Warlord family의 ambient bind가 해당 배경을 덮는다고 판단하지 않는다.

사용자가 V/ALT V dragon 모델만 local space를 켜도록 범위를 확정하여 실제 세 모델의 8문서 23행을
원본 Required true로 복구했다. 본·socket·Transform과 다른 particle의 world-space 설정은 보존했다.
SourceRecipe가 true여도 DIRECT_AUTHORED_DOCUMENT의 저작 false를 자동 덮지 않는 점을 함께 점검한다.
세부 범위와 빌드/사용자 확인 경계는 [창술사 G13/G14 결과](09-11/2026-09-11_TIGER_HORSE_ANIMATION_AND_LANCEMASTER_ALTV_RESULT.md)다.

### 부착 이펙트의 원본 localSpace와 선택적 조명 제외

`DIRECT_AUTHORED_DOCUMENT`는 원본 Required 값을 reconstructed 경로에서 다시 적용하지 않는다.
따라서 본·카메라 부착 metadata가 정상이어도 저작 `particle.localSpace=false`이면 기존 입자가
생성 시점의 root를 계속 사용한다. 원본 `buselocalspace`, 실제 cue와 설치 모델, 앵커 갱신 순서,
살아 있는 입자의 변위를 함께 검사한다. 차원술사 V는 해당 camera_view 17개의 원본 true를 복구했고
실제 Catalog→Playback에서 카메라 +1m에 입자 +1m 이동을 확인했다. 초기 바닥·유리 재질의
시각 문제 전체가 이 수정으로 해결됐다는 뜻은 아니다. 사용자가 world-space를 요청한 다른
이펙트까지 전역으로 되돌리지 않는다.

차원술사 T의 소환 모델은 사용자 요청에 따라 exact cue만 기존 mask/depth와 NONBLEND를 유지하고
diffuse/specular 조명 항 대신 emissive RGB를 출력한다. scene post와 fog는 기존대로 소비한다.
이는 해당 모델의 조명 제외 정책이며 원작 전체 shader 복원 완료 판정이 아니다.
세부 근거는 [차원술사 T/V 결과](09-15/2026-09-15_DIMENSIONMASTER_T_UNLIT_V_RECTANGLE_IMPLEMENTATION_RESULT.md)다.

### 연출의 플레이어 도착과 카메라 종료

쥐 불꽃에 맞춘 플레이어 도착은 Effect 좌표를 Character Transform에 직접 복사하지 않는다.
원본 발생기의 XZ와 현재 occurrence 변환을 합성한 뒤 Server navigation의 지면 Y를 사용하고,
Sequence Logic이 기존 typed command로 요청하여 Server가 목적지를 검증한다. 현재 연결은
Sequence 저작의 `ROOM_PLAYER_ARRIVAL`이며 같은 방의 최대 네 명을 고정 슬롯으로 배정한다.
Effect 발생기 자체의 공중 Y와 플레이어의 발 위치를 혼동하지 않는다.
일반 Play는 종료에서 follow 카메라로 돌아오며, 명시적 Complete 재생만 승인된 관문과
저장 Pattern Flow를 이어간다. 이동 요청의 성공과 실제 이펙트·카메라 화면 판정은 구분한다.
세부 근거는 [Sequence 결과 G26](09-14/2026-09-14_KOUKU_SEQUENCE_PLAYBACK_EDITOR_IMPLEMENTATION_RESULT.md)이다.

이 문서는 Character Select·캐릭터·무기·스킬 이펙트를 복원하면서 확인한 원리, 반복 결함,
실제 연결 범위와 다음 확장 순서를 유지하는 공통 노트다. 이름의 V2는 이 기록의 두 번째
복원 단계이며 **Effect Tool V2 전용 문서나 새 런타임의 이름이 아니다.**

복원·손튜닝 문서는 F1 `Effect Tool V1`에서 계속 편집한다. `Effect Tool V2`는 별도 창으로
leaf/group·target attachment를 편집하며 V1을 열 때 함께 생성하지 않는다. 각 도구의 draft와
Sequencer를 분리하고, 기존 V1의 선택 항목 지연 로드·저장 성능 개선을 유지한다.

발탄 검증용 action Full Restore 35개는 원본 action/stage/clip/time metadata를 통해
실제 애니메이션과 함께 재생한다. All Effects 패턴의 PRODUCT 바로 아래 `[FULL RESTORE]`는
SourceActionIds와 현재 ClipOccurrences를 모두 비교하며, 라이브러리 직접 열기는 해당 원본
clip을 사용한다. editor preview와 Product cue 승격은 별개이며 제품 full.restore cue는 0개다.
`.restore`를 player recovery로 오분류하지 않고 기존 World Preview와 Valtan animation clock을
사용한다. notify delay·root basis·scale을 preview에서 중복 적용하지 않는다.

맵의 source BG 검증은 catalog/shader와 CModel이 같은 supported branch를 받아야 한다.
subspecular-only와 grass emissive flicker는 기존 shader 지원을 따른다. embedded material의
누락 PNG는 실제 source DDS 대응을 확인해 교정하며 geometry/scope를 바꾸지 않는다.
빌드·실행 경계와 비UI 검증은 [맵·발탄 결과 G24-V](09-15/2026-09-15_MAP_AND_VALTAN_FULL_RESTORATION_RESULT.md)에 기록한다.

새 작업은 먼저 해당 표면/스킬의 현재 코드와 이 노트를 확인한다. 확인된 원인과 해결 방법은
이 문서의 해당 항목을 갱신하고, 날짜별 변경 파일·빌드 로그·실패 과정은 대응 RESULT에 둔다.
오래된 현재 상태를 남긴 채 아래에 반대되는 내용을 계속 붙이지 않는다. 조사만 한 후보,
제품 소스에 연결한 항목, 빌드한 항목, 사용자가 화면에서 확인한 항목을 구분한다.

현재 작업의 상세 근거: [구현 PLAN](09-08/2026-09-08_CHARACTER_MATERIAL_AND_EFFECT_ROUND2_ESTIMATE_PLAN.md),
[구현 RESULT](09-08/2026-09-08_CHARACTER_MATERIAL_AND_EFFECT_ROUND2_ESTIMATE_RESULT.md).

## 화염·masked LocalVF·distortion 동반 합성의 현재 연결

워로드 Alt+V 시작 공간의 활성 cylinder는 최초 full 생성부터 native 재질 미연결로 빠진
항목이었다. 기존 family의 native673으로 원본 PS/VS와 세 texture를 연결하고 원본 발생기를
추가했다. 이 재질은 mesh UV 대신 화면 좌표·viewport 비율·SceneDepth를 읽는다. 원본의
실제 sampler와 varying 소비를 기준으로 복구하며 legacy의 미해결 texture를 사용하지 않는다.
원본 PS 수치 대조, 실제 전체 Product Stage와 발생 재생을 검증했다. 제품 빌드·화면 확인의
상태는 [워로드 결과 G17](09-09/2026-09-09_WARLORD_ASVF_FULL_RESTORE_IMPLEMENTATION_RESULT.md)에 둔다.

워로드 후속 배치에서는 원본 notify 여섯 개의 FRotator yaw가 저장 변환에서 모두0으로
사라져 마지막 균열이 겹쳤다. source 회전은 발생 중심과 axis-locked quad의 방향을 각각
소비하는 기존 입력에 연결한다. 위치 행렬만 맞춘 것을 최종 띠 방향 복구로 대신하지 않는다.
별도 root에 저작한 큰 방패와 본 부착 낙뢰는 설치 b_effectroot의 축을 실측해 해당 발생의
socket에서만 맞춘다. source 기준 배치 반경과 사용자 FOV·높이 튜닝, 실제 재생 검증과
화면 확인 경계는 [워로드 결과 G18](09-09/2026-09-09_WARLORD_ASVF_FULL_RESTORE_IMPLEMENTATION_RESULT.md)에 기록한다.

화염링 `backstep.ring`의 hoop2875는 원본 masked PS가 particle alpha를 읽는 `CB0[0].w`가
0으로 남아 전부 discard됐고, twirl2876은 이미 opacity가 포함된 RGB에 최종 합성이 alpha0을
다시 곱했다. 같은 화면에서 서로 다른 두 재질 층이 빠지는 결함이다. 기존 창술사 masked
LocalVF와 같은 방식으로 정확한 PS/VS·native float4 wire가 확인된13개 masked 프로그램의
row0을 `input.color`에 연결하고, 원본 additive/PS A0가 확인된130개 early-return의 출력
coverage를 일반 dispatch와 같게 연결한다. 원본 mask·RGB·fade·왜곡, 정상 translucent를 보존한다.

도화가 Alt+V 31930의 나비 native536도 같은 masked prefix 결함을 고쳤다. 정확한 원본
PS `390b1fe8a7081c45bf96c8afc4bf11e9` / VS `d17daa101dec2b4493fce2f510407f32` 조합에서만
CB0[0]을 particle RGBA에 연결한다. Group512와 생성기 수정, 원본 packed PS 수치 대조,
현재 전체 문서의 나비9개 발생, 생성 동치와 Mesh512 FXC를 확인했다. 설치 CSO와 실행 중
Client 반영 및 최종 화면은 [도화가 결과 G12](09-09/2026-09-09_ARTIST_CORE_FULL_RESTORE_IMPLEMENTATION_RESULT.md)의 별도 상태를 따른다.

나비 후속 실측에서는 같은 문서 안에서도 카메라 anchor와 실제 골격 anchor의 배율이 달랐다.

사용해야 한다. 문서 전체를 등록해 다른 발·카메라 발생까지 확대하지 않는다. 원본 배율,

현재 검증 범위와 제품 반영, 사용자 화면 대기는 [화염 재질 결과](09-14/2026-09-14_FIRE_MATERIAL_CLIPPING_RESULT.md)에 둔다.

## 관문 조명과 저작 Enabled의 소유권

쿠크 3관문의 어두운 Scene Profile과 기존 배경 조명 제외는 관문 상태가 소유한다.
청색 스포트라이트와 새 저작 광원의 enabled·색·밝기는 MapLight source가 소유한다.
현재 `Prepare_GateMapLights`는 원본 `source_baked_character`/`source_direct`와 기존
1·2관문 광원만 제외하고 나머지 광원의 enabled를 보존한다. 단일 청색 ID 강제 활성화는
새 백색광과 off 입력을 모두 버리므로 재사용하지 않는다. 청색광 삭제도 유효한 문서 변경이다.

`Same_MapLightSource`의 enabled·색상·개수 비교 뒤 관문 문서가 다시 만들어지고,
`CMapLightPresentationRuntime`은 활성 광원만 기존 transient 경로에 제출한다.
Engine은 transient 목록과 조명 RT를 매 프레임 비우므로 이전 프레임의 청색 조도를
재사용하는 구조가 아니다. 구운 RNM·정적 그림자와 shader uniform 재설정 최적화는 별개다.
변경 전후 회귀·컴파일·배포와 사용자 화면 확인의 범위는
[3관문 조명 결과](09-14/2026-09-14_KOUKU_GATE3_LIGHT_ENABLED_RESULT.md)를 따른다.

## 먼저 이해할 원리와 확장 순서

최종 그림에는 네 종류의 입력이 함께 필요하다.

| 입력 | 쉬운 뜻 | 누락됐을 때 생기는 실제 문제 |
|---|---|---|
| 모델·텍스처·UV·색 채널 | 그릴 모양과 재료 | 추가 UV 누락, 잘못된 material 선택, 거리에 따른 깜빡이는 무늬 |
| 재질식·shader 분기·uniform | 그 재료를 빛과 섞는 방법 | 금속이 갈색 고무처럼 보임, 사각형 sprite, 반사색 손실 |
| 발생 시간·위치·회전·기본값 | 어디서 언제 어떻게 움직이는지 | 재질은 맞는데 100배 크거나 90도 돌아가고 파편이 한쪽에 모임 |
| 장면 입력·조명·합성·카메라 | 장면 속에서 최종 표시하는 방법 | 유리 배경 왜곡 부재, lightmap 중복, 노출 손실, 전체 재생 누락 |

따라서 텍스처를 찾았거나 유리 하나가 보였다는 사실은 큰 진전이지만 전체 스킬 완성과
같지는 않다. 반대로 새 스킬마다 모든 코드를 처음부터 만들 필요도 없다. **같은 원본
프로그램과 입력 계약이면 재사용하고, 다른 계산·geometry·장면 입력만 추가한다.**
색만 다른 MIC는 값 변경으로 끝날 수 있으나 static switch·opacity·굴절·화면 합성이 다르면
같은 유리라는 이름만으로 같은 프로그램이라고 판단하지 않는다.

현재 흐름은 full restore에서 원본 재질·발생을 복구한 뒤 사용자가 개별 재생으로 핵심을
남기는 것이다. W/E full의 사용자 선별 결과는 보존한다. Q 튜닝은 성공2개+실제 crack1개이며
파편 크기는 full Q mesh03의 원본 size4모듈/SourceScale1과 같다. R/A 검격 교정은 현재
사용자가 선별 중인 full 문서를 대상으로 한다. W/F/V의 파편은 cube가 아닌 crack이다.
Alt V 튜닝은 원본 box25행+crack1행+원본 CModel cue1개와448 camera key를 사용한다.
초기2개 mesh와 후반 skinned model cue에 occurrence의 연출 직전 HDR/Bloom 캡처와 ALT178
native material을 연결했다. 현재 full311행/tuning26행과 retimed cube WModel의 설치를
확인했으며 원작 capture camera의 동일성과 사용자 화면 판정은 별도다.

작업량은 파일 개수보다 빠진 계약에 좌우된다. 이미 연결한 재질·모델·atlas 조합의 배치 추가는
작고, 새 MIC/UV/분기 연결은 그보다 크며, 카메라 이펙트·자식 모델·화면 후처리가 얽힌 Alt+V는
별도 재생 구성 작업이다. 전체 원본 목록의 admission 조사 없이 기간이나 완성률을 제시하지 않는다.

### 오브젝트 추출에서 재질·환경 입력을 보존하는 공통 절차

새 오브젝트와 기존 모델의 정적·애니메이션·반전 변형 모두 같은 절차를 따른다. geometry와
D/N/S 텍스처만 추출한 결과를 원본 재질까지 적용한 결과로 취급하지 않는다.

공통 도구와 입력 형식은 [LevelPlacementExtractor README](../../Tools/LevelPlacementExtractor/README.md#팀-재추출-순서-가시성기하재질을-함께-보존)를 따른다.
schema3는 actor/component·archetype/CDO의 source visibility를 보존하며 LV_MODULE/nav/water/FX
이름으로 숨기지 않는다. 기존 Bern/variant cook은 실제 glTF의 추가 UV·COLOR0·tangent.w를
WModel에 보존한다. 공용 source parameter 추출기는 명시적0/false/null과 부모 상속을
보존하고 미기록 기본값을 별도 보고한다. 원본 mip 회수는 mip0 압축 byte 일치 후 수행한다.
source surface compiler와 scene consumer는 정확한 slot/MIC/필드 coverage 및 입력·texture
hash를 대조한다. 알 수 없는 scalar나 render flag를 family 전체 지원으로 대신 승인하지 않는다.
MIC switch OFF만으로 vertex/pixel의 다른 경로까지 해당 값을 쓰지 않는다고 단정하지 않는다.

1. 원본 mesh의 실제 material array와 actor/component override를 찾고, 각 slot의 MIC 상속·
   static switch·shader permutation·uniform 기본값·texture/sampler를 해석한다. 이름이 같은 slot도
   variant MIC가 다를 수 있으므로 model ID와 원본 object 경로를 함께 확인한다.
2. geometry는 필요한 UV0/UV1/UV2, vertex color, normal/tangent와 단위를 보존한다. WMA2의 일반
   텍스처 경로 외에 native family/program과 named parameter, mask 채널, roughness/specular,
   IBL texture 또는 cube, BRDF LUT, 색 공간과 sampler를 해당 material descriptor에 연결한다.
   WModel 변환 자체가 이 shader 계약을 자동으로 추론하지는 않는다.
3. actor/weapon의 기존 exact model 재질은 `CActorCatalog::Build_ModelLoadDescription`으로
   `CModel → CMaterial`에 전달한다. 파생 World Object는 원본과 slot이 같을 때
   `materialSourceModelAssetId`로 기존 catalog 재질을 참조한다. 배경 source는 승인된 Area
   `mapMaterialBindings`를 사용한다. 한 모델의 family나 program 번호를 모든 오브젝트에 복사하지 않는다.
4. 맵의 직접광·ambient·환경 영역·fog·노출은 장면 입력으로 별도 확인한다. 원본 IBL 반사와 장면
   조명은 서로 대체하지 않는다. 배치에 종속된 RNM/lightmap/static shadow를 움직이는 파생 모델에
   복사하거나 빠진 반사를 맵 ambient 증가로 가리지 않는다. geometry의 음수 축 반전은 광학 반사가 아니다.
5. 실제 target slot과 descriptor 입력, Resources 파일·추가 UV, publisher 결과와 runtime 소비를
   확인한다. 모델·재질·입력·게시·빌드·사용자 화면 확인 상태를 구분한다. 미지원 family 또는
   명시 source의 누락은 오류를 보존하며 이전 승인 객체/저장을 유지한다.

보조 MRT·색 인코딩 전체까지 동일함을 입증한 것은 아니다.

Q의 검격은 별도 Slice 식이다. flow texture, UV 변형, 반경 mask, 칼날 무늬, depth fade가
함께 작동한다. 다른 스킬의 검격도 이 식과 동일한 원본 프로그램이면 재사용할 수 있다.
이름이 검격이라는 이유로 모든 distortion/보조 합성 분기가 같다고 보지는 않는다.

### Alt+V 큐브 안의 SceneCapture는 일반 유리 굴절과 다른 입력이다

사용자 첨부에서 카메라는 캐릭터 상체를 비추지만 큐브 면에는 맵 바닥과 캐릭터를 위에서
본 장면이 담겨 있다. 실제 원본에도 enabled `CEFActionNotify_SceneCapture`가0~.1초에 있다.
초기 camera notify013의 `par_m_swp_tw_s1_camera_01` emitter18/31은 `fm_h_box_01_1`을
카메라 앞.5m에 두고 `fx_m_me_swp_box_01`을 요구한다.2초의 notify036 애니메이션 큐브도
같은 override를 요구하지만 별도 발생이다. 첫 화면의 큐브를 후반 model cue 하나로 단정하지 않는다.

이 재질의 원본 PS는 `screencapture` texture를 world position과 engine-owned CB0[0..5]
행렬로 계산한 좌표에서 읽는다. `00_alpha01_usecamuv=true`, `99_use_meshtype=true`,
`capture_centeruvtile=1.15`를 확인했다. Parent는 masked이고 실제 lighting model은
`mlm_unlit`이다. 과거 out의 PS pass 이름에서 추정한 lit/non-unlit 분류는 부정확하다.

현재 Q42의 `Target_EffectSceneColor`는 해당 occurrence 직전 HDR 복사본이다.
Alt V 초기 emitter18/31은 별도 ALT178의 원본116 RT0 식을 사용하며 occurrence 시작에
완료된 `Target_SceneHDR`를 GPU에서 한 번 복사해 frozen texture로 보관한다. Save refresh는
그 occurrence의 기존 캡처를 유지한다. 화면 이미지 파일을 저장하거나 UI를 캡처하지 않는다.

원본 capture-view CB0[0..5]는 미해석이다. 현재는 프로젝트 cube-face UV→원본 /360 식의
명시 adapter이며 원본 masked RT0 alpha0도 기존 alpha carrier의 particle alpha로 연결했다.
따라서 native RGB/왜곡 식 연결과 원작 capture camera/투영의 동일성은 구분한다. 후반
animated CModel의 skeleton/clip/child bone과 30Hz retime을 유지하며 exact cube ModelCue도
ALT178 capture override를 사용한다. 기존 사용자 opacity/tint는 유지한다. 이는 현재 view의
2D texture를 mesh에 넣는 구조이며 6면 cubemap rendering이 아니다. 사용자 구도·투명도 판정 전이다.

### 셰이더 패스의 상태 차이와 중복 컴파일을 구분한다

같은 VS_MAIN/PS_MAIN을 pass마다 compile하면 Effect bytecode에 실행 코드가 반복될 수 있다.
기존 결과의 실제 SHEX가 mesh7벌/particle5벌 동일했다. 두 preview entry는 이제 global
VertexShader/PixelShader 각1개를 compile하고 기존7/5개 pass에서 공유한다. pass 순서·이름과
blend/depth/cull은 그대로다. 새 복원 식을 포함한 Debug /Od /Zi 검사는72초/93초이며
결과는98.34MB→14.16MB,74.24MB→15.29MB다. 전체 Product 빌드 시간의 보장은 아니다.
새 HLSLI 계산 변경은 해당 CSO를 재생성하지만 JSON 색·크기·위치·수명 손튜닝은 FXC 대상이 아니다.
패스의 VS/PS 공유만으로 큰 native switch의 컴파일 비용이 해결되지는 않는다. 새 프로그램을
기존 cohort에 추가할 때 64 ID 구간별 물리 include와 실제 carrier 선택을 함께 확장한다.
쿠크 installer처럼 한 구간의 상한만 계속 늘리면 수백 재질을 하나의 PS로 컴파일하게 된다.
생성기·include·dispatch·실행 표·project/filter를 같은 변경에서 맞추고 함수 본문과 native ID를
보존한다. write-if-changed와 무변경 Build, 한 leaf의 실제 재컴파일 범위도 확인한다.
새 분할의 시간·제품 검증은 [빌드 성능 결과 G09](09-09/2026-09-09_EFFECT_SHADER_BUILD_AND_PLAY_ALL_PERFORMANCE_RESULT.md)를 따른다.
FXC의 float4 배열 초기화에서는 각 원소를 float4로 명시한다. 배열 안의 scalar 0을 혼합하면
X3017 initializer 불일치가 발생할 수 있으므로 값은 유지하며 float4(0,0,0,0)으로 작성한다.

### E01. RGBA를 찾는 것과 실제 소비까지 연결하는 것은 다르다

원본 package → material instance → parent/static switch → 선택 shader → texture/sampler와
uniform → mesh/particle varying → 장면 입력 → blend/depth의 순서로 따라간다. ABI는 이
입력을 어느 위치와 형식으로 전달하는지의 계약이고, shader 식은 전달된 입력을 계산하는
코드다. 둘 다 필요하다. raw shader를 찾았다는 사실만으로 DynamicParameter나 VertexColor,
source UV, SceneDepth가 올바르게 공급된다고 판단하지 않는다.

색 변화만 필요하면 descriptor/parameter를 재사용한다. 수식이 다르면 같은 파일의 명시적
프로그램이나 별도 HLSLI로 분리할 수 있다. 스킬마다 복사본을 늘리는 것보다 같은 원본
계산을 한 곳에서 고치는 편이 확대에 유리하다. shader 수천 개를 수동 제작하는 것이 목표가 아니다.

### E02. 노란 사각형은 반드시 texture 누락을 뜻하지 않는다

Q45/49는 원본 Dynamic 모듈이 없는 경우 (1,1,1,1) 입력이 필요했다. 0을 공급한 상태에서
Q45는 UV가 중앙 한 점으로 모이고 opacity 지수가 0이 돼 큰 평면이 드러났고,
Q49는 alpha/fade 식을 제대로 소비하지 못했다. 해당 두 프로그램의 모듈 부재에만 기본값을
공급한다. 실제 Dynamic 모듈/곡선은 그대로 평가하며 다른 프로그램에 1을 전역 강제하지 않는다.

skeletal ModelCue는 particle DynamicParameter를 소유하지 않는다. 창술사 T 용의 native1360처럼
원본 재질의 `MeshEmitterDynamicParameter`를 사용하는 경우에는 이미 bind한 material parameter를
명시적으로 전달한다. zero-init particle 입력을 그대로 넘기면 source noise가 정상이어도 opacity가
항상0이 된다.1360은 `g_LanceVASourceMaterialParameters[8u]`를 소비하며 다른 profile은 기존 입력을 유지한다.

사각형이 남으면 material 선택·alpha 식·blend·입자 UV·정렬을 분리한다. 사각형이라고 모두
같은 결함은 아니다. 검은 조각 역시 additive/alpha 합성 후보를 먼저 구분하고 이미지 한 장으로
발생 element를 확정하지 않는다.

### E03. `unbound`와 원형 빛

이전 All Effects의 `unbound`는 표시할 Resource 파일명을 찾지 못했다는 라벨이었다.
Q47은 원본 PS의 texture sample이 0개인 절차적 glow이므로 texture가 없는 것이 정상이다.
UV 중심까지 거리 `d = length(UV - 0.5)`로 감쇠를 만들고 power·색·alpha를 계산한다.
원형 입자도 사각 평면 위에서 바깥을 투명하게 만들어 보인다.

정확한 Q47 material 계약이 확인된 경우만 `Procedural Glow (no texture)`로 표시한다.
다른 진짜 누락 Resource의 unbound를 일괄 정상 표시로 바꾸지 않는다.

Q47의 원형은 UV 안의 감쇠 형태다. 원본 Size는 200×600cm이고 속도 정렬·pivotY=0.9,
크기 수명 곡선을 함께 사용한다. 따라서 최종 화면에 항상 완전한 원으로 나타나는 것은 아니다.
중앙의 장식 무늬나 검격까지 Q47 하나가 그린다고 이미지 한 장으로 단정하지 않는다.

### E04. 원본에서 생략된 값은 0이 아니다

원본은 instance에서 변경된 값만 저장할 수 있다. class-default(CDO) → archetype → instance를
필드별로 합쳐야 한다. Q는 8개 분포에서 실제 행동을 바꾸는 기본값이 빠졌다.

| 발견 | 실제 영향 | 교정 방식 |
|---|---|---|
| Mesh/Sprite StartRotation 범위 누락 | 파편/검격이 같은 방향에 모임 | 원본 uniform 범위와 LUT metadata 복원 |
| MeshRotationRate의 LUT는 있지만 op/chunk 누락 | 범위에서 고르지 않고 첫 값만 읽음 | 명시 LUT 유지, 상속 metadata만 복원 |
| LocationDirect ScaleFactor 1이 0으로 투영 | 원본 -130→110cm 이동 곡선이 소거됨 | source (1,1,1) 기본 분포 연결 |
| Cylinder VelocityScale 1 누락 | 원기둥 반경 방향 이동이 없음 | source 1 복원과 radialvelocity=true 소비를 함께 연결 |

Cylinder radial velocity는 높이축을 뺀 원형 평면의 속도다. 원본 CDO의 true를 확인했고
기존 소비자에 명시된 true만 적용한다. 속도값을 먼저 복원하고 이 분기를 빼먹으면 높이축으로도
파편이 흩어진다. 의미 대조는 [Epic Cylinder 설명](https://dev.epicgames.com/documentation/en-us/unreal-engine/location-modules?application_version=4.27)을 참고했으며,
이 문서가 LostArk CPU 구현 전체를 증명하는 것은 아니다.

명시적 0/false/LUT는 덮어쓰지 않는다. 전역 default=1 패치는 금지한다. 이번 Q 원샷 수량은
원본 burst 합계 15개이며, 기존 손 조정 count 배율을 전체 복구본에 복사하지 않는다.
원본과 난수열·모든 CPU 옵션까지 동일한지는 별도 경계다. bAdjustForWorldSpace,
bInheritParent와 생략된 Required duration 등은 확인된 소비 범위 이상으로 완료 처리하지 않는다.

자동 확대의 다음 수정 지점은 기존
[build_imported_effect_documents.py](../../Tools/LevelPlacementExtractor/build_imported_effect_documents.py)의
`SourceIndex`다. 현재 raw properties만 복사하고 class/archetype 상속을 소비하지 않으며,
`build_distribution_recipe`는 op가 없으면 target class로 1/2를 추정한다. 따라서 Q JSON을
고친 것만으로 다음 스킬의 자동 변환이 교정되지는 않는다. 명시적인 native CDO/archetype
입력을 같은 SourceIndex에서 합친 뒤 기존 분포·duration/detail 생성기를 재사용해야 한다.
struct의 필드 병합과 배열 전체 교체, 명시 0/false/null 보존, 상속 순환/누락 시 오류 보존을
검증하고 우선 Q10만 재생성해 대조한다. 이 공통 importer 확장은 현재 미구현이며 전체
authored 문서를 일괄 재생성하는 작업과 분리한다.

### E05. 100배 크기와 90도 방향은 서로 다른 단계다

쿠크처럼 ActorX/FBX로 쿠킹한 MN_RPCT_05의 골격은 root basis100을 이미 포함한다.
설치된 세 공격 clip의 본을 읽으면 CModel preScale .017 뒤의 basis는1.7이며 socket local
입력은 미터다. 이 본에 cm 역보정100을 또 곱하면170이 되어 크기뿐 아니라 소켓 오프셋도
100배로 벌어진다. `Build_SourceAnchorWorlds`는 이미 포함된 단위를 다시 곱하지 않는다.
정점 단위, skeleton local/root basis, model preScale, owner root와 notify offset을 따로 측정한다.
raw 행렬이 유한하다는 검사나 synthetic1.7 anchor를 넣은 성공은 실제 모델 부착 검증이 아니다.

설치된 Q cube/swing/crack WModel 정점은 원본 cm를 `(x,z,-y)`로 변환한 것이다.
modelPreScale=.01은 단위 변환이고 원본 StartSize는 입자 크기다. 둘을 중복 적용하지 않는다.
Character CModel은 추가 Y -90도 import basis를 쓰지만 root Transform에는 그 회전이 없다.
Q의 root snapshot에 source basis -90도를 한 번 넣어 source +X 전방을 actor +Z에 맞춘다.

원본 cue 위치·속도·메시를 각각 눈대중으로 90도 돌리지 않는다. 기존
`actionCueAttachment.snapshotRootSourceBasisYawDegrees`가 local 공간 입력 전체에 같은
기준축을 적용한다. bone-follow나 다른 캐릭터에 전역 강제할 값이 아니다.
회전은 거리 자체를 줄이지 않으므로 남은 거리 차이는 anchor·location·원본 cue로 다시 분리한다.

일부 mesh만 90도 틀리면 먼저 실제 정점의 면·긴 축과 원본 TypeData pre-rotation을
확인한다. sourceRecipe literal의 존재와 `detail.mesh.sourceTypeDataRotationDegrees`의
runtime 소비는 다르며, 특정 asset 전용 codec 보정이 다른 asset까지 처리한다고 가정하지 않는다.
FRotator 정수·StartRotation turn·TypeData degree를 구분하고 기존 UE3 Euler 변환으로
pre-rotation과 particle rotation을 각각 한 번 적용한다. 최종 재생 행렬의 중심·전방·법선과
geometry preScale을 포함한 크기를 대조한 뒤 사용자 화면 확인을 받는다. 원본 notify 배율과
사용자 확대값을 분리하며, 정상 carrier나 다른 bone-follow occurrence에 일괄 보정을 넣지 않는다.

### E06. Play All이 2초 멈춘 뒤 끝으로 가면 시계와 준비를 구분한다

원본 Q 수명보다 긴 동기 resource 준비 시간이 첫 dt에 포함되면 재생 시작부터 끝으로
이동한다. Preview row를 만들었는데 Sequencer Play가 그 임시 row를 삭제하거나 입력
owner를 요청하지 않는 경우도 있었다. 리소스가 보이는 Family 재생 성공이 전체 재생의
성공을 보장하지 않는 이유다.

현재 Play/Preview는 transient row를 유지하고 성공 시 interaction을 요청한다. 준비 직후
한 번의 advance를 제외하며 정상 dt는 그대로 사용한다. full recovery는 버릴 WorldPreview를
먼저 준비하지 않고 Sequencer occurrence를 한 번 준비한다. 실패 시 기존 유효 row를
보존하고 Loop는 선택 anchor를 유지한다. GPU 초기 준비 자체가 무조건 사라지는 것은 아니다.

실제 멤버 함수 CPU 대조에서 이전 transient 삭제/큰 dt skip/owner 누락을 재현했고 수정
분기를 검증했다. GPU·모델 경계는 대역이므로 UI 재생과 화면 PASS를 대신하지 않는다.

### E07. 원본 Product, 복구본, 손 조정본을 구분한다

복구본은 `Data/Effects/Authored/*.restore.effect.json`이고 All Effects의 해당 skill Product
아래 Recovery Effect로 연결한다. 제품 `.unified`와 성공한 Q2 비교본을 자동 덮어쓰지 않는다.
현재 full Q는 `effect.dimensionmaster.skill.2050100.full.restore`다. 별도 툴 대신 기존 V1의
All Effects·Model View·Sequencer·Play/Family를 사용한다. Save/Load는 같은 stable ID와
원본 식 입력을 보존하며 editor draft도 실제 occurrence snapshot에 전달해야 한다.

먼저 full Q를 Model View root 기준으로 Play All하고 같은 시각을 Seek/Family로 비교한다.
원본 위치·회전·기본값을 정리한 뒤에도 차이가 남으면 hand authoring 단계로 넘어갈 수 있다.
그때 바꾼 위치/색/수량은 PROJECT_TUNED로 기록하고 원본 바이너리에서 얻은 값으로 포장하지 않는다.

손튜닝본의 optional `sourceRecipe.authoredModuleOverrides=true`는 기존 module/distribution
편집 UI를 연다. sourceRecipe 실행·재질·geometry 소비는 유지하며 원본 full과 native 증거는
읽기 전용으로 남긴다. Q42 몸체는 material `color`, Q51 윤곽은 `aura_color`가 소유한다.
일반 RGBA만 바꾸고 실제 색 입력을 수정했다고 판단하지 않는다.

같은 재질의 반복은 emitter burst로 합칠 수 있지만 birth 시각과 particle age를 구분한다.
Q42 유리는 출생 시각별 위치·크기·수명·속도 곡선으로 묶을 수 있다. Q51 검격은 material
UV가 emitter 시간에 의존하므로 여러 타격을 한 emitter로 합치면 후속 검격의 무늬가 바뀐다.
element 수 감소를 목표로 이 차이를 버리지 않는다. 셰이더 계산·컴파일 변형 수와 실제
particle 수·화면 중첩 비용도 따로 확인한다.

### E08. 속도 정렬의 U/V와 모델 기준축은 별개다

Q의 원본 offset-center VS 두 개는 앞 181개 명령이 동일하다. velocity 선택 분기에서
U=cross(toCamera,motion), V=-motion을 사용한다. Required의 명시 PSA_Velocity를 읽어도
renderer가 local X를 속도에 맞추면 세로로 긴 검격·glow가 90도 틀어진다.
우리 ParticleRect는 local=(u-0.5,0.5-v)이므로 이 분기를 표현하는 world matrix는
row0=U, row1=+motion이다. row1을 -motion으로 복사하면 UV가 뒤집힌다.

Make_ParticleSpriteWorld는 확인된 Q native profile과 명시 CAMERA_VELOCITY에만 이
3D motion plane을 사용한다. authored pivot/크기를 유지하고 이 정렬에서는 roll을 적용하지
않는다. Q49의 명시 rectangle, 다른 profile, source-disabled 경로는 이전 동작을 유지한다.
속도 0 또는 시선과 평행하여 평면을 정의할 수 없는 경우는 기존 finite fallback을 유지한다.
원본 LostArk CPU의 실제 selector CB를 실행 중 회수한 것은 아니며, 원본 VS 분기와
serialized alignment·별도 Epic source 구현을 대조한 명시적 대응이다.

원본 UV 네 모서리와 실제 함수·DirectXMath의 197개 수치 확인은 통과했다.
카메라 평면 안에서 각도만 90도 바꾸면 입자가 깊이 방향으로 움직일 때 오차가 남으므로
단순 전체 yaw 보정으로 이 문제를 대신하지 않는다. 실제 실행 화면의 최종 승인은 별도다.

### E09. 한 클래스의 모든 스킬이 안 나오면 이벤트 문서 로드를 먼저 확인한다

한 슬롯만 다른 경우에는 `PlayerSkills → skillbindings → animevents → 실제 effect asset ID`를
먼저 대조한다. 워로드의 F17140 native446 번개 보강이 V17170에만 있었고 Alt+V17250에는
다른1166 sprite만 복제돼 있던 사례가 있다. Alt+V 두 clip에는 F의 native446 mesh/WPO,
DynamicParameter, root snapshot과 수명을 그대로 재사용하고 실제 startcolor만 황금 HDR로
저작한다. 새 발생 수와 색은 사용자 요청 튜닝이며 원본 Alt+V 발생 수로 기록하지 않는다.

`.animevents`는 원본 참고 행과 제품 `effectref=asset` 행을 함께 세어 헤더의 총 이벤트 수와 비교한다. 제품 EFFECT를 합치거나 삭제하면서 헤더 수를 그대로 두면 `CAnimationEffectCueDocument::Load_FromText`가 문서 전체를 거부하여 정상 스킬까지 등록되지 않는다. Artist Alt V에 이어 LanceMaster Alt V 네 행→한 행 통합에서도 같은 문제가 재발했다(선언3139/실제3136). Effect 파일 존재·catalog ID 연결만으로 완료하지 않고 실제 `Load_ForProductPrewarm`과 설치 모델의 clip catalog를 받는 `Load_WithCatalogSnapshot`을 확인한다. Lance의 헤더 교정 후 두 경로 모두43cue/171HIT, clip·ID·anchor 누락0을 확인했으며 Client 재시작 후 화면은 사용자 검증 대상이다. 통합 도구가 최종 event 산출물의 header count도 함께 소유하게 하고, runtime parser 검사를 끄지 않는다. 상세는 [호랑이·말과 ALT V 결과 G07](09-11/2026-09-11_TIGER_HORSE_ANIMATION_AND_LANCEMASTER_ALTV_RESULT.md#g07-창술사-전체-이펙트-미출력의-실제-로더-회귀)을 따른다.

개별 full 문서의 Codec/Stage 성공만으로 캐릭터 입력 연결을 확인했다고 기록하지 않는다. 기존 로더의 문서 검증을 유지하고, 헤더 수·Catalog 대상과 실제 모델 clip을 넣은 Load를 함께 확인한다. 이미 생성된 캐릭터는 정본 수정 후 class 재선택이나 재입장으로 다시 생성해야 한다. 상세 근거는 [Artist 결과 G09](09-09/2026-09-09_ARTIST_CORE_FULL_RESTORE_IMPLEMENTATION_RESULT.md)에 둔다.

통합 문서는 실제 Product Catalog의 파일 읽기 계약까지 검사한다. [Lance 결과 G08](09-11/2026-09-11_TIGER_HORSE_ANIMATION_AND_LANCEMASTER_ALTV_RESULT.md#g08-alt-v-제품-로더의-16mib--64mib-불일치)에 실패와 수정 후 검사를 구분한다.

본에 붙은 MeshParticle의 방향은 실제 설치 메시의 긴 축, 손본 basis, Source MeshRotation과 TypeData pre-rotation을 함께 확인한다. 같은 창 mesh를 사용하는 T34650의 두 full 문서에도 typed pitch 누락/0이 남아 있었다. 네 창 행을 같은 원본 회전으로 맞추고 dragon 두 행에는 사용자가 ALT V clip1에서 확정한 Transform position `[1,0,0]`을 적용했다. donor의 실제 `Midcontrol -> b_weapon_rhand` 부착은 유지했다. 수정 후 T 화면 확인은 별도이며 [후속 결과 G11](09-11/2026-09-11_TIGER_HORSE_ANIMATION_AND_LANCEMASTER_ALTV_RESULT.md#g11-t-창의-방향과-사용자-alt-v-dragon-위치-적용--2026-09-12)에 기록한다.

### E10. simulation-only 위치 제공 요소는 GPU 발생 수에 포함하지 않는다

위치 제공 요소는 CPU에서 다른 입자의 위치를 계산하지만 그 자체를 그리지 않는다. Playback이 해당 요소를 GpuOccurrences에서 제외하면 Renderer의 GPU family·개수·순서 집계도 같은 조건으로 제외해야 한다. Artist Alt V는254행 중 provider2개가 이 기준과 달라 Render admission에서 실패했다. provider의 visible 값을 끄거나 전체 frame 개수 검사를 없애지 않고 family를 END로 분류해 두 소비자를 맞춘다.

static WorldObject의 CModel material override가 SOURCE_CHARACTER이면 일반 map shader 초기화 뒤에도 Bind_SourceCharacter를 호출해야 해당 재질의 frame/light 입력이 채워진다. 공의 원본 PBR처럼 텍스처가 존재해도 범용 D/N/S/E만 연결하면 mask 의미와 환경반사 계산을 잃을 수 있다.

## 렌더링 복원은 실제 표면에서 소비되는 입력부터 연결한다

렌더링 툴은 이미 구현한 계산의 빛·노출·반사 강도를 비교하고 조정하는 도구다. 빠진 texture 채널, 잘못 선택된 material, 끊긴 lightmap UV나 원본 shader 연산을 slider가 대신 만들어 주지는 않는다. 새 표면은 **보이는 배치 식별 → 실제 material 선택 → 원본 texture/parameter/분기 → CMaterial 입력 → geometry 채널 → shader·조명·후처리** 순서로 확인한다.

원작도 DirectX로 그린다는 사실은 같은 그림을 보장하지 않는다. 같은 GPU 명령을 사용하더라도 어떤 재질식·입력·광원·간접광·색 변환을 조합하느냐가 다르다. 특히 밝게 하거나 채도를 올리는 조작은 원인 분리 이후에 수행한다. 조작감·이펙트 발생 시점·발생 위치는 별도 gameplay/presentation 입력이다.

비어 있어도 component override에 색이 있을 수 있다. 이번7배치에는 실제 색이 있으며
floor4는 모두 다르고 rock3는2그룹이다. A는전부255이고 R은실제분포가 있다. source VS의
BGRA→RGBA swizzle을 한 번만 적용해 CModel COLOR0으로 운반한다.

CPU 정점색 배열이 존재해도 GPU 입력이 연결됐다는 뜻은 아니다. 이번에 WModel reader는
색을 보존했지만 VTXMESH/CMesh 업로드에서 빠진 경로를 발견했다. 실제 vertex stride68,
RGBA8 COLOR0 offset64, 일반·인스턴스 layout과 업로드를 함께 연결했다. 같은 데이터에
swizzle을 다시 적용하지 않으며 public 구조 변경 뒤에는 Engine/Client를 함께 빌드한다.

원본 asm은 레지스터를 덮어쓴 뒤의 값을 추적한다. 이 식의 Base/Direct/Baked는 모두
`overlayD.a² * (1-saturate(baseNormal.z²*D.a))`를 coverage 입력으로 사용한다. 이전
raw XY 길이 해석은 레지스터 덮어쓰기를 놓친 오류였다. 다만 mixed normal은 Base/Baked만
정규화하며 Direct diffuse는 미정규화 mixed normal, Direct specular는 base normal을 쓴다.
기존 G-buffer의 두 여유 재질 입력을 marker7에 한해 재사용해 이 차이를 보존한다.

원본 floor UV1과 현재 WModel/source glTF의 정점 수가 다르므로 같은 인덱스로
UV를 덮어쓰지 않는다. native corner 대응으로 UV1·색·tangent W를 보존해 배치별 variant를
쿠킹했다. UModel 반복 추출의 rock COLOR0/W가 변하거나 UV1의 half-zero 값을 잘못 내보내는 경우도
확인했으므로 원본 native 채널을 대조한다. 같은 atlas도 배치의 좌표·계수는
다를 수 있으며 이동·복제한 EDITOR 배치에 원본 baked를 무조건 재사용하지 않는다.

원본 Point GUID가 lightmap의 참조 목록에 들어 있으면 직접광과 구운 diffuse의 중복 기여를
확인한다. 현재 발탄 Point22개는 다른 배치의 baked에 포함되지만 이번7배치의 GUID와는
교집합0이다. 전체맵의 교집합을 개별 바닥의 중복으로 오해하지 않는다. GUID 일치만으로 즉시 광원을 삭제하거나
모든 원본 광원을 동적으로 추가하지 않는다. 발탄에서 찾은256×16 LUT는 ColorLookupTable
이며 BRDF LUT가 아니다. static map, 파괴 가능한 Deploy, 파편과 원본 LAND/컷신 입력도
실제 소비자와 활성 범위를 나눠 확장한다.

`11789713951910399058`이다. 조사 분모는

### Rendering Workbench에서 확인하고 마지막에 튜닝한다

같은 카메라·선택 배치·광원·Exposure/Gamma/Bloom 상태를 유지하고 Floor Materials의 A/B와 Base color → Normal → Direct specular 또는 Roughness/Metallic/Material AO → Reflection delta → Final 순서로 기여를 분리한다. 이 진단은 지원되는 선택 재질 범위의 출력이다. 화면의 모든 표면을 대상으로 하는 검사는 아니다.

쿠크 선택 바닥 family1/2의 marker1 직접 반사는 재질 RGB에 MapLight diffuse radiance를 곱한다. MapLight가 0으로 두는 legacy specular를 곱해 직접 반사가 끊기는 소비자를 교정했다. marker0/2의 legacy specular와 Phong lobe는 유지한다. 기존 하네스36 GPU조건은 통과했고 수정 전에는 직접 반사만 실패했다. 바닥 전체 검정과 최종 화면 판정은 대응 RESULT로 구분한다.

직접 반사가 검다면 재질 입력뿐 아니라 실제 광원도 확인한다. legacy specular와 선택 PBR 직접 반사는 같은 slider 계약이 아니므로, 어느 shader가 해당 광원의 diffuse/specular를 소비하는지 먼저 읽는다. global 밝기 증가로 이 차이를 가리지 않는다. tone mapping의 clipping·White Point·Gamma는 고유색·빛 입력이 맞은 뒤 맞춘다.

가까운 화면과 먼 화면을 비교해 texture mip/filter, geometry 경계 AA, 재질/빛 결함을 분리한다. 새 MRT와 추가 source material × light draw에는 비용이 있다. 합성 WARP 검사나 빌드 성공으로 실제 장면 GPU 병목 또는 FPS 개선을 주장하지 않는다. 실제 원본 유사도는 사용자가 제출한 관찰과 비교로 종료한다.

검증은 변경 범위의 JSON/XML·기존 publisher·실제 CModel/Clone binding·필수 입력 실패 보존·해당 shader 수치·필요한 최소 컴파일을 재사용한다. 기존 쿠크23/CS57 native 검사와 shader 검사는 그 당시 입력 범위의 증거다. 새 표면을 추가하면서 예전 PASS를 자동 승계하지 않는다. WARP는 실제 shader에 대한 수치 실행이며 원본 Client 화면 비교가 아니다.

### 정적 메시 접선과 actor의 blend·기본 오라

UE→glTF `(x,z,y)`와 glTF→runtime `(x,y,-z)`는 각각 반사다. native packed TangentZ.W를
glTF에 넣을 때 한 번 반전하고 공통 cooker에서 다시 반전해야 최종 runtime W가 원본과 같다.
원본 T/N/W·UV 미분 B와 최종 geometry를 함께 대조한다. 신규 변환에서 발견한 부호 결함을
이미 정상인 모델에 전파하지 않는다. 현재 쿠크 FLOOR08/FLOOR08A와 기존 발탄7개는 원본 대조 후 유지했다.

유령 발탄 program84는 원본 master의 translucent 계약을 기존 native character forward pass로
소비한다. 격자 coverage를 원본 alpha 합성과 혼동하지 않는다. post-render depth/sort는 별도 경계다.
LookInfo 기본 오라는 action notify와 구분해 실제 본·TRS·owner 수명을 연결한다. source loops0은
유한1회가 아니며, owner-sustained 재생은 기존 고정 step Update를 유지한다. 주기 reset이나 매프레임
전체 Seek로 입자 이력을 대체하지 않는다. 세부 근거·검증은 [맵·발탄 결과](09-15/2026-09-15_MAP_AND_VALTAN_FULL_RESTORATION_RESULT.md)에 둔다.

### 원본 장면 후처리와 밝기 비교

Bern/Character Select의 원본 WorldInfo·chain·환경 영역은 같은 bloom이나 ambient 숫자로
대체할 수 없다. World override와 effect의 bUseWorldSettings, inherited flag를 함께 resolve한다.
Bern Lightmass의 환경색은 baked 입력이고, 실제 runtime SH packing은 별도 경계다.
현재 local light315개 중285 SOURCE_CHARACTER 분리는 유지하며, 원본 monster carrier를 쓰는
배경의 material baked enabled와 픽셀 RNM flag가 모두 있을 때는 이 광원을 다시 더하지 않는다.

Rendering Benchmark의 Before/Restored source profile/Return은 네 맵의 별도 profile을 사용하는
session 비교다. 원본 bloom threshold/scale/tint와 맵·region의 활성 후처리를 기존 service로 연결한다.

블록이 없는 profile은 기존 Hable을 유지한다. 이것은 SSAO, DOF, vignette, 원본 sun exclusion과

기존 RNM/반사/발광이 함께 담긴 emissive의 안개 처리는 버퍼 의미를 분리하기 전에 통째로 바꾸지 않는다.
앞 단계 입력 출처는 [원본 렌더링 결과](09-14/2026-09-14_BERN_RENDERING_RESTORATION_RESULT.md),

사용자의 A 원본 관찰에서 검격 경계의 가로 파쇄는 정상 표현이다. 검은 중심 면과 보라색

### 원본 재질 증가 이후 실제 로딩과 배포 확인

[베른 FPS 결과](09-11/2026-09-11_BERN_FRAME_TIME_RECOVERY_IMPLEMENTATION_RESULT.md)에 구현과 미측정 경계를 기록한다.

### Source Modulate와 collision event의 현재 소비 범위
