# 렌더링·이펙트 복원 V2

이 문서는 Character Select·캐릭터·무기·스킬 이펙트를 복원하면서 확인한 원리, 반복 결함,
실제 연결 범위와 다음 확장 순서를 유지하는 공통 노트다. 이름의 V2는 이 기록의 두 번째
복원 단계이며 **Effect Tool V2 전용 문서나 새 런타임의 이름이 아니다.**

복원·손튜닝 문서는 F1 `Effect Tool V1`에서 계속 편집한다. `Effect Tool V2`는 별도 창으로
leaf/group·target attachment를 편집하며 V1을 열 때 함께 생성하지 않는다. 각 도구의 draft와
Sequencer를 분리하고, 기존 V1의 선택 항목 지연 로드·저장 성능 개선을 유지한다.

새 작업은 먼저 해당 표면/스킬의 현재 코드와 이 노트를 확인한다. 확인된 원인과 해결 방법은
이 문서의 해당 항목을 갱신하고, 날짜별 변경 파일·빌드 로그·실패 과정은 대응 RESULT에 둔다.
오래된 현재 상태를 남긴 채 아래에 반대되는 내용을 계속 붙이지 않는다. 조사만 한 후보,
제품 소스에 연결한 항목, 빌드한 항목, 사용자가 화면에서 확인한 항목을 구분한다.

현재 작업의 상세 근거: [구현 PLAN](09-08/2026-09-08_CHARACTER_MATERIAL_AND_EFFECT_ROUND2_ESTIMATE_PLAN.md),
[구현 RESULT](09-08/2026-09-08_CHARACTER_MATERIAL_AND_EFFECT_ROUND2_ESTIMATE_RESULT.md).

## 먼저 이해할 원리와 확장 순서

최종 그림에는 네 종류의 입력이 함께 필요하다.

| 입력 | 쉬운 뜻 | 누락됐을 때 생기는 실제 문제 |
|---|---|---|
| 모델·텍스처·UV·색 채널 | 그릴 모양과 재료 | 추가 UV 누락, 잘못된 material 선택, 거리에 따른 깜빡이는 무늬 |
| 재질식·shader 분기·uniform | 그 재료를 빛과 섞는 방법 | 금속이 갈색 고무처럼 보임, 사각형 sprite, 반사색 손실 |
| 발생 시간·위치·회전·기본값 | 어디서 언제 어떻게 움직이는지 | 재질은 맞는데 100배 크거나 90도 돌아가고 파편이 한쪽에 모임 |
| 장면 입력·조명·합성·카메라 | 장면 속에서 최종 표시하는 방법 | 유리 배경 왜곡 부재, lightmap 중복, 노출 손실, 전체 재생 누락 |

따라서 텍스처를 찾았거나 유리 하나가 보였다는 사실은 큰 진전이지만 전체 스킬 완성과
같지는 않다. 반대로 새 스킬마다 모든 코드를 처음부터 만들 필요도 없다. **같은 원본
프로그램과 입력 계약이면 재사용하고, 다른 계산·geometry·장면 입력만 추가한다.**
색만 다른 MIC는 값 변경으로 끝날 수 있으나 static switch·opacity·굴절·화면 합성이 다르면
같은 유리라는 이름만으로 같은 프로그램이라고 판단하지 않는다.

현재 흐름은 full restore에서 원본 재질·발생을 복구한 뒤 사용자가 개별 재생으로 핵심을
남기는 것이다. W/E full의 사용자 선별 결과는 보존한다. Q 튜닝은 성공2개+실제 crack1개이며
파편 크기는 full Q mesh03의 원본 size4모듈/SourceScale1과 같다. R/A 검격 교정은 현재
사용자가 선별 중인 full 문서를 대상으로 한다. W/F/V의 파편은 cube가 아닌 crack이다.
Alt V 튜닝은 원본 box25행+crack1행+원본 CModel cue1개와448 camera key를 사용한다.
초기2개 mesh에 occurrence의 연출 직전 HDR 캡처를 연결했으며 후반 skinned model-cue의
native capture override는 미완료다. 사용자가 확정한 미지원 Solo 정리 뒤의 full 데이터 수는 아래 표와 RESULT에 둔다.

작업량은 파일 개수보다 빠진 계약에 좌우된다. 이미 연결한 재질·모델·atlas 조합의 배치 추가는
작고, 새 MIC/UV/분기 연결은 그보다 크며, 카메라 이펙트·자식 모델·화면 후처리가 얽힌 Alt+V는
별도 재생 구성 작업이다. 전체 원본 목록의 admission 조사 없이 기간이나 완성률을 제시하지 않는다.

마리오 공처럼 기존 `Effect/.../Meshes` 아래 파일이 있는 경우에도 본체가 particle-only라는 뜻은 아니다.
MN_PPCC_00의 노란/파란 LookInfo는 같은 skeletal mesh와 서로 다른 명시 MIC/DDS를 사용한다.
정적 Map Assets 배치에는 원본 bind geometry를 NONANIM으로 쿠킹하고 glTF의 실제 material 이름에
variant diffuse/normal/specular를 연결한다. 원본 리그/클립, shader 전체 복원, 피격/폭발 gameplay는 별도다.
현재 공 2종과 MN_RHCN_01 폭탄, 추가 빨간 별/줄무늬/광대 얼굴 공 및 MN_REUP_04+나팔 정적 소품의 Palette 연결·Drive 위치·수동 확인 경계는
[마리오 Palette 결과](09-09/2026-09-09_MARIO_PALETTE_PROPS_RESULT.md)에 기록한다.
추가 네 소품은 WORLD Object Resource와 HOLD 표시 모션도 등록했다. 이는 기존 Play Sequence trigger의 presentation이며 불꽃, 공격 AI, 영구 server entity를 추가한 것은 아니다. 실제 위치·트리거와 광대 기본 자세의 화면 확인은 사용자 설정/판정으로 남긴다.

마리오 원본 몬스터 REUP/RHKP/CDMD의 PSA→glTF 결합에서는 root 회전을 유지하고
자식 뼈 quaternion을 conjugate해야 한다. PSA track 순서/flattened parent가 아니라
mesh의 실제 hierarchy를 사용한다. 이를 생략하면 팔·손이 뒤틀리고 같은 뼈에 붙은 망치도
어긋난다. 또한 UModel의 normalized UINT8 skin weights는 현재 bundled Assimp에 넣기 전에
FLOAT accessor로 풀어야 한다. 그대로 넣으면 일부 가중치가 garbage/NaN/Inf로 쿠킹된다.
`build_umodel_gltf_psa.py`는 이 두 변환을 수행한다. 기존 재질·geometry·socket을 임의로
바꿔 가리는 문제가 아니다. 이번 재쿠킹은 MarioOriginal의 3종만 해당하며 다른 자산까지
일괄 갱신하지 않는다. 뼈대/가중치 수치 확인과 사용자의 실제 모션 승인은 별개다.

Sprite/Mesh는 **그리는 geometry 종류**다. 각각 하나의 shader family 이름이 아니다.
한 sprite 안에도 texture mask·절차적 원형 빛·굴절·깊이 fade 등 서로 다른 프로그램이 있다.
현재 registry는 복원한 원본 식, 제한된 adapter, 프로젝트 튜닝이 함께 존재하므로
“공통 family가 전부 복원됐다”는 표현을 사용하지 않는다.

full은 검토 문서의 이름이다. 모든 원본 action/광원/발생량과 실제 시각 결과의 완료 표식이 아니다.
현재 Alt V318은 수치 fixture에서308행이 발생하며8행은 .1초 fallback 창보다 뒤의 burst까지
도달하지 않는다. importer의 요소당64 BUDGET_CLAMP는 엔진의 입자 수 한도가 아니다.
원본 burst/rate/loop와 현재 cap을 대조하고 실제 Spawn 요청·수용·손실을 분리해 기록한다.

같은 모델의 입자를 묶을 때는 primitive 순서와 effective shader/texture 상태를 함께 보존한다.
여러 submesh를 각각 instance로 바꾸면 alpha 순서가 바뀔 수 있다. 동일 상태인 submesh의
기하를 CModel 내부에서 원래 순서로 준비한 뒤 입자 전체를 instance로 반복하면 순서를 유지할
수 있다. source material slot 범위는 보존하고 override/geometry/입력 변경 때 재검증한다.
현재 native mesh occurrence에 이 구조를 적용했다. crack032/037의 실제 CModel WARP 검사182건과
일반/instance shader의 GPU 수치 대조를 수행했다. 원본 vertex68-byte/index32 ABI는 유지한다.

### E01. RGBA를 찾는 것과 실제 소비까지 연결하는 것은 다르다

원본 package → material instance → parent/static switch → 선택 shader → texture/sampler와
uniform → mesh/particle varying → 장면 입력 → blend/depth의 순서로 따라간다. ABI는 이
입력을 어느 위치와 형식으로 전달하는지의 계약이고, shader 식은 전달된 입력을 계산하는
코드다. 둘 다 필요하다. raw shader를 찾았다는 사실만으로 DynamicParameter나 VertexColor,
source UV, SceneDepth가 올바르게 공급된다고 판단하지 않는다.

색 변화만 필요하면 descriptor/parameter를 재사용한다. 수식이 다르면 같은 파일의 명시적
프로그램이나 별도 HLSLI로 분리할 수 있다. 스킬마다 복사본을 늘리는 것보다 같은 원본
계산을 한 곳에서 고치는 편이 확대에 유리하다. shader 수천 개를 수동 제작하는 것이 목표가 아니다.

### E02. 노란 사각형은 반드시 texture 누락을 뜻하지 않는다

Q45/49는 원본 Dynamic 모듈이 없는 경우 (1,1,1,1) 입력이 필요했다. 0을 공급한 상태에서
Q45는 UV가 중앙 한 점으로 모이고 opacity 지수가 0이 돼 큰 평면이 드러났고,
Q49는 alpha/fade 식을 제대로 소비하지 못했다. 해당 두 프로그램의 모듈 부재에만 기본값을
공급한다. 실제 Dynamic 모듈/곡선은 그대로 평가하며 다른 프로그램에 1을 전역 강제하지 않는다.

skeletal ModelCue는 particle DynamicParameter를 소유하지 않는다. 창술사 T 용의 native1360처럼
원본 재질의 `MeshEmitterDynamicParameter`를 사용하는 경우에는 이미 bind한 material parameter를
명시적으로 전달한다. zero-init particle 입력을 그대로 넘기면 source noise가 정상이어도 opacity가
항상0이 된다.1360은 `g_LanceVASourceMaterialParameters[8u]`를 소비하며 다른 profile은 기존 입력을 유지한다.

사각형이 남으면 material 선택·alpha 식·blend·입자 UV·정렬을 분리한다. 사각형이라고 모두
같은 결함은 아니다. 검은 조각 역시 additive/alpha 합성 후보를 먼저 구분하고 이미지 한 장으로
발생 element를 확정하지 않는다.

### E03. `unbound`와 원형 빛

이전 All Effects의 `unbound`는 표시할 Resource 파일명을 찾지 못했다는 라벨이었다.
Q47은 원본 PS의 texture sample이 0개인 절차적 glow이므로 texture가 없는 것이 정상이다.
UV 중심까지 거리 `d = length(UV - 0.5)`로 감쇠를 만들고 power·색·alpha를 계산한다.
원형 입자도 사각 평면 위에서 바깥을 투명하게 만들어 보인다.

정확한 Q47 material 계약이 확인된 경우만 `Procedural Glow (no texture)`로 표시한다.
다른 진짜 누락 Resource의 unbound를 일괄 정상 표시로 바꾸지 않는다.

Q47의 원형은 UV 안의 감쇠 형태다. 원본 Size는 200×600cm이고 속도 정렬·pivotY=0.9,
크기 수명 곡선을 함께 사용한다. 따라서 최종 화면에 항상 완전한 원으로 나타나는 것은 아니다.
중앙의 장식 무늬나 검격까지 Q47 하나가 그린다고 이미지 한 장으로 단정하지 않는다.

### E04. 원본에서 생략된 값은 0이 아니다

원본은 instance에서 변경된 값만 저장할 수 있다. class-default(CDO) → archetype → instance를
필드별로 합쳐야 한다. Q는 8개 분포에서 실제 행동을 바꾸는 기본값이 빠졌다.

| 발견 | 실제 영향 | 교정 방식 |
|---|---|---|
| Mesh/Sprite StartRotation 범위 누락 | 파편/검격이 같은 방향에 모임 | 원본 uniform 범위와 LUT metadata 복원 |
| MeshRotationRate의 LUT는 있지만 op/chunk 누락 | 범위에서 고르지 않고 첫 값만 읽음 | 명시 LUT 유지, 상속 metadata만 복원 |
| LocationDirect ScaleFactor 1이 0으로 투영 | 원본 -130→110cm 이동 곡선이 소거됨 | source (1,1,1) 기본 분포 연결 |
| Cylinder VelocityScale 1 누락 | 원기둥 반경 방향 이동이 없음 | source 1 복원과 radialvelocity=true 소비를 함께 연결 |

Cylinder radial velocity는 높이축을 뺀 원형 평면의 속도다. 원본 CDO의 true를 확인했고
기존 소비자에 명시된 true만 적용한다. 속도값을 먼저 복원하고 이 분기를 빼먹으면 높이축으로도
파편이 흩어진다. 의미 대조는 [Epic Cylinder 설명](https://dev.epicgames.com/documentation/en-us/unreal-engine/location-modules?application_version=4.27)을 참고했으며,
이 문서가 LostArk CPU 구현 전체를 증명하는 것은 아니다.

명시적 0/false/LUT는 덮어쓰지 않는다. 전역 default=1 패치는 금지한다. 이번 Q 원샷 수량은
원본 burst 합계 15개이며, 기존 손 조정 count 배율을 전체 복구본에 복사하지 않는다.
원본과 난수열·모든 CPU 옵션까지 동일한지는 별도 경계다. bAdjustForWorldSpace,
bInheritParent와 생략된 Required duration 등은 확인된 소비 범위 이상으로 완료 처리하지 않는다.

자동 확대의 다음 수정 지점은 기존
[build_imported_effect_documents.py](../../Tools/LevelPlacementExtractor/build_imported_effect_documents.py)의
`SourceIndex`다. 현재 raw properties만 복사하고 class/archetype 상속을 소비하지 않으며,
`build_distribution_recipe`는 op가 없으면 target class로 1/2를 추정한다. 따라서 Q JSON을
고친 것만으로 다음 스킬의 자동 변환이 교정되지는 않는다. 명시적인 native CDO/archetype
입력을 같은 SourceIndex에서 합친 뒤 기존 분포·duration/detail 생성기를 재사용해야 한다.
struct의 필드 병합과 배열 전체 교체, 명시 0/false/null 보존, 상속 순환/누락 시 오류 보존을
검증하고 우선 Q10만 재생성해 대조한다. 이 공통 importer 확장은 현재 미구현이며 전체
authored 문서를 일괄 재생성하는 작업과 분리한다.

### E05. 100배 크기와 90도 방향은 서로 다른 단계다

설치된 Q cube/swing/crack WModel 정점은 원본 cm를 `(x,z,-y)`로 변환한 것이다.
modelPreScale=.01은 단위 변환이고 원본 StartSize는 입자 크기다. 둘을 중복 적용하지 않는다.
Character CModel은 추가 Y -90도 import basis를 쓰지만 root Transform에는 그 회전이 없다.
Q의 root snapshot에 source basis -90도를 한 번 넣어 source +X 전방을 actor +Z에 맞춘다.

원본 cue 위치·속도·메시를 각각 눈대중으로 90도 돌리지 않는다. 기존
`actionCueAttachment.snapshotRootSourceBasisYawDegrees`가 local 공간 입력 전체에 같은
기준축을 적용한다. bone-follow나 다른 캐릭터에 전역 강제할 값이 아니다.
회전은 거리 자체를 줄이지 않으므로 남은 거리 차이는 anchor·location·원본 cue로 다시 분리한다.

### E06. Play All이 2초 멈춘 뒤 끝으로 가면 시계와 준비를 구분한다

원본 Q 수명보다 긴 동기 resource 준비 시간이 첫 dt에 포함되면 재생 시작부터 끝으로
이동한다. Preview row를 만들었는데 Sequencer Play가 그 임시 row를 삭제하거나 입력
owner를 요청하지 않는 경우도 있었다. 리소스가 보이는 Family 재생 성공이 전체 재생의
성공을 보장하지 않는 이유다.

현재 Play/Preview는 transient row를 유지하고 성공 시 interaction을 요청한다. 준비 직후
한 번의 advance를 제외하며 정상 dt는 그대로 사용한다. full recovery는 버릴 WorldPreview를
먼저 준비하지 않고 Sequencer occurrence를 한 번 준비한다. 실패 시 기존 유효 row를
보존하고 Loop는 선택 anchor를 유지한다. GPU 초기 준비 자체가 무조건 사라지는 것은 아니다.

실제 멤버 함수 CPU 대조에서 이전 transient 삭제/큰 dt skip/owner 누락을 재현했고 수정
분기를 검증했다. GPU·모델 경계는 대역이므로 UI 재생과 화면 PASS를 대신하지 않는다.

### E07. 원본 Product, 복구본, 손 조정본을 구분한다

복구본은 `Data/Effects/Authored/*.restore.effect.json`이고 All Effects의 해당 skill Product
아래 Recovery Effect로 연결한다. 제품 `.unified`와 성공한 Q2 비교본을 자동 덮어쓰지 않는다.
현재 full Q는 `effect.dimensionmaster.skill.2050100.full.restore`다. 별도 툴 대신 기존 V1의
All Effects·Model View·Sequencer·Play/Family를 사용한다. Save/Load는 같은 stable ID와
원본 식 입력을 보존하며 editor draft도 실제 occurrence snapshot에 전달해야 한다.

먼저 full Q를 Model View root 기준으로 Play All하고 같은 시각을 Seek/Family로 비교한다.
원본 위치·회전·기본값을 정리한 뒤에도 차이가 남으면 hand authoring 단계로 넘어갈 수 있다.
그때 바꾼 위치/색/수량은 PROJECT_TUNED로 기록하고 원본 바이너리에서 얻은 값으로 포장하지 않는다.

손튜닝본의 optional `sourceRecipe.authoredModuleOverrides=true`는 기존 module/distribution
편집 UI를 연다. sourceRecipe 실행·재질·geometry 소비는 유지하며 원본 full과 native 증거는
읽기 전용으로 남긴다. Q42 몸체는 material `color`, Q51 윤곽은 `aura_color`가 소유한다.
일반 RGBA만 바꾸고 실제 색 입력을 수정했다고 판단하지 않는다.

같은 재질의 반복은 emitter burst로 합칠 수 있지만 birth 시각과 particle age를 구분한다.
Q42 유리는 출생 시각별 위치·크기·수명·속도 곡선으로 묶을 수 있다. Q51 검격은 material
UV가 emitter 시간에 의존하므로 여러 타격을 한 emitter로 합치면 후속 검격의 무늬가 바뀐다.
element 수 감소를 목표로 이 차이를 버리지 않는다. 셰이더 계산·컴파일 변형 수와 실제
particle 수·화면 중첩 비용도 따로 확인한다.

### E08. 속도 정렬의 U/V와 모델 기준축은 별개다

Q의 원본 offset-center VS 두 개는 앞 181개 명령이 동일하다. velocity 선택 분기에서
U=cross(toCamera,motion), V=-motion을 사용한다. Required의 명시 PSA_Velocity를 읽어도
renderer가 local X를 속도에 맞추면 세로로 긴 검격·glow가 90도 틀어진다.
우리 ParticleRect는 local=(u-0.5,0.5-v)이므로 이 분기를 표현하는 world matrix는
row0=U, row1=+motion이다. row1을 -motion으로 복사하면 UV가 뒤집힌다.

Make_ParticleSpriteWorld는 확인된 Q native profile과 명시 CAMERA_VELOCITY에만 이
3D motion plane을 사용한다. authored pivot/크기를 유지하고 이 정렬에서는 roll을 적용하지
않는다. Q49의 명시 rectangle, 다른 profile, source-disabled 경로는 이전 동작을 유지한다.
속도 0 또는 시선과 평행하여 평면을 정의할 수 없는 경우는 기존 finite fallback을 유지한다.
원본 LostArk CPU의 실제 selector CB를 실행 중 회수한 것은 아니며, 원본 VS 분기와
serialized alignment·별도 Epic source 구현을 대조한 명시적 대응이다.

원본 UV 네 모서리와 실제 함수·DirectXMath의 197개 수치 확인은 통과했다.
카메라 평면 안에서 각도만 90도 바꾸면 입자가 깊이 방향으로 움직일 때 오차가 남으므로
단순 전체 yaw 보정으로 이 문제를 대신하지 않는다. 실제 실행 화면의 최종 승인은 별도다.

### E09. 한 클래스의 모든 스킬이 안 나오면 이벤트 문서 로드를 먼저 확인한다

`.animevents`는 원본 참고 행과 제품 `effectref=asset` 행을 함께 세어 헤더의 총 이벤트 수와 비교한다. 제품 EFFECT를 합치거나 삭제하면서 헤더 수를 그대로 두면 `CAnimationEffectCueDocument::Load_FromText`가 문서 전체를 거부하여 정상 스킬까지 등록되지 않는다. Artist Alt V 통합 뒤의 전체 미발생은 이 불일치였으며, 헤더와 실제 행 수를 맞추는 것으로 실제 Product prewarm과 캐릭터 로드가 정상화됐다.

개별 full 문서의 Codec/Stage 성공만으로 캐릭터 입력 연결을 확인했다고 기록하지 않는다. 기존 로더의 문서 검증을 유지하고, 헤더 수·Catalog 대상과 실제 모델 clip을 넣은 Load를 함께 확인한다. 이미 생성된 캐릭터는 정본 수정 후 class 재선택이나 재입장으로 다시 생성해야 한다. 상세 근거는 [Artist 결과 G09](09-09/2026-09-09_ARTIST_CORE_FULL_RESTORE_IMPLEMENTATION_RESULT.md)에 둔다.

### E10. simulation-only 위치 제공 요소는 GPU 발생 수에 포함하지 않는다

위치 제공 요소는 CPU에서 다른 입자의 위치를 계산하지만 그 자체를 그리지 않는다. Playback이 해당 요소를 GpuOccurrences에서 제외하면 Renderer의 GPU family·개수·순서 집계도 같은 조건으로 제외해야 한다. Artist Alt V는254행 중 provider2개가 이 기준과 달라 Render admission에서 실패했다. provider의 visible 값을 끄거나 전체 frame 개수 검사를 없애지 않고 family를 END로 분류해 두 소비자를 맞춘다.

static WorldObject의 CModel material override가 SOURCE_CHARACTER이면 일반 map shader 초기화 뒤에도 Bind_SourceCharacter를 호출해야 해당 재질의 frame/light 입력이 채워진다. 공의 원본 PBR처럼 텍스처가 존재해도 범용 D/N/S/E만 연결하면 mask 의미와 환경반사 계산을 잃을 수 있다.

## 렌더링 복원은 실제 표면에서 소비되는 입력부터 연결한다

렌더링 툴은 이미 구현한 계산의 빛·노출·반사 강도를 비교하고 조정하는 도구다. 빠진 texture 채널, 잘못 선택된 material, 끊긴 lightmap UV나 원본 shader 연산을 slider가 대신 만들어 주지는 않는다. 새 표면은 **보이는 배치 식별 → 실제 material 선택 → 원본 texture/parameter/분기 → CMaterial 입력 → geometry 채널 → shader·조명·후처리** 순서로 확인한다.

원작도 DirectX로 그린다는 사실은 같은 그림을 보장하지 않는다. 같은 GPU 명령을 사용하더라도 어떤 재질식·입력·광원·간접광·색 변환을 조합하느냐가 다르다. 특히 밝게 하거나 채도를 올리는 조작은 원인 분리 이후에 수행한다. 조작감·이펙트 발생 시점·발생 위치는 별도 gameplay/presentation 입력이다.

### 실제 배치와 material identity를 먼저 닫는다

MapCatalog는 생성 정의, placement는 위치·회전·크기와 stable placement ID, material 문서는 named material override를 소유한다. 원본 StaticMesh의 기본 material과 원본 actor/component가 선택한 material은 다를 수 있다. 예를 들어 같은 BRIDGE01E의 410/490과 411/495는 다른 원본 재질을 사용한다. override가 하나만 지정된 slot은 남은 기본 material 상속을 보존한다.

```text
mapmaterials + MapCatalog + mapplacements
→ Publish-MapAuthoring
→ runtime mapassets/material 참조
→ CMapAssetCatalog / Loader / MapTool MODEL_ASSET_LOAD_DESC
→ CModel named material override 검증
→ immutable CMaterial texture·수치
→ CMapAssetRenderUtils
```

### 색 공간·geometry·축소 품질을 서로 구분한다

색상 입력은 sRGB decode 후 선형 공간에서 조명하고, 마지막 표시 단계에서 encode한다. 그러나 원본의 특정 diffuse가 SRGB=false인 사례도 있으므로 이름만으로 일괄 바꾸지 않는다. 원본 tagged 값이 없으면 native class-default까지 확인하고, 미확정이면 프로젝트 해석으로 남긴다. 선택 CS의 ORM/lightmap linear와 일부 engine 상수는 그런 경계다.

normal/mask/alpha의 데이터 의미를 보존한다. 현재 TGA mip은 diffuse/emissive RGB를 linear로 풀어 면적 평균하고 다시 encode하며, alpha는 색 공간 변환 없이 독립 평균한다. normal/mask 채널은 linear 평균이다. 이를 원본의 normal 분산 보정이나 특수 alpha-coverage mip 알고리즘까지 복구한 것으로 표현하지 않는다.

DDS 로더는 파일에 있는 mip을 읽는다. 모든 DDS가 자동으로 full mip이 생기는 구조가 아니다. 차원술사 무기 DDS12개는 mip0 압축 bytes와 decoded pixels를 보존하며 하위 mip을 offline 생성해 mip11로 교체했다. TGA full mip은 CMaterial CPU 경로에서 생성한다. Loader worker가 rendering immediate context의 GenerateMips를 호출하는 우회는 사용하지 않는다. Aniso16과 FXAA는 서로 다른 역할이며, FXAA만 켜서 texture minification 복구를 끝내지 않는다.

Tangent handedness, UV1, COLOR0는 mesh에 실제로 있던 채널과 프로젝트 재구성을 구분한다. 반복 UModel 추출에서 달라지는 COLOR0/tangent.w를 원본으로 인증하지 않는다. BRIDGE/MAGICFLOOR의 일부 tangent 부호는 UV 미분 재구성이었고, 근거가 있는 FLOOR12/FLOOR13H는 보존 경로를 사용했다. Normal G나 binormal을 화면 느낌만으로 한 번 더 반전하지 않는다. UV1은 UV0 복제로 대신할 수 없으며 추가 UV가 필수인 source program은 실제 채널 부재를 거부한다.

있으면 component 전체 ABI를 복원했다고 표시하지 않는다.

대표 `lv_lut_heartrb.mat.bg_pap_stone_rock04_mi_ksr`는 `bg_base_opa`의 D/N+overlay D/N,
정점색, saturation/brightness, specular_color/intensity/power를 사용하는 원본 분기다.
이 선택식에는 ORM이 없고 D alpha는 opacity clip이 아니다. CS PBR 또는 쿠크 바닥의
alpha clip 분기에 텍스처만 바꾸는 것으로 대체하지 않는다. 원본 식의 정점색 의존과 실제
모델/배치가 비백색 정점색을 가진다는 증거도 구분한다. 원본 mesh 자체 color buffer가
비어 있어도 component override에 색이 있을 수 있다. 이번7배치에는 실제 색이 있으며
floor4는 모두 다르고 rock3는2그룹이다. A는전부255이고 R은실제분포가 있다. source VS의
BGRA→RGBA swizzle을 한 번만 적용해 CModel COLOR0으로 운반한다.

CPU 정점색 배열이 존재해도 GPU 입력이 연결됐다는 뜻은 아니다. 이번에 WModel reader는
색을 보존했지만 VTXMESH/CMesh 업로드에서 빠진 경로를 발견했다. 실제 vertex stride68,
RGBA8 COLOR0 offset64, 일반·인스턴스 layout과 업로드를 함께 연결했다. 같은 데이터에
swizzle을 다시 적용하지 않으며 public 구조 변경 뒤에는 Engine/Client를 함께 빌드한다.

원본 asm은 레지스터를 덮어쓴 뒤의 값을 추적한다. 이 식의 Base/Direct/Baked는 모두
`overlayD.a² * (1-saturate(baseNormal.z²*D.a))`를 coverage 입력으로 사용한다. 이전
raw XY 길이 해석은 레지스터 덮어쓰기를 놓친 오류였다. 다만 mixed normal은 Base/Baked만
정규화하며 Direct diffuse는 미정규화 mixed normal, Direct specular는 base normal을 쓴다.
기존 G-buffer의 두 여유 재질 입력을 marker7에 한해 재사용해 이 차이를 보존한다.

원본 floor UV1과 현재 WModel/source glTF의 정점 수가 다르므로 같은 인덱스로
UV를 덮어쓰지 않는다. native corner 대응으로 UV1·색·tangent W를 보존해 배치별 variant를
쿠킹했다. UModel 반복 추출의 rock COLOR0/W가 변하거나 UV1의 half-zero 값을 잘못 내보내는 경우도
확인했으므로 원본 native 채널을 대조한다. 같은 atlas도 배치의 좌표·계수는
다를 수 있으며 이동·복제한 EDITOR 배치에 원본 baked를 무조건 재사용하지 않는다.

원본 Point GUID가 lightmap의 참조 목록에 들어 있으면 직접광과 구운 diffuse의 중복 기여를
확인한다. 현재 발탄 Point22개는 다른 배치의 baked에 포함되지만 이번7배치의 GUID와는
교집합0이다. 전체맵의 교집합을 개별 바닥의 중복으로 오해하지 않는다. GUID 일치만으로 즉시 광원을 삭제하거나

실제 소비자와 활성 범위를 나눠 확장한다.

### Rendering Workbench에서 확인하고 마지막에 튜닝한다

같은 카메라·선택 배치·광원·Exposure/Gamma/Bloom 상태를 유지하고 Floor Materials의 A/B와 Base color → Normal → Direct specular 또는 Roughness/Metallic/Material AO → Reflection delta → Final 순서로 기여를 분리한다. 이 진단은 지원되는 선택 재질 범위의 출력이다. 화면의 모든 표면을 대상으로 하는 검사는 아니다.

직접 반사가 검다면 재질 입력뿐 아니라 실제 광원도 확인한다. legacy specular와 선택 PBR 직접 반사는 같은 slider 계약이 아니므로, 어느 shader가 해당 광원의 diffuse/specular를 소비하는지 먼저 읽는다. global 밝기 증가로 이 차이를 가리지 않는다. tone mapping의 clipping·White Point·Gamma는 고유색·빛 입력이 맞은 뒤 맞춘다.

가까운 화면과 먼 화면을 비교해 texture mip/filter, geometry 경계 AA, 재질/빛 결함을 분리한다. 새 MRT와 추가 source material × light draw에는 비용이 있다. 합성 WARP 검사나 빌드 성공으로 실제 장면 GPU 병목 또는 FPS 개선을 주장하지 않는다. 실제 원본 유사도는 사용자가 제출한 관찰과 비교로 종료한다.

검증은 변경 범위의 JSON/XML·기존 publisher·실제 CModel/Clone binding·필수 입력 실패 보존·해당 shader 수치·필요한 최소 컴파일을 재사용한다. 기존 쿠크23/CS57 native 검사와 shader 검사는 그 당시 입력 범위의 증거다. 새 표면을 추가하면서 예전 PASS를 자동 승계하지 않는다. WARP는 실제 shader에 대한 수치 실행이며 원본 Client 화면 비교가 아니다.

### Solo의 의존 모델·준비 시간과 종료 자원 수명

Element/Group/Family Solo는 선택 요소의 modelCueId가 요구하는 모델을 숨긴 pose 공급자로
남긴다. Alt V full의 자식27개는 부모 cue를 삭제하면 codec 단계에서 실패한다. 실제로
stage한 필터·draft 문서를 Update/Seek의 anchor 수집에도 사용하고, 제외한 형제의 bone을
다시 요구하지 않는다. CPU-only Open Editor 다음 Solo는 기존 shared character/skill target을
먼저 준비한다. Play All은 기존 sequencer가 소유한다.

리소스 준비와 같은 프레임의 긴 delta는 첫 preview 시각에 더하지 않는다. 다음 정상 tick부터
진행해 짧은 검격이 첫 표시 전에 끝나는 것을 막는다. 이 변경은 저작 수명·delay를 늘리는
보정이 아니다. 실제 CPU 시계 검사는 화면 재생의 증거와 구분한다.

원본 MIC의 `overridedtwosided`는 parent의 `twosided`보다 우선한다. V57/58/59/60/70/71/73/74/75는
parent만 읽은 descriptor를 교정했고, 사용하는 A/V full14행과 추가 S58도 같은 two-sided
profile을 사용한다. 특히 V70의 `fm_h_sphere_01_1` 반구는 단면 culling으로 안쪽 면이
사라질 수 있었다. blend나 투명도를 전역 변경해 감추지 않는다.

WVF1은 원본 XYZ volume/sample을 저장한다. 입자만 Client `(x,z,-y)`로 변환하고 field를
그대로 두면 같은 중심이 필드 밖으로 판정된다. domain·translation·rotation·sample velocity를
함께 변환한다. CylinderSpin의 radialvelocity는 높이축 속도를 제외하며 원형 평면 성분을
보존한다. source 모듈이 존재하는 것과 그 옵션을 실제로 소비하는 것을 구분한다.

V2 shutdown은 loader join과 Level/tool 객체 소멸 뒤 target/group callback·snapshot을 먼저
비우고 GPU cache·particle pool을 마지막에 비운다. 종료 누락으로 남은 strong/COM reference와
반복 플레이의 지속 증가 누수는 별개다. Engine shutdown 중 D3D live report는 뒤에서 해제할
cache도 포함하므로 그 보고 한 번이나 작은 수명 probe만으로 전체 누수 유무를 판정하지 않는다.

### 한 mesh particle이 원본 재질 슬롯 여러 개를 사용할 때

D `7508b2684fd272292d7b`의 `fm_d_crack_037`은 source materialIndex0의 LocalCrack
286 triangles와 index1의 Ice565 triangles로 구성된다. 단일 Required.Material은
EngineMaterials.DefaultMaterial이지만 실제 ParticleModuleMeshMaterial은 두 MIC를 지정한다.
`detail.mesh.sourceMaterialSlots`가 있으면 그 배열이 실행 재질을 소유하고 기존 primary
metadata는 보존한다. 원본 슬롯 번호를 현재 mesh vector 위치로 바꾸지 않는다.

각 material은 기존 native descriptor·codec·resource stage를 사용한다. 같은 CModel과 한 번
평가한 particle의 위치·수명·dynamic parameter를 공유하고 해당 source materialIndex만 그린다.
중복/누락 슬롯, 원본 MeshMaterial 경로 불일치와 리소스 실패는 전체 stage를 거부하며 기존
preview를 유지한다. 슬롯0은 V66, 슬롯1은 새 SD324의 정확한 Ice RT0 식이다. Ice는 기존

않는다. 새 Resources는 없으며 두 표면의 최종 모습은 사용자 확인 전이다.


### DimensionMaster 저작 preview의 시간·재질·운동 경계

V1의 문서 validation/ready 문구는 각 element의 Solo, 입자 생성 또는 화면 품질을 보증하지
않는다. hidden, material hold, source module 지원, bone/owner 이력, 실제 첫 생성 tick과
GPU 재질 출력을 순서대로 구분한다. 특히 mesh material slots를 쓰는 element는 사용하지 않는
primary hold가 아니라 실제 slot 계약으로 판단한다. Data Files의 Add Element도 같은 경계를
사용하되 FOLLOW/Trail/source history를 임의로 분리하지 않는다.

수명 배율 Life16은16초가 아니라 원본 particle life의16배다. emitter 생성 구간과 실제 입자

### 정적 World Object의 명시 diffuse와 공유 character material 상태

`CWorldSequenceObject`의 static draw는 `CMapAssetRenderUtils::Bind_Material`에 명시 diffuse SRV를
전달할 수 있다. 이 분기는 `CMaterial::Bind_ShaderResource(DIFFUSE)`의 character program reset을
거치지 않으므로 공유 `Shader_VtxMeshBinary`에 직전 장비의 source program/row·염색·피격 발광 값이
남으면 올바른 diffuse가 로드돼 있어도 다른 재질 계산을 사용한다. 정적 draw에서 해당 선택 상태를
초기화해야 하며 optional character 변수가 없는 instanced shader는 기존 방식으로 유지한다.

쿠크 등장 공은 `fm_d_rhcn_00.wmodel`과 `mn_rhcn_00_d.dds` 연결을 유지한다. 실제 DDS는 원본과
동일하고 유색 texel이 존재한다. texture 파일 존재·4slot 로드 성공만으로 공유 shader의 잔류 상태를
배제할 수 없다. 이번 수정은 Client의 기존 material binder이며 Resources payload를 수정하지 않는다.
source mapping/수치·컴파일과 사용자 화면에서의 색 확인은 별도 증거로 기록한다.

골격을 확장한 WModel은 mesh/WSKL뿐 아니라 각 WANM trailer의 skeletonHash도 동기화한다.
애니메이션 key·event를 그대로 보존하더라도 이전 골격 hash가 남으면 실제 WAnimationReader가
전체 모델을 거절한다. Python section parse만으로 actual decoder 성공을 대신하지 않는다.
