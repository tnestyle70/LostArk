# 발탄 강제 이동과 지면 지지 분리 구현 계획

## G00. 현재 실측과 변경 범위

Release 4인 발탄에서 일반 피격은 붕괴 경계를 넘지 못하고, 보스가 아래 지형으로 내려가는 증상을 조사했다. 8월 19일 `156634cde`가 스킬용 `Clamp_StepToWalkable`을 일반 넉백에 재사용했고, 8월 28일 `feae67183`은 뒤잡기 `ARENA_EJECTION`만 그 제한에서 제외했다. 일반 피격의 절벽 낙사 차단을 사용자 요구로 확인할 근거는 당시 문서에 없다.

현재 발탄 navigation policy의 최대 단차 0은 무제한이다. 게시된 바닥 `(142.25, -114.25)`의 높이 23.1116과 옆 `(141.75, -114.25)`의 높이 10.8561이 벽 파괴 후 첫 바닥 붕괴 구간에서 연결된다. 아래 셀은 void region도 아니다. 따라서 보행 경로가 낮은 지형을 받아들이는 문제와, 피격 이동이 void 전에 막히는 문제를 함께 수정한다.

사용자는 구조 설명과 실제 수정을 요청했다. 기존 작업의 dirty 변경을 보존하고 필요한 블록만 수정한다. 잡기 일부 포획의 일반 피해/전원 포획의 처형 분기는 이번 이동 수정 범위에 포함하지 않는다. Client/UI를 실행하지 않는다.

## G01. `GameRoom_PlayerSimulation.cpp` — 피격 변위의 지지 판정

일반 발탄 피격은 보행 경로 탐색과 walkable clamp를 사용하지 않는다. 기존 `Advance_PlayerKnockback`에서 뒤잡기 강제 발사와 별도로 처리하며, 같은 Server tick과 기존 `FALLING` 상태를 소비한다.

호출 흐름은 피격으로 예약된 변위 → 현재 높이의 `Resolve_CircleMove` 벽/몸체 sweep → 실제 확정 구간의 지면 검사 → 위치 반영 또는 `Begin_PlayerFall`이다. 강제 이동에서는 몸체 slide를 끄고 실제 직선 구간을 검사한다. 지면 검사는 기존 `Sample_SurfacePosition`을 사용한다. 이 질의는 보행 금지와 물리 지지면을 구별하고, 파괴된 void의 지지는 거절하며, 가까운 셀로 투영하지 않는다.

- 확정 구간을 셀 절반 이하로 검사한다. 셀 모서리를 짧게 관통하는 대각선은 이 표본 방식만으로 전수 검증되지 않으며, 후속 DDA 보완 대상으로 분리한다.
- 실제 벽과 다른 몸체는 기존 충돌 시스템이 막는다. 충돌 뒤의 실제 이동 구간을 검사하므로, 몸체에 막힌 플레이어를 경계 후보만 보고 낙사시키지 않는다.
- 같은 층의 작은 높이 변화만 따라간다. 큰 하강, void, 물리 바닥 부재는 현재 높이를 보존한 채 낙하를 시작한다.
- 높은 지형으로 올라붙는 변위는 마지막 지지 위치에서 끝낸다. 아래층이나 위층 높이로 순간이동하지 않는다.
- 뒤잡기 `ARENA_EJECTION`, 쿠크의 저작된 낙사/울타리/마리오 정책과 일반 이동·스킬의 nav 계약을 보존한다.
- 새 wire 상태나 Client 권위 이동을 만들지 않는다.

## G02. navigation publisher와 `ValtanBrain.cpp` — 보스 보행 높이

기존 navigation publisher의 발탄 최대 보행 단차를 1m로 게시한다. 아래 지형 자체나 다른 Area의 정상 지형은 삭제하지 않는다. 정본 publisher 후보를 먼저 검증하고 발탄 policy 출력만 현재 저장본 기준으로 반영한다.

`MoveAlongPath`는 먼 경로점의 Y를 직접 대입하지 않고, 매 tick 실제 이동 구간을 현재 보스 높이로 검증하여 그 지면 높이를 사용한다. 실패한 오래된 경로는 정리하고 기존 재탐색 흐름으로 돌아간다. 스크립트 점프와 명시적 패턴 수직 이동은 보행과 구분한다. 변경 소비자와 모든 호출 지점을 함께 검사한다.

## G03. 기존 Server 계약 테스트의 Release 실행 경로

기존 `ServerGameplayContractTests_WorldDestruction.cpp`에 focused runner를 추가한다. `ServerGameplayContractTests_Runner.h`의 public static 선언과 `Main.cpp`의 `--valtan-arena-support-contract-test` 분기로 연결한다. 새 C++ 파일이 없으므로 프로젝트/filter 등록은 필요 없다.

확인할 계약은 실제 발탄 게시 데이터에서 4명 중 피격자만 void를 넘어 낙사하는지, 실제 벽 앞에서는 멈추는지, walkable이 아니어도 물리 지지가 있는 지면에서는 강제 이동이 되는지, 낮은 지형으로 Y가 붙지 않는지, 뒤잡기 발사·정상 보스 보행이 유지되는지다. 테스트 body를 Debug 전용으로 감싸지 않는다.

## G04. 빌드·검증·완료 보고

변경 source/생성 policy를 대조하고 정상 Release Product 증분 Build를 실행한다. focused Server 계약 테스트와 관련 navigation 검사를 실행하며, 불필요한 광역 하네스는 돌리지 않는다. 문서에는 실행한 명령과 결과만 기록한다. 변경 JSON/XML이 생기면 parse하고 `git diff --check`를 확인한다.

RESULT는 코드 반영, 게시, Release 빌드, 자동 수치 검증, 사용자 4인 화면 확인을 분리한다. 사용자 화면 확인 전에는 끼임/낙사 화면의 최종 성공을 주장하지 않는다. 공통 지면/넉백 계약은 팀 사용서와 gotchas에 필요한 변경만 반영한다. 대규모 기존 dirty 작업은 자동 stage/commit하지 않는다.

사용자의 후속 요청은 우선 현재 변경분을 컴파일 오류 없이 마무리하는 것이다. 추가 기능 확장은 중단하고 Release Product 빌드와 이미 추가한 focused 검사를 완료한다. 보행 불가·지지면 존재 셀에서의 이동 복귀, 대각선 모서리 전수 검사, 보스 scripted stride의 높이 제한 연결은 RESULT에 미완료로 남긴다. 이 단계의 컴파일 성공을 끼임 전면 해결로 기록하지 않는다.
